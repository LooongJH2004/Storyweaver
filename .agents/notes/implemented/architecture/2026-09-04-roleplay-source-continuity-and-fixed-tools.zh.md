# Agent Note: 来源连续性、固定工具与并行私有准备

Status: implemented

[English](2026-09-04-roleplay-source-continuity-and-fixed-tools.md) | 中文

## Problem

滑动的近期历史窗口可能丢掉尚未兑现的承诺，却保留更新的普通发言。替代同类型全部已批准记忆可能移除无关认知。每次请求都在前部重建可变上下文会缩短可复用前缀，而串行私有准备在不需要公开因果顺序时增加延迟。

## Decision

导演和演员在正常提交中提出需玩家审核的短记及来源处理建议，[经批准的上下文保留](2026-09-04-player-approved-context-retention.zh.md) 负责审批、修订、来源及裁剪规则。

原文回查与近期窗口保留遵循[经批准的上下文保留](2026-09-04-player-approved-context-retention.zh.md) 所规定的当前来源索引和明确玩家审批。

导演和角色使用相互独立且固定的 schema：八个导演操作加回查，或 `npc_commit_turn` 加回查。能力和讨论阶段在执行时检查。底层 Actor 方法继续供可信 Host 代码使用，但不是模型工具。上下文基线保留有序的前导系统区段，后面依次追加精确字段变化和本轮事务。达到配置的来源数量或累计变化文本边界、静态区段变化或换场时重建基线。非系统配方区段保留原有尾部顺序。请求头记录全部模型可见基线和变化；进程重启仅重建派生批次，不改变权威状态。

记忆提案通过 `replaces` 显式列出替代 id。批准前必须保留全部被替代来源引用、各原私有受众的非空记忆，以及公共内容和原公共受众。其他已批准条目继续有效。这些结构检查不能证明语义完整性，玩家仍需审核文本。捕获当时公共受众，防止之后才出现且不知情的角色自动继承旧公共认知。

私有准备登记独立的持久 attempt，以有界并发运行，默认上限为四。全部参与者准备完成或被明确跳过后才选首位发言者。准备不计作公开跳过，公开发言继续串行。取消传播到全部活跃子 Agent，迟到 attempt 无法结算，准备失败仍可重试。Actor 记录与 Story 持久化之间发生崩溃后，已接受的闭合标记可幂等回放。现有 Story/Actor 改写检查点同时恢复新增状态。

## Alternatives considered

**逐轮总结或按估算 token 触发。** 这会增加常规模型输入输出和不稳定延迟。稀疏标记复用 Actor 提交，确定性分批不依赖 token 估算器。

**随阶段改变工具列表。** 这会改变前缀中的模型可见 schema。按角色固定定义保留前缀复用机会，由执行守卫落实权限。

**使用一份全局最新事项状态。** 私有纠正会悄然改变其他角色的认知。不可变的受众范围变化能保留每位观察者自己的认知。

**把来源覆盖当作摘要准确性的证明。** 保留来源 id 和受众字段可防止结构丢失，却无法验证改写文本保留了全部条件或例外。因此仍需审核与原文回查。

## Consequences

针对性 AgentLoop 测试覆盖同时准备、取消、失败重试、跳过、首位发言者选择、已接受来源标记，以及准备和公开阶段工具 schema 完全一致。领域测试覆盖私有撤回、归属、显式替代覆盖与回放。批次测试覆盖前缀不变、精确追加删除替换、来源边界及改写失效。本次网页外观交由用户验收，组件和本地化检查继续自动执行。

该设计不保证 token 上限或提供方缓存命中率。未批准原文与有效短记持续进入请求，来源索引和完整检查点可能增长。持久化版本 10 要求新建运行实例，可复用故事书保留。
