# Agent Note: 独立剧情实例与执行适配器

Status: implemented

[English](2026-09-07-independent-narrative-instances.md) | 中文

## Problem

StoryRegistry、Actor Session 投影、导演工具和 StoryController 共同拥有可变剧情。人物编辑可能恢复 Agent，上下文准备可能修改 Story，而一次 Session 事件决定角色回合是否进入剧情权威。从另一局目录创建故事，也让固定作者基线变得不清楚。这些依赖妨碍独立业务测试，并使打断、重试和实例隔离难以验证。

## Decision

将不可变故事书发布版本、独立剧情实例和技术执行会话保留为三个对象。采用显式命令、按受众区分的查询结果、范围明确的执行接口与专用事务 RoleplayStore。事件提交是权威来源；投影和检查点从剧情事件派生。模型请求及其回执属于执行证据。不自动迁移旧文件、不对两套权威双写、不增加运行中分叉，也不在实例之间同步。

## Current implementation

指定当前修订的查询在核对修订的同一事务内读取已提交投影；历史查询仍重放事件，包含删除实例和补偿恢复。当前作者详情查询因此无需逐次重建全部历史。未采用进程缓存，因为失效处理与跨实例隐私会扩大本次修复范围。剧情、世界和 SQLite 定向回归通过 152 项测试；新增读取路径测试验证当前查询不扫描提交，并验证再次提交后旧修订仍可读取。这不代表端到端页面延迟已完成测量，也未优化长执行日志的读取。

[玩家身份展示决策](../feature/2026-09-08-player-identity-presentation.zh.md)为已授权的玩家视图增加真实姓名附注。演员视角查询保持独立，并保留身份限制。

纯 roleplay-core 包负责故事书、状态、知识、身份、大纲、讨论和生命周期规则。独立应用能力分别负责发布、实例、人物、认知、配置、剧情提交、运行协调、恢复与视角查询。内存和 SQLite 适配器提供相同的原子提交、修订、幂等和发件箱语义。演员与导演执行器接收窄命令／查询回调；模型执行不占用数据库事务。

默认角色扮演 profile 已在独立 Storyweaver Home 中安装新应用和 ui-narrative，不再挂载旧 Story Registry、Story API、Actor 业务服务或 Director 工具编排器。旧组合成为不导出的回归夹具。既有运行目录和工作区未提交改动保留，不自动迁移或双写。

发布版本保持固定，导入分配独立实例与版本身份。人物和认知编辑不要求存在 Actor。先过滤受众再检索；稳定视角引用保护身份和历史称呼。检查点与补偿恢复保留原日志，由 Harness 适配器支持同 Session 重发。保留提案、审阅、原始检索、当前上下文配方和实际请求重建分别归应用或适配器所有。

作者界面接入设定、人物、风格、动态状态、生命周期 JSON、大纲锁定与提案、上下文和素材收录。同视角刷新保留已编辑设定，并更新未编辑字段；冲突保留草稿。个人风格预设复制内容。并发完全相同的运行重试共用一次执行，命令状态查询区分已提交剧情和已结束执行。导入实例可查看可移植请求正文与回应，无需恢复原 Session。可选实时诊断在视角变化时清空私密输出，不将其发布为剧情。

执行模型偏好归 Harness 设置适配器，不属于故事事实。写入校验模型路由和设置修订。已有及新建的演员／导演 Session 在下一次执行时读取选择；请求头保留实际模型。密钥仍由原设置系统管理。

## Validation

最终定向回归通过 23 个文件、116 个测试，包括独立夹具、API Client、UI、依赖、SQLite 和真实 Loader 检查。独立浏览器场景通过发布、隐私、配角、状态、设定冲突、个人风格、大纲审阅、讨论、检查点恢复、存档导出导入、素材选择、实时草稿隐私与模型切换。真实 Loader／HTTP 测试覆盖插件组合、原生工具纠错及原子接受、冷恢复、原始请求证据和同 Session 重发。资源测试保留固定字节；2,000 个离场人物查询覆盖上下文规模和实例隔离。最终检查日志位于工作区 .tmp 目录。

早先的全量 GUI 和 Web 测试并未全部通过，目录选择器、欢迎提示、滚动条及平台夹具的无关失败仍有记录，不应报告为通过。真实模型的姓名泄漏、无依据知识、重复建人、延迟、token 和表演质量仍未测量；无密钥测试不代替人工游玩评审。

## Remaining validation and limitations

超长执行日志性能需要测量：实时诊断合并通知但仍扫描请求历史。高级作者字段仍使用 JSON，草稿尚未覆盖所有导航路径的保留。本轮不包含离场自主调度、实例分叉／合并、旧格式隐式迁移或跨实例知识共享。保留在旧夹具下的真实模型评测器属于历史证据，不代表新组合的评测结果。

## Alternatives considered

**继续由 Story 与 Session 共同拥有剧情。** 这会保留作者编辑需要恢复 Actor、剧情依赖执行协议等耦合。

**将通用 Harness KV 扩展为剧情事务存储。** 专用 RoleplayStore 提供跨记录原子性，无需扩大无关 Harness 存储的职责。

**双写新旧数据表示。** 产品改为使用独立目录，旧组合仅作回归夹具，不引入数据对账桥接。

## Consequences

独立应用可用内存存储和脚本执行器测试。固定故事书版本与按实例作用域提交防止运行数据继承。新产品采用独立目录，既有用户需显式导入作者设定或支持的新格式存档。无密钥验证说明结构行为；真实模型性能与人工表演评审仍需单独完成。
