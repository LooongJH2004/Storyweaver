# Agent Note: 用户中断会主动结算流与子进程工作

Status: implemented

[English](2026-09-01-interrupt-reaches-runtime-quiescence.md) | 中文

## 问题

停止一个轮次会中止 agent（智能体）阶段，但有两类下游操作可能阻碍 Host 事件循环及时发布随后的 idle 状态。DeepSeek 响应在响应头已经到达后，SSE（Server-Sent Events）读取器仍可能无限等待；当创作模式的 DSML 内容被缓冲到响应完成时，这个问题尤其明显。在 Windows 上，子进程取消会同步执行 `taskkill`，因此中止监听器本身可能阻塞取消 Remote 和状态帧。用户中断任务后，UI 便会继续显示忙碌状态。

## 决策

取消操作会主动结算其拥有的两类运行时资源：

- `dsh-llm-deepseek` 把请求的 `AbortSignal` 传入 `parseSse`。解析器拥有转换后的流读取器，在中止时取消该读取器，在清理期间移除监听器，并重新抛出中止原因，而不是把被中断的流归类为提供方响应截断。
- `dsh-subprocess-local` 通过异步 `taskkill` 子进程请求终止常规 Windows 进程树。同步 `taskkillProcessTree` 路径仅保留给 Host 进程退出时的最终清理，因为此时无法依靠事件循环完成异步清理。
- 当 Host 仍报告轮次运行中时，Session Controller 会保留停止响应失败提示。Host 的权威 idle 控制帧会清除该停止错误；即使重连基线里的 running 位原本已经是 false，也会清除，因为此时可以确认请求结果已经落地，只是单次响应丢失。新的停止尝试也会清除旧停止错误，但不会擦除无关的发送失败。
- 此变更不会合并创作模式和故事模式的工具注册表。仅当请求携带创作模式终止工具时，才启用创作模式专属的 DSML fallback；故事导演和演员请求继续保有独立的工具表面和原生解析行为。

## 验证

DeepSeek 适配器测试会在响应头到达后中断一个仍保持正文打开的创作模式实时响应，并要求系统无需等待流完成就返回 `ABORTED`。解析器测试要求中止操作取消底层读取器。Session Controller 测试要求从运行到 idle 的帧，以及原本已经是 idle 的重连基线，都只清除语义不确定的停止传输错误。另一项隔离测试会把同一份 DSML 载荷分别交给创作模式和故事模式工具表面，并要求只有创作模式发出工具调用。子进程包的类型检查覆盖拆分后的常规取消与 Host 退出钩子；平台专属进程测试继续负责验证进程树行为。

## 考虑过的替代方案

**把停止按钮当作 UI 超时并强制显示 idle。** 这种做法会隐藏仍在运行的提供方或子进程工作，并允许迟到事件在界面声称完全停稳后继续抵达。运行时资源必须先结算，idle 状态才能保持真实。

**Host 报告 idle 后仍永久保留停止响应失败。** 响应失败只能证明页面没有收到确认。一旦 Host 报告 idle，继续保留错误就会歪曲当前状态，并让本可继续的会话看起来被阻塞。

**继续依赖 `fetch` 把中止传播给响应正文。** 并非所有提供方和运行时实现都能及时结算响应头到达后的正文读取，而转换流又增加了一层所有权。显式取消读取器，可以让适配器的所有权和清理行为保持确定性。

**每次 Windows 取消都同步运行 `taskkill`。** 这能保证监听器退出前命令已经返回，却会阻塞同一个负责确认取消的 Host 事件循环。同步清理仅保留给进程退出场景。

## 后果

- 即使提供方让响应正文保持打开，或 Windows 工具进程仍在终止，打断创作模式工作也可以让会话返回 idle。
- 常规 Windows 取消会变为「发出请求后进行有界存活观察」，而不是阻塞式 OS 调用。既有升级终止和 `waitForExit` 行为仍负责判断进程树是否真正停止。
- Host 退出清理仍保持同步，因此保留更强的尽力进程树最终清理能力。
- 取消确认丢失时，Host 仍在运行期间可能短暂显示错误；权威 idle 状态会恢复交互，无需重新加载页面。
- 创作模式与故事模式继续保持运行隔离；此次生命周期修复只改变资源清理，不改变工具可用性或权限。
