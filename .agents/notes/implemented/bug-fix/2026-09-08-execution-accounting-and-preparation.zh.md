# Agent Note: 独立执行统计与导演准备

Status: implemented

[English](2026-09-08-execution-accounting-and-preparation.md) | 中文

## Problem

独立游玩缺少原生 token 用量，不透明的导演工具输入导致反复纠正参数。空场景隐藏了已有角色身份。群组讨论结束后等待另一条玩家命令。长篇原始记录被截断后无法续读，角色流式内容则藏在诊断开关后。

## Decision

执行适配器使用原生完整回合 token 汇总，保留每次请求尝试，并随可移植请求证据导出统计。浏览器复用原生用量折叠组件、语言文案及精确的缓存、输入、输出分项。缺失记录显示不可用，不估算为零。

工具使用必填的 command 联合类型，从领域命令规则派生完整操作字段、必填属性与枚举。领域解析继续校验数值和文本边界。上下文在尚未布置出场人物时也提供有界的已有角色目录。工具说明区分场景布置与旁白发布，并将分析语言交给已启用的剧情指令。

讨论结束后，宿主在原取消纪元内自动调用一次导演收尾。续接不记录玩家消息，重试复用持久化回执。讨论前的私有准备使用冻结输入并行执行。共享修订检查仅随同批准备写入推进；外部编辑与取消都会拒绝迟到结果。角色公开回应保持串行，手动讨论默认值来自实例配置。

原文检索收录导演可见的玩家指令与已发布旁白，并保留不同来源。角色访问仍单独过滤。原文截断时返回来源 ID 与字符偏移，下一页先续读该原文，再转到其他记录；来源变化时拒绝续读。

游玩主视图跟随宿主指定的当前回应角色。尚未完整返回的公开行为字段显示为未提交草稿，私有修改保留在诊断中。下一步生成时仍可阅读先前请求。已接受剧情记录始终是历史正文的唯一来源。

## Alternatives considered

**按页面正文估算 tokens。** 这会漏掉提示词、缓存、工具与重试用量，不能复现提供方统计。

**禁止导演多次请求。** 准备过程包含合理的依赖工具步骤，禁止所有迭代会掩盖失败并阻止场景发布。

**重写历史请求或合并同名人物。** 历史输入必须保持真实，同名也不代表同一人。

## Consequences

针对性应用、原生适配器及浏览器测试覆盖请求统计、来源续读、取消、幂等讨论续接和可读草稿。隔离的真实提供方检查验证四人开局的旁白发布、重复建人、工具失败、语言及原生用量。提示词规定的推理长度仍是模型指令，不是 token 或句数硬限制。已有作者配方选择和用户故事数据均保留。
