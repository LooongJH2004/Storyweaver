# Agent Note: recipe roles and readable character turns

Status: implemented

English | [中文](2026-09-08-recipe-roles-and-turn-reading.zh.md)

## Problem

The independent defaults assigned every context module the user role. The Director's invented reasoning marker did not preserve the referenced analysis instructions, and the language preference was serialized as data. Existing instances retained these defects after code updates. Appearance initials made ambiguous avatars; repeated speaker headers and nested disclosures obstructed reading. Deletion existed behind secondary navigation.

## Decision

Default setting and rule sources use system messages. Player guidance and the final reasoning module use user messages. Director instructions use the referenced `〖思维模式要求〗` analysis mode; Actor immersion remains unchanged. Language is an explicit instruction for every reasoning step. Adjacent equal-role modules retain the existing request grouping.

Repair is a draft operation followed by revision-checked saving. It corrects all-user built-in defaults, adds missing default sources, and replaces only the exact defective Director text. Custom content, disabled sources, mixed role choices and recorded history remain intact. Reads never repair stored data. Published books and existing instance recipes have separate ownership.

Each accepted character turn displays one primary player-facing name and a secondary appearance description, followed by actions and speech. Appearance initials are removed. Direct reasoning and original-context actions open a separate reader with request steps, searchable messages, response, parameters and original JSON. Only recorded evidence supplies historical input. The sidebar exposes deletion beside each book and instance, with a confirmation naming the target and explaining retained versions.

Native dsh token accounting is projected from complete technical turns and displayed through the shared TurnUsageDisclosure component. Every retry and tool step contributes once; incomplete accounting stays unavailable. Per-turn request counts make multi-step Director preparation visible. Recorded reasoning, message content and tool arguments have separate reading blocks; long blocks expand in place. Speech and action cards share one speaker heading. Source editing uses a modal, and Director prompt ordering is independently editable in new or explicitly repaired recipes.

## Alternatives considered

**Rewrite every recipe automatically.** This would erase intentional author choices and make historical requests irreproducible.

**Treat a mock request as proof of model compliance.** Mocks verify transport and persistence, not generated reasoning. A separate bounded live-provider diagnostic uses synthetic fiction in isolated storage.

## Consequences

Ownership selection must not depend on scene attendance. Reusing the observer's scene-only embodiment choices left new runs with only the observer option. The query now separates the full non-archived control roster from immediate embodiment choices and marks attendance. The composer explains off-scene ownership and prevents premature speech; selection never stages a character. Core and browser regressions start with an unstaged cast, claim a character, and verify scene-dependent response availability. The API mirror also tests late roster rejection across run changes.

Narrative focus and player ownership now have distinct contracts. A protagonist remains an ordinary characters entry referenced by protagonistActorId; the editor offers Add protagonist and explains that an unspecified protagonist is valid. Missing, null and blank values normalize to null; ordinary character creation does not select a lead. Validation still rejects a nonempty unknown actor ID. The AI authoring reference and creation guidance preserve this choice. Per-run player-control/current is an explicit player command, separate from viewing or temporarily embodying a character. Claiming invalidates stale attempts, exempts pending private preparation without manufacturing player intent, blocks Actor execution and commits, and filters accidental Director dispatch. Discussion scheduling waits on the owned floor, with explicit player speech or silence and a nearby continuation action. Ownership survives archive import and browser reload. Core regressions exercise claim/release, late results, preparation, speech/pass and Director filtering; browser coverage checks claim/reload/release. Narration receives guidance, but arbitrary prose cannot be semantically guaranteed by the structured execution guards. Original user JSON and existing book versions are not rewritten.

Group preparation already uses concurrent actor execution against frozen batch inputs, but the reading UI previously selected only one active actor. The group card projects accepted-ready counts and distinguishes active work from paused preparation. It now retains independently collapsible character records after preparation. Stored attempt/revision coordinates prevent later public speech from replacing preparation evidence; legacy records use the first public-turn receipt boundary. Expanded live records refresh on demand and stop on collapse. Private submitted stances and thoughts remain explicitly author diagnostics. The real Loader test blocks both preparation requests, releases the second first, verifies one accepted preparation and no public turn, then releases the first and verifies sequential speech. Cancellation and external-write fences remain covered by the core runtime test.

Author navigation has a persistent Back to story action. Reading follow suspends outside play and restores its last tracked position on return, rather than reading the shared viewport after author content has replaced the transcript. Unsent directions remain in the instance draft store. Hook coverage checks paused restoration, following resumption and scope isolation; browser coverage visits all four author shortcuts and returns with the same reading position and draft on a narrow viewport.

Play tools now belong to the sticky navigation container with the title, rather than the scrolling opening area. The scene-person trigger remains beside the other tools throughout the transcript. Its native modal replaces the inline/sticky sidebar, avoiding prose reflow and keeping the list reachable after long scrolling. Browser coverage checks tool geometry at the bottom on desktop and narrow screens, modal opening without scroll/height changes, and Escape focus return.

Actor cache ordering is a separate explicit edit: stable settings, judgments and lifecycle records precede live people, state and evidence. Only adjacent built-in modules with equal message roles can move; custom modules and reasoning instructions are barriers. Selection and memory budgets remain unchanged, and historical requests replay their original recipe. New defaults use this order; saved instances and authored books require an explicit save. Tests cover bounded source selection, immutable history and the browser save flow. Offline replay of 37 consecutive local Actor request pairs increased every compared character prefix without changing rendered source content; it does not establish actual provider cache hit rates.

Normal completion also needs a continuous dispatch phase: a committed actor does not mean its owning Director run has settled. Play uses the dispatch cursor between actor executions, and accepted row revisions suppress older actor drafts arriving on the separate execution stream. Settled footers and fully loaded records stop background reads; command completion refreshes incomplete accounting without waiting for library listings. Footers reserve height. The browser scenario completes its streamed turn and checks stable geometry across 30 subsequent frames, enabled submission, and retained historical footer nodes; cancellation-only coverage cannot establish normal completion stability.

Streaming stability requires preserving loaded usage footers and expanded records during same-scope refreshes. Clearing them at execution phase changes collapses earlier transcript height and disturbs scroll anchoring. Scope identity excludes refresh triggers, while story, actor and historical revision changes still hide stale evidence immediately. Draft Markdown uses the shared incremental renderer with stable labels and request identity. A reading-column ResizeObserver follows growth before paint, while upward reader movement pauses following. Delayed scroll events from a prior chunk cannot cancel following merely because the next chunk has increased bottom distance. The [layout browser regression](../../../../apps/web/tests/reading-layout.e2e.ts) holds real mock tool streams between paragraphs and verifies bottom following, paused reading, paragraph DOM retention, and desktop/mobile alignment. Component regressions cover retained footers, expanded evidence, queued scroll events and incomplete TeX. Natural line wrapping and the final Markdown parse can still change content height.

The [browser regression](../../../../apps/web/tests/independent-narrative.e2e.ts) exercises reading, search, archived input and unchanged historical requests. The [authoring regression](../../../../apps/web/tests/authoring-recovery.e2e.ts) covers visible deletion and consecutive Director requests. The [optional live diagnostic](../../../../apps/web/tests/director-reasoning.e2e.ts) records DeepSeek V4 Flash analysis and language across tool steps without writing user stories. Observed reasoning is Chinese and non-immersive, but the requested one-to-three-sentence length is not consistently followed. Prompts do not provide a hard reasoning-length guarantee.

This decision refines the [storybook editor repair](2026-09-08-storybook-editor-and-reasoning.md). A visible recently-deleted recovery page remains outside this change.

The previous preparation card incorrectly followed the entire transcript. Preparation now has a first-public-turn boundary and is inserted in chronology; completed discussions retain separate positions. Compact character selectors reveal one record, while persistent discussion controls and heavier inspection move to side panels. The visual direction follows [Linear’s quieter supporting navigation](https://linear.app/now/behind-the-latest-design-refresh) and [Carbon’s progressive disclosure](https://carbondesignsystem.com/patterns/disclosures-pattern/). The skill’s generated marketing-page patterns did not match this reading workspace and were not applied. Existing theme tokens remain the source of color. Local investigation also found full-world deep cloning for every replayed event, repeated log inspection within request reconstruction, and unrelated current-author queries before original-context reads. Replay now shares immutable unchanged entities internally and detaches its result; recorded inspection bypasses unrelated views and reuses loaded events. Tests cover historical ordering, perspective races, drawer close/return and the existing restoration/import contracts.

A runtime-created minstrel exposed another presentation mismatch: the turn header treated a staged encounter label (Outside the room) as the character description. Play projections now carry definition appearance separately, and both live and accepted headers use it alongside the canonical name. Perspective controls retain encounter labels. A runtime creation regression covers all three player projections, and the browser extraction flow checks the now-visible collection heading and explicit selection disclosure. Extraction still creates a separate reviewed draft rather than updating the source book.

Book import previously lived inside a collapsed library section and only opened unvalidated local editor content, while export sat below the entire form. The visible sidebar/library/editor entry now opens a file-or-paste panel with separate book and archive modes, explicit confirmation, host-validation errors and a retained draft identity for retry. Successful book import opens a newly saved draft for later publication. Export uses the saved document and resources with a recognizable filename. Component coverage rejects malformed envelopes and retains failed imports; the browser scenario checks invalid-file recovery, archive restoration and book export/reimport without overwriting the original or creating another run.
