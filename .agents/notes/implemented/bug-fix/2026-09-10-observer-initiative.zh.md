# Agent Note：旁观模式下的主角主动性与叙事节奏

Status: implemented

[English](2026-09-10-observer-initiative.md) | 中文

## 证据

本地一则故事的六次导演运行均未调度主角，而每次记录的准备上下文中 playerControlledActorId 都为 null。作者指导仍将该角色描述为玩家控制，导演上下文也未提供 protagonistActorId。后续玩家接管命令与这些历史旁观回合属于不同状态。记录中的旁白长度为 90～225 字符，完整运行约耗时 15～26 秒。这些观察证明控制权指令冲突与输出偏短，不能用于判断供应商吞吐量或 token 上限。

## 决策

导演在现有必需场景段中同时接收 protagonistActorId、playerControlledActorId 和当前由 AI 控制的在场人物 ID。实际控制权优先于作者文本中的玩家角色标签。可选主角字段始终只表示叙事焦点，不隐含玩家控制，也不从第一个角色推断。在场名单描述冻结修订；后续调度以成功布景的回执为准。宿主仍负责控制权、在场状态和讨论发言权校验。

导演通常通过角色执行器给予在场、可行动的主角推进当前情节的机会。导演展开可观察事件与后果，不代写角色选择。演员指令鼓励根据已有目标和感知主动行动，允许一次提交包含充分展开且有序的言语与行为。精简规划和仅记录私有状态增量不限制公开正文篇幅。沉默、明确的节奏要求、准备内容的私密性以及等待世界裁定仍是有效停止条件。

## 研究与取舍

[SillyTavern 群聊文档](https://docs.sillytavern.app/usage/core-concepts/groupchats/)区分发言者激活与角色生成。[社区场景节奏讨论](https://www.reddit.com/r/SillyTavernAI/comments/1bk7xwm)建议用角色目标带动情节；其中面向慢节奏场景的建议未被整套采用。这些是设计参考，不能证明提示词一定改善模型表现。不采用每回合强制调度主角、固定字数配额或增加讨论轮数，以避免无关发言、填充内容与额外延迟。故事原始设定和模型设置保持不变。

## 验证与限制

应用测试覆盖可选主角信息、旁观调度、主角接管、接管其他角色、离场状态和历史回放。无需密钥的真实 Harness 组合测试记录导演规则与场景输入，核对日志上下文与冻结的应用查询，并调度主角提交含多段言语和行为的响应。NPC 请求快照覆盖更新后的演员规则。这些检查证明输入传递及执行规则，不证明真实模型的文学质量、主角调度频率或速度收益。规则文本变更会使缓存前缀失效一次；动态场景信息仍位于原有段落。
