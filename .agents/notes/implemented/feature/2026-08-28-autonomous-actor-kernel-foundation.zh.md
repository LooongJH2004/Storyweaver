# Agent Note: 自主 Actor 内核基础

Status: implemented

[English](2026-08-28-autonomous-actor-kernel-foundation.md) | 中文

## Problem

harness 已经能够编排上下文并隔离 agent，但这些机制本身不能让角色扮演 NPC 成为自主主体。导演可以要求普通 agent 编写对白，但角色并不真正拥有持续的选择，例如说话、行动、内心活动、记住、遗忘、建立目标，或打算稍后行动。把 assistant 文本同时视为所有这些行为，也无法区分私有想法和世界可见行为。

玩家面对的是另一种权限问题。在这个产品概念中，玩家不必是某一个角色。玩家以上帝视角观察、选择故事方向、改变世界，也可以暂时代替任意角色说话或行动。如果把这种权限折叠进 NPC 身份，玩家覆盖就会看起来像 NPC 的自主决定。

## Decision

固定模型工具、有来源的持续事项及显式记忆替代由[来源连续性与固定工具](../architecture/2026-09-04-roleplay-source-continuity-and-fixed-tools.zh.md)规定。

实验性基础由两个私有包组成：

- `@deepseek-ai/dsh-experimental-actor` 拥有 Actor 身份、事件词汇、重放投影、记忆、目标、意图、面向世界的行为意图、回合关闭，以及可信 PlayerAuthority 宿主 API。
- `@deepseek-ai/dsh-experimental-tool-actor` 在每个精确 Actor Agent 作用域中安装按能力筛选的工具和动态自我状态策略。

一个 Actor 是绑定到一个不可变 `ActorDescriptor` 的精确实时 dsh Agent。它的 Session 必须不带继承的 fork 历史，并在第一次对话回合前完成绑定。`ActorId` 稳定存在，且独立于显示名和 Session id。Actor 状态保存在自己的追加式 Session 日志中；不存在由导演拥有的可变角色对象。

assistant 文本没有虚构世界权限。此切片中，`actor_speak` 和 `actor_act` 创建唯一由 Actor 自主产生、面向世界的意图。`actor_reflect` 记录显式虚构内心活动，而非隐藏模型推理。核心记忆由 Actor 主动控制：调用 remember、recall 或 forget；遗忘追加墓碑并结束当前回合，使下一次请求在没有该记忆的情况下重建。当配置的记忆容量已满时，remember 会先为足够数量的低重要度活跃记忆追加 `core-memory-capacity` 墓碑，同重要度优先选择更早记录，再写入新记忆，而不会让 Actor 回合直接失败。目标使用带修订号的快照，未来意图采用最小世界时间触发器，`actor_yield` 显式关闭回合。仅输出文本就结束会被记录为 `implicit-silence`。

PlayerAuthority 与 Actor 能力相互独立。它把故事方向和世界介入记录进调用者选择的控制 Session。它也可以代替任意已绑定 Actor 说话或行动，不受该 Actor 模型工具能力列表限制。代演会先追加玩家介入事件，再追加匹配的表达或行动事件；后者永久携带 `origin: 'player'` 和介入 id。上帝视角检查会返回 Actor 模型上下文排除的内心活动和已遗忘记忆墓碑。

## Event and context boundaries

所有 Actor 事件都只写日志。严格 fold 校验描述归属、稳定且唯一的 id、单向记忆墓碑、连续的目标放弃修订、玩家代演来源，以及每个通用 Agent 回合最多一个 Actor 关闭事件。包 invariant 会在追加前针对已提交 Session 前缀重放每个候选事件。

工具策略会渲染 persona、活跃记忆、活跃目标、已安排意图，以及有界的近期表达/行动窗口；它排除内心活动和已遗忘记忆。常规 request-header 事件会记录组装后的模型可见提示词；工具结果只会在领域事件追加后返回。这样保持了“模型可见状态必须有日志来源”的仓库规则。

Actor 作用域使用原生工具呈现。默认情况下，它们隐藏继承来的全局工具，再加入描述授予的 Actor 工具和始终存在的 yield 工具。这使 Actor API 成为行为边界，同时把操作系统/进程沙箱留给现有 harness 层。

## Alternatives considered

**把可继续 subagent 直接当作 NPC。** 可继续 subagent 解决的是委托工作和继承任务上下文，而不是虚构身份。其工具面、父级权限和可选 fork 历史不适合作为信息隔离角色的拥有者；角色的决定还需要跨场景持续。

**保留单一导演 Agent，由它生成所有 NPC 台词。** 这保留了集中叙事控制，却仍把角色当作输出而非 agent。记忆、遗忘、目标和未来行动都由导演代写，无法形成真正的角色自主性或信息差。

**把 assistant 文本同时视为说话、行动和内心活动。** 这样 API 最少，但没有可靠的世界边界。私有草稿可能意外变成对白，叙述动作也可能在没有环境结算的情况下宣称成功。显式工具为每类行为赋予类型化、可审计的含义。

**把玩家建模成另一个 Actor。** 这会简化路由，却错误地把玩家限制在一个身体和一条信息边界中，也会掩盖 NPC 是自主选择还是被玩家代演。因此 PlayerAuthority 保持为独立的可信宿主能力。

**物理删除已遗忘事件。** 删除会缩小当前 Actor 上下文，却会破坏重放、调试和上帝视角审计。墓碑让记忆离开活跃回忆与模型上下文，同时保留真实发生过的记录。

## Consequences

基础层现在为角色自主性提供了可编译的领域接缝，并建立了独立的玩家上帝权限。它产生真实信息差：每个 Actor 拥有独立的新鲜 Session，只有自己主动选择的活跃记忆会重新进入模型上下文，容量压力可审计且不会中断回合，玩家来源行为也不会被错误归因为 NPC 自主选择。

第一切片有意止于意图。说话尚无受众投递适配器，行动尚无结果结算器，世界介入尚无分发投影，已安排意图也没有唤醒 Actor 的时钟。回忆只是简单文本/标签匹配，动态状态尚无检查点或上下文预算压缩。这些层现在可以作为插件，围绕稳定事件来源继续演化，而不必藏进 agent loop 或单体导演提示词。

真实 AgentLoop 组合测试覆盖按能力筛选的 schema、已记录说话加显式 yield，以及仅文本输出时的隐式沉默。领域测试覆盖记忆墓碑、私有检查、玩家来源、身份冲突和重放关系错误。
