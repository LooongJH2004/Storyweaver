# Agent Note: 带修订控制的故事书编辑

Status: implemented

[English](2026-08-29-storybook-authoring.md) | 中文

## Problem

Storyweaver 会把 `world/storybook.json` 载入 Director 与 Actor 上下文，但浏览器只能检查从该文件派生的投影。作者必须在产品外部编辑受管文件，而且 Director loader 与浏览器投影各自维护一套校验规则。浏览器写入还必须保留角色私有设定，同时不能暴露 Host 路径，也不能让故事内容替换固定 Director 职责策略。

## Decision

`dsh-story` 归属严格的 `schemaVersion: 4` 故事书 schema。允许的顶级部分包括身份、标题、设定、前提、世界真相、角色、节拍、Director 补充规则、结构化 `directorGuidance` 和一个 `protagonistActorId`。角色定义包含稳定 Actor 身份、公开人设、展示状态、能力、私有上下文和结构化 `actingGuidance`。非空角色列表必须且只能把其中一个既有 Actor 标为主角；该字段是 Director 维护叙事连续性的锚点，不限制玩家代演谁。未知顶级字段、角色字段或指导字段会校验失败，因此故事书不能增加 `systemPrompt`、工具定义或其他权限扩展。

Director loader、角色状态投影与编辑 Remote 全部通过同一 schema 解析。Director 指导只会在固定策略之后进入 Director 上下文；表演指导只会进入其所属 Actor 的私有快照。两者都不能授权持久角色对白或行动、替换工具协议、暴露 Director Outline、泄露世界真相或复制其他 Actor 的私有数据。

Story Controller 在不暴露物理路径的前提下提供完整规范 JSON。每次读取返回 SHA-256 内容修订，并区分缺失文件与内容相同的已持久文件。保存必须携带准确修订，解析完整替换内容，按 Story 串行执行，并原子替换 `world/storybook.json`。无效、过大或过期写入都会失败，不会替换持久文件。

角色扮演 Client 把强化显示的故事书工作台放在玩家位置操作区旁；新 Story 使用空场景 Hero 布局时，该区域仍会挂载。其视口级固定面板在桌面端保持在输入框上方，在窄视口使用紧凑屏工作区布局。默认编辑器把规范文档投影为基础信息、世界数据、Director 指导、补充规则和逐 Actor 设定。角色卡会标出主角并允许作者移动该标记；删除或重命名角色时会保持一个有效的唯一选择。结构化指导提供专用控件、恢复默认值、单步撤销、分区级修改前后对照和带标签的快速粘贴解析；完整文档 JSON 仍保留为高级模式。规范故事书 JSON 与单个 Actor JSON 均可导入或导出，草稿导出会序列化当前正在编辑的完整文档。导入内容在普通准确修订保存成功前始终只是未保存草稿。过期保存会保留草稿并提供明确的最新版本读取入口。保存成功后还会同步 Story 聚合的标题与前提，使侧栏导航描述已编辑文档。上下文检查器请求经 Host 过滤的 Director 或 Actor 区段，并显示来源、权限、可见性和纳入原因。该 Client 投影不会定义另一套持久 schema，Host 校验仍是权威校验。

## Alternatives considered

**使用独立 Client schema 的浏览器表单。** 这能立即提升字段级易用性，但会重复持久校验，并可能丢失灵活私有上下文。首个表层编辑完整规范文档；后续专用表单可以继续投影同一个 Remote 值。

**允许任意顶级字段的自由格式故事书。** 这能提供最大的作者灵活性，但故事内容可能伪装成系统策略或工具配置。严格命名部分让创作数据保持可编辑，同时把权限保留给 Host composition。

**不检查修订的最后写入覆盖。** 这种方式更简单，但一个浏览器页签可能静默覆盖另一个页签。准确修订可以明确报告冲突，同时不在 wire 上暴露文件系统元数据。

**自由格式提示词替换。** 单一文本框更便于粘贴，但会模糊创作偏好与不可变权限，也难以检查逐 Actor 隔离。命名指导字段保留实用的创作自由，同时由严格 schema 拒绝形似策略扩展的内容。

## Consequences

作者可以在 Storyweaver 内编辑、交换、检查和恢复世界设定、Director 指导、主角锚点与 Actor 范围内的表演指导。保存后的文档就是 Director 与 Actor 建立时消费的输入，上下文预览则在不暴露 Host 路径的前提下证明过滤结果。不可变职责提示与工具 schema 继续由 Host 归属；无论主角选择为何，玩家仍可代演任意角色。该编辑器继续交换一份故事书 JSON 或一个 Actor 定义；后续版本化 Story Package 表层会独立打包聚合、故事书、Session 日志与可移植世界文件。
