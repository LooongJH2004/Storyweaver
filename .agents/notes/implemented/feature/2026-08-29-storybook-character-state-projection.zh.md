# Agent Note: 故事书角色状态投影

Status: implemented

[English](2026-08-29-storybook-character-state-projection.md) | 中文

## Problem

最初的角色面板只列出拥有活跃私有 Actor Session 的 Story。导演正文可以写出很多虚构角色，但正文不是 Actor 生命周期事件，因此面板仍然显示零。故事书还需要在模拟开始前提供可用的初始状态，而 Actor 开始运行后，又必须用自己的持久选择替换这些初值。

AIAgentRolePlay 通过任意嵌套的世界与角色状态提供了有价值的作者灵活性，但它让浏览器递归解释状态，并混合可变世界、心理与关系对象。直接复用这种结构会让浏览器渲染依赖存储格式，也会让全局状态更新模糊私有知识的归属。

## Decision

`world/storybook.json` 是可选的初始角色名册来源。Story Controller 校验这个持久文件，并把每个角色投影为与运行中 Actor 相同的浏览器安全状态值。文件不存在表示没有设定角色；文件存在但无效时明确失败。物理路径与原始 JSON 都不会越过 Remote API。

角色状态分为两层。情绪、信念、关系、记忆、目标与意图使用语义字段，因为这些值参与自主行为与持久 Actor 事件。故事书还可以通过任意 `state` 键定义位置、装备、伤势、姿态或场景专用事实。Host 会把每个扩展项压平为带标签的展示 facet，浏览器只渲染稳定列表，不递归理解作者存储。

每个投影角色都有生命周期标记。`defined` 表示卡片来自故事书；`active` 表示相同稳定 ActorId 已拥有运行中的私有 Actor Session。运行时 Actor 的非空语义值覆盖对应初值；故事书扩展 facet 继续显示，因为当前 Actor 事件词汇并不归属这些值。

私有上下文只通过可信玩家上帝视角请求可见。角色模型不会从该投影接收其他角色的 facet、知识、盲区、秘密或记忆。

浏览器使用角色优先导航，因为信息归属边界在 Actor；随后用页签拆分概览、认知与心理、关系、记忆与意图。桌面端可在边界内调整面板大小，窄屏则使用响应式纵向布局。

## Alternatives considered

- **只列出运行中的 Actor Session。** 拒绝，因为自主 Actor 启动前，已创作的角色表仍不可见，会让故事书读取表现得像是失败。
- **把原始嵌套故事书对象暴露给浏览器。** 拒绝，因为这会让展示层耦合存储结构，并模糊 Actor 私有状态与共享世界状态的边界。
- **把 Director 正文当作角色状态。** 拒绝，因为这会让 Director 绕过 Actor 事件，间接决定持久角色的行动与信念。

## Consequences

在自主调度完成前，角色面板也能显示完整测试名册，数量反映设定角色，而不再只反映私有 Session。详情区一次只显示一个角色的一类状态，因此大规模角色表也能保持可读。作者可以增加场景专用展示状态而无需修改 Client。Actor 自主性继续以事件为依据，不会被通用可变 JSON 树取代。

导演正文仍不会自动更新状态。后续世界结算能力需要归属位置、伤势、物品及其他共享世界变化，Actor 工具继续归属私有语义状态。自动创建 Actor 与唤醒调度仍是独立工作。
