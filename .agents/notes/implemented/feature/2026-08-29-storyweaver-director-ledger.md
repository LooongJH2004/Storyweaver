# Agent Note: Storyweaver Director Boundary and Plot Ledger

Status: implemented

English | [中文](2026-08-29-storyweaver-director-ledger.zh.md)

## Problem

Storyweaver had separate Story, scene, control, and Actor Sessions, but the scene-facing model still carried a broad world-director prompt. That prompt could write dialogue and autonomous action for persistent characters even though the Actor subsystem already defined `npc_speak` and `npc_act` as the durable sources of NPC behavior. A prompt-only convention could not stop a Director or Host caller from bypassing the Actor tools.

The Story aggregate also lacked persistent orchestration state. A Director could not read and replace one current situation, established fact set, open-thread set, or Actor-specific context against an exact revision, so concurrent Actor events and planning passes could silently overwrite each other. Longer-range plot arcs and foreshadowing existed only in transient model context, with no player-visible ownership, locks, review policy, or evidence link to what actually happened.

Finally, persistence alone did not close the runtime loop. Nothing loaded the Story Bible into the Director's request, created information-isolated Actor Agents from a Brief, or projected accepted Actor behavior back into the public scene. Asking the Director to improvise that bridge would have restored the authority violation the Ledger was meant to prevent.

## Decision

Every Story owns one revisioned Plot Ledger and one revisioned Director Outline in the version-3 Story domain. The Ledger stores the current situation, established facts, open threads, NPC events awaiting the next planning pass, and the latest structured Director Brief. The Outline stores non-canonical premise, themes, hard constraints, arcs, candidate beats, foreshadows, mysteries, and narrative clocks. The domain rejects older records without migration or compatibility handling.

`StoryRegistry.commitDirectorBrief()` accepts an active control Session or the current scene Session. Its strict input contains an expected Ledger revision, current scene, situation, facts, threads, and per-Actor perceptions and uncertainties. Unknown fields fail parsing, duplicate or inactive Actors fail validation, and a stale expected revision cannot overwrite newer state. The committed Brief records its authoring Session, source revision, new revision, and the pending NPC events it consumed. A Brief may replace an unstarted run over the latest Ledger revision, including its complete Actor roster; the first dispatch attempt closes that correction window, after which callers must resume the durable run.

A Director Brief supplies context only. It has no field for character dialogue, thoughts, decisions, objectives, or actions. The Storyweaver prompt states the same negative authority rule: Director prose does not create persistent-character behavior, and a character remains silent and unresolved when no accepted NPC event exists.

The Ledger also owns one exact-revision Director Run checkpoint. Its Run state machine is `brief_committed -> dispatching -> completed | awaiting_retry`, with explicit `paused` and terminal `cancelled` controls. Per-Actor state is `pending | running | completed | failed | skipped | cancelled`. Every begin operation mints a unique attempt id, increments that Actor's generation and attempt count, and records the Actor Session plus its pre-attempt event sequence floor. A begin replay is idempotent only for the same ownership tuple. Settlement is idempotent only for the same attempt, generation, result, and already accepted references; all other stale ownership fails. Ordinary resume never redispatches completed or skipped Actors and selects only pending, failed, or cancelled Actors. The narrow exception is a durable active discussion: the exact completed Actor that currently owns the floor may be requeued over the current Run revision, preserving earlier event references before a fresh owned attempt begins.

Every Outline item has a globally unique stable id, player lock, and player/director/system source. Player replacements use optimistic revision checks and can select automatic updates of unlocked content or review of every Director patch. Review mode stores a pending suggestion until the player accepts or rejects it. A Director cannot change or remove locked content. Brief commits never update the Outline revision: the Outline remains the long-range plan, while each Brief is context for one Actor dispatch. Resolved beats require Actor or world event references, and planted or paid-off foreshadows require planting and payoff references; planning status cannot silently become canonical history.

## Runtime orchestration and information boundaries

`@deepseek-ai/dsh-experimental-tool-director` builds each Director model request from cacheable leading Story context, durable Session history, and a logged high-frequency state tail. The leading block contains the complete Story Bible, opening prose, approved memory, and private non-canonical Outline; World, Plot Ledger, discussion, and authored non-system instructions remain after history. A missing storybook is explicit, and an invalid present file fails the step. The Director receives strict tools to commit a Brief, patch the Outline, and dispatch Actors; no tool lets it author NPC speech or action. Its fixed policy tells the Director to initialize an empty revision-0 Outline before the first Brief and to patch it whenever the long-range plan materially changes.

Every fresh Brief owns one required Director narration World Event before Actor dispatch, and ordinary player turns instruct the Director to narrate objective development even when no Actor response is needed. If the Director ends such a turn with visible prose but no authoritative narration, the Host supplies a bounded corrective continuation; recovery controls and player-paused discussions do not duplicate narration. Player-visible narration is stored as canonical Markdown: the Host converts only legacy bare `<p>` and `<br>` fragments into Markdown breaks, then rejects any remaining HTML or XML construct. The browser applies the same narrow conversion to historical narration before rendering it through the shared untrusted-Markdown path, where raw HTML, relative links, and unsafe protocols remain non-executable. This presentation format does not widen Director authority: narration may establish objective environment and transition prose, but cannot establish persistent-character dialogue, private thought, or voluntary decisions.

A durable group discussion begins with one private preparation slot per participant. Each Actor declares only its own stance and eagerness without public behavior and cannot read another participant's declaration. The Host chooses the opening floor after all declarations, then advances public turns through explicit hand-offs, eagerness, queued player requests, and fair speaking counts. Preparation consumes no public round budget; public speech remains sourced Actor behavior.

Committing a Brief provisions every named storybook Actor in a fresh or resumed private Session. Each Actor mounts the separate `storyweaver-actor` preset, which shadows the Director persona and retains the capability-filtered NPC policy. Dispatch sends only that Actor's public persona, own storybook state and private context, and its Brief perceptions and uncertainties. It never sends world truth, the Outline, another Actor's context, or a desired response.

Dispatch waits for those Actor turns. The Host combines request cancellation with a Run-owned `AbortController`, forwards it to the model stream, and calls `Agent.cancel()` for affected live Actors. Settlement first verifies the exact attempt id and generation, persists the outcome and accepted event references, and only then projects accepted events. A pause, Run cancellation, Actor skip, or Actor cancellation closes ownership before aborting execution, so a late response cannot enter the Ledger or public scene. Accepted NPC behavior remains authoritative in the Actor Session and Plot Ledger, then enters the live scene as `story/npc-event-projected` with the original Actor Session and event references. The projection is presentation data, not new Director authorship. Quota and other classified failures keep their checkpoint; later resume or single-Actor retry preserves accepted references and runs only unfinished Actors.

The browser exposes both the complete Outline and a Director Run console beside the player-intent dock, including in blank scenes. The console displays the Brief, exact Run revision and status, Actor queue, attempt count and generation, failures, and accepted event references, with resume, retry, pause, cancel, skip, and Actor-abort controls. The viewport-fixed Outline panel displays its revision separately from the latest Brief revision and run status. Its structured studio edits intent and rules, arcs, reorderable Beats and their dependencies, foreshadows, mysteries, and clocks through source-labeled lockable cards. Event references remain visible on the items whose resolved status requires evidence. Revision history and the Director proposal queue are read-only projections with explicit accept and reject operations. Advanced JSON contains only player-writable fields; server-owned provenance, revision history, and suggestion internals never enter that draft. Exact-revision saves retain stale drafts and require loading the latest revision before another write.

Every durable `actor/*` event also advances a monotonic state revision on that Actor's Story Session registration. Story follow frames expose only this invalidation signal, never private state content. The character panel automatically refetches the separate trusted god-view projection when the revision changes, while private thoughts, emotions, memories, and goals remain absent from the public Story projection and Plot Ledger.

## NPC event provenance

The Story registry listens to committed Actor Session events. It admits an Actor-origin `actor/expression` only when an unmatched `npc_speak` tool call precedes it in the same Agent step, and admits an Actor-origin `actor/action-intent` only for a matching `npc_act` call. The Actor must also be running under a matching durable attempt, in that attempt's Session, after its recorded event floor. Each Ledger item records the Actor Session id plus the tool-call and Actor-event sequence numbers. Player-origin embodiment remains outside this NPC provenance rule.

The Story invariant checks the same relation before append and rejects Story-owned Actor behavior that bypasses the NPC tools. The post-commit registry observer independently refuses an event without matching provenance, so Ledger projection does not depend on diagnostics being enabled. Actor Session logs remain the authoritative behavior history; the Plot Ledger retains only pending events and the latest Brief's source events.

The Story Controller projects the Ledger in `StoryView` and exposes `commitDirectorBrief` plus exact-revision Run resume, single-Actor retry, pause, cancel, skip, and Actor-cancel operations through both Story Remote and `IStories`. It delegates execution to the Host `DirectorRunExecutor`, maps ownership, revision, and strict-field failures to explicit Remote failures, and never exposes physical paths or private Actor prompts.

## Alternatives considered

**Let the Director write a complete scene, then ask Actors to maintain private state.** This preserves fluent prose but makes character autonomy cosmetic because the Director still chooses every public line and action. It also leaves no event provenance for deciding whether a persistent character actually acted.

**Accept any ActorService speech or action event.** The Actor service is a domain provider and trusted player embodiment also calls it directly. Requiring the matching NPC tool call distinguishes autonomous model behavior from direct Host calls without changing player-origin provenance.

**Store the Plot Ledger only in the control Session.** A Session log preserves chronology but does not provide the Story-level current record needed by browser baselines, optimistic revision checks, or scenes that change over time. The Story domain owns current orchestration state while Actor Sessions own behavior history.

**Put dialogue and action suggestions in each Director Brief.** Suggestions would still let the Director choose persistent-character behavior under a different field name. Per-Actor context therefore stops at perceptions and uncertainties.

**Give every Actor the complete Story Bible and tell it to ignore private facts.** That would make information isolation a prompt convention instead of a structural boundary. The dispatcher constructs one Actor-specific snapshot and never places world truth or the Outline in that Agent's request.

**Store the long-range plan as prose in the Director Session.** Prose history is visible to one model but cannot support player locks, optimistic edits, review queues, category projections, or event-evidence requirements. The structured Outline remains non-canonical while making those ownership rules enforceable.

**Render Director output as sanitized raw HTML.** This would preserve model-generated tags but expands the accepted language and creates a second sanitation boundary beside the existing untrusted-Markdown renderer. Canonical Markdown keeps paragraph and emphasis semantics while the Host rejects ambiguous markup before persistence.

**Keep narration as plain text and rely on prompting alone.** Prompting does not reliably prevent literal `<p>` fragments, and plain text loses intentional paragraph and emphasis structure. Host normalization makes the stored format deterministic while retaining safe literary formatting.

## Testing

A real AgentLoop orchestration test loads the “Moonshadow Ledger” Story Bible, commits a Brief through the Director tool, provisions an Actor Session, dispatches that Actor, executes `npc_speak` and `npc_yield`, and observes both the provenance-linked Ledger event and public scene projection. The captured Actor request contains its own private knowledge but excludes Director-only world truth and the Outline. Runtime tests also cancel a model stream that is already running and verify that the attempt settles as cancelled without a projection; retry tests preserve accepted events without duplicating the Brief or scene event. Registry tests cover exact Run revisions, attempt generations, idempotent settlement, stale ownership rejection, late-event rejection, pause, resume, Actor skip and cancel, terminal Run cancellation, strict fields, invalid roles, persistence, and Brief correction boundaries. Controller tests cover all six Remote delegations and the missing-executor failure. Browser-component tests cover exact-revision console actions, queue details, scene projections, automatic character-state refetch, player editing, suggestion review, and distinct Outline and Brief status.

## Consequences

Storyweaver has a durable handoff point between world direction and character autonomy. The Director can frame scenes and maintain continuity without becoming a persistent character, while accepted NPC dialogue and action remain traceable to exact Actor tool events. Optimistic revisions preserve Actor input that arrives between planning passes.

The runtime now creates or resumes Actor Agents named by a committed Brief and wakes them when the Director dispatches or the player resumes an exact checkpoint. Players can stop or narrow execution without deleting completed evidence, and quota interruption no longer requires replaying completed Actors. The synchronous control request remains open until selected Actors settle or cancellation unwinds. A later Story-domain extension now resolves sourced outcomes, applies typed shared-world patches, and delivers audience-specific perceptions without weakening the provenance, ownership, or information-isolation rules. Independent scheduled wakes and semantic compaction remain separate work.

Director narration now has one explicit storage and rendering contract. New narration retains Markdown paragraphs and emphasis, known legacy paragraph fragments are normalized, and unsupported HTML/XML fails at the tool boundary instead of appearing literally or becoming executable browser markup.
