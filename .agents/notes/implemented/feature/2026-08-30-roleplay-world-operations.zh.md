# Agent Note: 角色扮演世界操作和可移植故事

Status: implemented

[English](2026-08-30-roleplay-world-operations.md) | 中文

## Problem

Storyweaver 已经具备持久 Story、隔离 Actor Session、Plot Ledger 与准确修订的 Director Run，但角色扮演循环仍停在持久 intent。玩家权限主要通过可编辑提示标记表达；Actor 发言与行动没有有类型的世界结果结算或受众投递。长篇记忆与多 Actor 讨论缺少持久审核和发言权状态。上下文检查可以描述区段，却不能安全编辑其顺序或预算。只导出 Storybook 也不足以迁移包含 Session 与世界文件的完整 Story。

较早的 AIAgentRolePlay MVP 展示了状态、记忆、讨论、旁观、打断和视角等有价值的玩家表层。但其中页面局部状态、任意深层更新、破坏式重抽和内存 watchdog 不能成为 Storyweaver 的权威行为，因为这些做法会绕过来源、修订、信息边界与恢复能力。

## Decision

版本 5 Story 聚合拥有带修订的世界、记忆、讨论、上下文配方记录与本次 Story 提示词覆盖值。世界变化使用严格的 `set` 与 `remove` 路径操作处理 JSON 值，并拒绝不安全的原型路径片段。一个有来源的 Actor 事件只能接受或拒绝一次；接受结算会记录有类型事实、应用 patch，并为声明的受众分别写入感知投递。Actor 只能收到自己的投递。可信 PlayerAuthority 分别提供指定方向、介入世界、代为发言与代为行动命令，并保留玩家来源，而不是复用普通聊天。

长篇记忆采用提案与审核流程。待处理或已拒绝条目不会进入模型上下文。批准可以取代较旧的同类已批准条目，在保留审核历史的同时只暴露当前有效版本。持久讨论会记录发起来源、参与者、当前发言者、队列、记录、轮数、最大轮数、总结阶段、完成状态与玩家干预。故事书保存玩家为自动讨论设定的最大轮数；该字段缺失时物化为 4 轮，已经显式保存的值不会被隐式迁移。每场讨论在开始时保存当前值的快照，而高级玩家操作可以直接为单场讨论指定轮数。导演根据剧情自动发起讨论并选择参与角色和开场顺序，但不能改写玩家的自动讨论轮数上限。一次 Host 调度会沿持久发言权自动接受 Actor 发言并持续推进，直到玩家明确介入、Actor 失败、Actor 自主结束，或达到轮次预算；它还会根据参与人数和持久发言记录派生已用与剩余发言机会，以及开场、发展、收束或总结阶段，并把同一进度交给导演和参与讨论的 Actor。Actor 从自身目标与利害出发推进，而不是迎合隐藏的剧情答案；进入收束阶段后，Actor 会作出具体选择、协商、带后果的拒绝，或由角色自己判断是否结束。当发言权再次轮到当前 Director Run 中已完成的 Actor 时，Host 只在当前 Run 修订上重新入队这一准确的发言权拥有者，保留早先已接受事件引用并签发新 attempt；普通已完成 Actor 仍不可重试。玩家可以申请发言、要求导演收束、在请求处理后恢复，或中断讨论。发言或收束请求处于等待状态时，即使当前 Actor 调用仍在收尾，玩家也可以取消；带准确修订的清除操作会移除干预标记，并让持久讨论恢复为自动调度的 `active` 状态。自然结束或耗尽预算会进入持久总结状态；Host 通过一条独立限制次数、携带准确修订的续步要求导演先旁白总结具体共识、未决分歧和紧接的转场，随后才能完成讨论。该总结与成功关闭会完成当前旁观推进请求，不再建立独立 Brief 或讨论后剧情拍；细化决策见 [Director 开局工具调度](../bug-fix/2026-09-03-director-opening-tool-scheduling.zh.md)。手工发起和调整发言权只作为高级干预保留。

规范故事书保存一份可复用的导演提示词，以及每名 Actor 各自私有的角色提示词。新运行随玩家创作的故事书资料复制这些基础值。Story 聚合通过准确修订保存覆盖值，因此修改一次运行不会污染其他运行。读取和更新 Remote 会返回基础值、覆盖值、最终生效值与来源；清除覆盖值即可恢复故事书默认值。导演只会在锁定产品策略之后收到最终导演自定义提示词，每个 Actor 只会收到自己的最终角色提示词。导出、导入和重新加载会保留两层数据。

上下文配方是面向 Director 与 Actor 的完整准确修订列表。玩家可以启用、排序并为创作区段设置字符预算。产品策略、工具协议与 Actor 身份被锁定，不能关闭。模型组合与浏览器预览应用同一配方，并报告完整字符数、实际纳入字符数与估算 token。Actor 组合会按 Actor 身份过滤世界感知、记忆备注与讨论。

Story Controller 通过不暴露路径的有类型 Remote 提供这些操作，并在 `StoryView` 中投影运行状态；提示词通过明确的读取与更新边界传输，避免广泛投影私有上下文。Director 工具可以结算一个有来源事件、提出记忆，并自动开始或收束讨论，但不会获得玩家审核权限。角色扮演 Client 提供独立提示词工作区，以及响应式、状态优先的世界操作工作区；底层表单通过渐进披露保留。故事列表提供常驻导入操作：独立版本 4 Storybook 会在完整校验后成为新的基础设定模板，完整 Story Package 则以全新聚合身份导入。

严格的版本 1 Story Package 包含带提示词覆盖值的 Story 记录、带提示词基础值的规范故事书、每份已注册 Session 日志，以及 `world/` 下受限的可移植文件。若任一已注册 Session 不可用，导出会失败，避免产生静默缺失的包。导入会在变更前校验大小限制、路径、角色 invariant 与每份 Session 日志，然后签发全新的 Story 身份和 Session 身份，并重写全部内部归属引用。它绝不会覆盖已有聚合，也不会恢复导入包中的不透明 id。

## Alternatives considered

**复用 MVP 的任意嵌套状态合并。** 这种方式灵活，但可能修改保留对象路径、擦除无关状态，也没有准确修订冲突边界。有类型的路径操作让每次变更都可检查，并拒绝不安全片段。

**把已接受 Actor intent 自动当成结果。** 这会把角色意图、世界真相与受众知识压成一个事件。显式结算保留这些差异，也让拒绝成为持久证据。

**允许模型直接写入长期记忆。** 模型生成的记忆会变成自证上下文，并可能静默改写连续性。提案加玩家审核既保留持久能力，也不会授予规范化权限。

**使用内存循环或 watchdog 运行讨论。** 进程重启会丢失发言权和轮次进度。Story 自有讨论状态让恢复与玩家介入保持确定性。

**让导演选择固定或模型生成的自动讨论轮数上限。** 固定值无法同时适合短对话与大型群像，而模型生成的上限会让玩家偏好退化为建议。故事书中的值归玩家所有并由新运行继承；模型可以提前结束，却不能扩大预算。

**暴露通用上下文 JSON patcher。** 它可能关闭安全策略，或向 Actor 泄露 Director 专属材料。封闭区段词汇和锁定必需区段会保持信息边界。

**只导出 Storybook JSON 或保留导入 id。** 只导出 Storybook 会丢失运行连续性；保留 id 会造成冲突，也可能意外接管已有 Session。Story Package 会在明确限制内保持完整，并始终作为新聚合导入。

## Consequences

Storyweaver 现在闭合了 P0 角色扮演循环：从有类型 intent 到显式世界结果，再到受众专属感知。它也提供长篇游玩所需的 P1 连续性表层：可复用与单次运行提示词创作、审核并可取代的记忆、受玩家轮数约束且自动编排和可恢复的群体讨论、安全上下文预算与完整可移植 Story 交换。讨论进度由持久输入派生而不重复保存，因此重启后仍能从相同输入算出相同阶段。自动续步可能在一个玩家回合内消耗多次 Actor 调用，但玩家设定并持久化的轮次预算仍是硬上限。Client 借鉴了 MVP 有价值的操作分类与常驻实时讨论强调，同时继续以 Host 状态为权威，并让玩家干预退居可见自动状态之后。

结算不会从正文推断，记忆批准仍是可信玩家动作，导入包始终创建新身份。叙事时钟仍没有独立 scheduler，语义记忆不会自动压缩，更丰富的素材专属行为留待后续实现。
