# Agent Note: 故事撤销检查点和可创作上下文模块

Status: implemented

[English](2026-09-01-story-rewrite-checkpoints-and-context-modules.md) | 中文

## Problem

同会话撤回只替换可见 Session 表层，却保留 Story 自有的世界、Plot Ledger、Director Outline、记忆、讨论和持久 Actor 历史。改写后的 Director 因此仍会依据已撤销回合推理。上下文配方同时还是封闭的运行态区段列表，导演与演员的思维风格约束无法独立创作，玩家也不能新增自己的上下文模块。

## Decision

`agent/history-rewrite` 成为带作用域的串行准备边界，并在追加替换输入前运行。Storyweaver 会在玩家回合前保存检查点，其中包含权威 Story 运行态和每个活跃 Actor Session 的可见边界。检查点保留数量属于部署配置策略，由 `storyTurnCheckpointLimit` 控制，每个 Story 缺省保留 128 条。改写带检查点的玩家回合时，系统先用明确的撤回通知遮蔽所有后续 Actor 表层节点，再恢复 Story 快照。检查点功能上线前的首个玩家回合可恢复到确定的空运行态基线；其他没有保留历史快照的回合会在 replacement 接纳前被拒绝，不会从不匹配的当前状态继续。未参与此边界的外部领域保持不变。

Chat 只在最近一条 durable 纯文本用户消息上显示重编铅笔。点击后，那个气泡会原位变成受控编辑器；「取消」与 Escape 不会暂存重编，只有「发送」才直接通过 Session 提交，而且不会借用或覆盖全局输入框的草稿及附件。若原位提交被拒绝，系统会清除完全匹配的暂存重编目标，防止之后的普通提示词误用陈旧的重编意图。

DeepSeek thinking 请求会把每条 Assistant 历史的 `reasoning_content` 显式带回 API。真实 reasoning block 原样串联；空推理工具回合和 Assistant 角色的创作上下文使用空字符串，避免字段缺失导致整个重发请求被 400 拒绝。关闭 thinking 时仍不为普通 Assistant 消息伪造该字段。

Director Outline 工具说明现在会显式告知受当前 JSON-schema 子集限制而无法机器表达的语义约束：情节拍优先级只能是 `1..5`，已埋设及后续状态的伏笔必须带证据引用。大纲输入解析和最终跨字段校验会在工具错误中保留 Zod 问题路径，使无效调用直接指出具体字段，不再只返回会诱发盲目重试的“patch fields are invalid”。

上下文配方现在区分固定内建 id 与稳定 `custom:*` id。导演与演员配方分别内置可编辑的分析式思维约束和第一人称沉浸思维约束。创作区段持久保存标题和完整正文，可以选择任一支持的消息角色，参与排序和启停，并通过有效预览与模型请求共用的同一渲染器。工作台支持新增、编辑、排序、启停、角色选择和删除自定义模块，并提供行内必填校验。

Director 请求分区会把策略、设定、Storybook 素材、已批准记忆与低频变化的 Director Outline 视为可缓存的前置 `system` 上下文。World、Plot Ledger、讨论、Brief、Actor 状态和首个创作非 system 区段会开启历史后的尾部。已批准记忆或 Outline 修订会有意使后续缓存链失效；普通高频世界更新不会重写更大的前置块。已知玩家控制信封会在 pre-step 接纳时拆分：持久历史保留压缩后的有类型值，解释协议则只进入该回合的请求快照，并位于保存的动态尾部之前。未知括号 prose 绝不会被隐式重新分类。

Storyweaver 现在会把这种物理分区与已记录的[请求历史投影](../architecture/2026-09-02-request-history-projection.zh.md)结合。每个新的 Director 或 Actor 轮次都会开启请求序列，其历史只包含当前轮次事务；同轮推理、工具调用、结果和纠正保持协议完整，后续轮次则从有界 World、Ledger、Brief、讨论、状态与已批准记忆投影恢复连续性，不再重放旧模型轨迹。

## Alternatives considered

**继续把撤回视为只影响 UI 的 Session 操作。** 拒绝，因为模型仍会读取已撤销的权威 Story 状态。

**通过重放旧聊天文本重建 Story 状态。** 拒绝，因为工具写入和 Actor 私有状态属于结构化领域数据，无法从对话文本忠实恢复。

**在配方外硬编码两段思维提示。** 拒绝，因为用户无法检查或自定义，预览也会与实际请求组成分叉。

**把完整玩家控制样板作为普通历史持久保存。** 拒绝，因为重复协议文本会消耗上下文，还可能被误认为长期故事事实；完全丢弃整条消息也不可取，因为具体的期望走向仍是有用的连续性数据。

## Consequences

新的玩家回合可以在 Session 展示、Story 权威状态和 Actor 可见私有历史三个层面真实撤销。上线前首回合也能确定地回到初始运行态；更晚回合的检查点若已不可用则会封闭失败，玩家仍可选择保留窗口内的回合，或发送普通新回合。DeepSeek thinking 模式的重发不再因空 reasoning 回合或 Assistant 上下文模块缺字段而失败。无效的 Director Outline 更新会得到可操作的字段级反馈，不再反复猜测重试。有类型控制历史会保留玩家意图，但不保留单回合解释规则；请求历史投影会阻止旧推理和工具轨迹意外成为连续性，而低频 Director 上下文在其归属修订改变前仍可使用提供方前缀缓存。外部文件改动和未接入回滚领域的工具仍不会撤销。现有当前格式 Story 记录包含两个创作模块，不增加旧格式兼容分支。定向 Host 测试与 TypeScript 构建会验证撤回、有界检查点保留、上下文分区和指令解析。
