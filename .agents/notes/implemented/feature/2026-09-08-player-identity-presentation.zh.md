# Agent Note: 玩家身份附注与审核展示

Status: implemented

[English](2026-09-08-player-identity-presentation.md) | 中文

## Problem

冗长的外观称呼使玩家难以区分发言人。人物、认知和记忆审核直接展示 JSON，掩盖了内容，也与剧情阅读卡片不一致。用户明确要求玩家侧用括号显示真实姓名，并统一这些视图的展示风格。

## Decision

玩家查询为可见人物、历史发言人和代演选项增加独立的 trueName 字段，读取所选实例与剧情修订的记录。发布时的称呼、实际对白、人物认知、模型安全引用和模型上下文保持原样。称呼与真实姓名相同时只显示一次；缺少附注时保留原称呼。界面不拼接作者名单来构建玩家称呼。

人物摘要、个人判断和记忆提案共用卡片、状态标签与依据折叠区。界面本地化协议状态，并保留原始自然语言内容。高级记录和 JSON 编辑仍可访问。此决策扩展[独立剧情架构](../architecture/2026-09-07-independent-narrative-instances.zh.md)的玩家展示边界；演员隐私继续使用独立的视角查询。

## Alternatives considered

**替换正文中的全部姓名。** 这会改写实际对白与历史称呼，也可能把误认与真实身份混为一谈。

**在共享模型视角记录中加入真实姓名。** 这会向演员泄漏未知身份。附注只属于已授权的玩家查询。

**继续以原始 JSON 为审核主体。** 这能保留精确结构，但增加了普通阅读和批准的难度。详情保留该结构供高级检查。

## Consequences

即使所选角色尚未认识对方，玩家也可以识别陌生人和易容人物。这是有意提供的玩家信息，不是世界中的身份揭示。当前视图使用当前真实姓名；历史修订查询使用该修订中的姓名。无需迁移事件或存档。核心测试验证玩家附注、历史称呼、私密受众和不变的模型上下文；无密钥浏览器验收覆盖审核批准、卡片、存档重载和窄屏布局。这些测试不衡量真实模型表现。
