# Agent Note：通过场景指导落实用户要求的角色表演

Status: implemented

[English](2026-09-10-director-performance-cues.md) | 中文

## 决策

导演权限包含代表用户向角色执行器提供可落实的表演指导。现有 scope=scene 的 style 命令承载面向指定接收者的目标、处理方式、语气、主动性和篇幅要求。调度示例旁提供对应工具示例。成功写入指引后再 finish 或推进讨论；写入指引本身不调度演员，也不发布行为。导演可查看有效指引并清除或替换，不修改永久角色设定。

演员请求将场景指引标记为作者侧表演指导，不是感知或证据。演员根据实际玩家控制权和自身可知内容，以角色口吻主动落实目标。自主性用于明确表演由谁完成，而非赋予演员否决指导的普遍权力。导演仍不能把未提交的角色选择写进旁白；指引不能确立他人的同意、未知事实或行动成功。源码无法证明任意自然语言指引不含秘密，因此模型协议也禁止通过指引转发私密作者上下文。

## 证据与参考

旁观主动性调整后，本地请求已包含新规则，主角也进入调度，但近期演员正文仍约为 97～233 字符。笼统要求充分展开没有提供有效的写作尺度。用户指定的 AIAgentRolePlay 参考项目通过 spotlight_cue 向每个接收者分别提供情境提示。本项目复用已有按接收者划分的场景指令机制，不增加另一套指引存储或调度器。不照搬参考项目中的强制问句结尾、对玩家标签主角的一律排除或用无关灾难打破停滞的做法。

## 正文与推进

导演展开原因、可观察变化和实际影响；演员展开回应并提出具体行动。重复氛围、犹豫和改述警告不足以构成新的实质性情节。默认编辑目标为旁白 4～6 段、500～900 中文字符，演员正文 3～5 段、400～800 字符；其他语言采用相当的内容深度。现有 lengthPreference 与场景指令可覆盖这些目标；短暂插话、私有准备、沉默和维护操作仍合法。不新增硬性下限、自动重写循环或额外讨论轮数。正文增长可能增加生成时间和 token 用量，不代表剧情一定推进得更快。

## 验证

应用测试覆盖单个演员的指引传递、与事实证据分离、演员及实例隔离、切换场景后的排除和历史回放。真实 Harness 组合执行 style 后再 finish，记录生成的演员指导，并为导演/NPC 规则及工具描述保存快照。可选的真实供应商诊断使用两个中立的临时角色，记录收到的指引、正文长度并检查调度成功。文学质量和情节推进是否恰当，仍需人工审阅生成内容。

一次 DeepSeek V4 Flash Low 诊断约 50 秒完成，旁白 490 字符，两名演员正文分别为 460 和 538 字符。两人分别收到指引，提出了过河方案、风险判断和分工。这只是一个中立场景，不是与用户故事的 A/B 对照、吞吐量基准或事实一致性保证。相关无需密钥的测试共 72 项通过；完整构建与可选真实模型诊断也通过。
