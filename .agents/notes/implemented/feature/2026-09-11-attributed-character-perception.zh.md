# Agent Note：带人物归属的角色感知

Status: implemented

[English](2026-09-11-attributed-character-perception.md) | 中文

## Problem

角色证据只有正文和人物引用时，模型必须另外查人物表，无法直接读取交流对象与传递方式，同一次提交中的言行顺序也会丢失。导演遗漏关键可感知细节或保留过时场景指导时，玩家旁白与角色感知也可能脱节。

## Decision

接受言行时，系统在每份接收者证据中固定保存人物归属：发言者或行动者、已知称呼、局部引用、发言对象与传递方式，或者动作的人物目标。台词与行动正文保持原文，私人意图和目的不进入他人感知。现有[寻址规则](../bug-fix/2026-09-10-npc-reference-routing.zh.md)继续生效：长的不透明引用用于工具寻址，称呼用于读懂历史；姓名不会被自动解析，也不直接构成已确认身份。

角色证据按条数优先选取近期记录，不设总字符上限，再按发布及言行顺序呈现已选内容。行动尝试与感知到的结果保持区分。原文回忆和固定证据保留同样的人物归属；回忆分页优先返回近期记录，并携带顺序信息。发布时的称呼不会随着后来认出身份、人物离场或换装而改变。已有纯文本证据从已接受的行为中恢复发出者称呼与顺序；未保存的历史交流对象投影明确标为未知。读取不会迁移记录，也不会改写已记录的模型请求。

角色指导允许使用外貌或自然称呼向陌生人交流，并在介绍、持续交往或当前目的需要时询问姓名。紧急场景不要求先完成命名仪式。听到的名字可以形成有来源的个人身份判断，但不自动证明真实身份。

导演旁白仍只展示给玩家，显式投递仍是各角色的感知。提示词要求导演保留相关的可见动作、可闻原话、细节和顺序，并更新或清除被已结算发展推翻的场景指导。角色指导要求以较新的感知为准，不执行建立在过时情境上的指引。本次没有引入旁白广播、自动感知筛选、语义校验器或额外模型调用。这是对[独立叙事架构](../architecture/2026-09-07-independent-narrative-instances.zh.md)的补充，不替代其中的感知归属规则。

## Alternatives considered

- 把完整旁白发送给所有角色会泄露私人及场外信息。
- 自动筛选文学旁白会增加模型开销，仍无法可靠推断注意力、遮挡或感官条件。
- 用当前认知重建历史交流对象的称呼，可能泄露后来获得的身份认知，或追溯关联不同伪装。
- 用姓名替代精确寻址引用会引入歧义，并绕过观察者各自的身份边界。

## Consequences

人物归属会增加入选证据的文本量。后续上下文长度调整取消了总字符上限；条数仍限制近期历史范围，其余原文仍可检索。[领域测试](../../../../packages/story/roleplay-core/tests/world.spec.ts)覆盖顺序、受众隔离、历史认知、伪装和离场、回忆、固定记录、存档回放及伪造归属。[上下文测试](../../../../packages/story/roleplay-core/tests/context-cache-order.spec.ts)覆盖先选近期内容、再按时间呈现。[真实执行测试](../../../../packages/experimental/actor/tests/narrative-executor.real.spec.ts)将另一角色带归属的发言与动作通过 SQLite、Loader 和 Harness 送入模型请求，同时用快照固定角色和导演指导。这些检查证明投递及校验行为，不保证文学质量或导演永远保持一致。
