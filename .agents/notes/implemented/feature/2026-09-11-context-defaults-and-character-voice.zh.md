# Agent Note: 初始上下文默认值与角色表达

Status: implemented

[English](2026-09-11-context-defaults-and-character-voice.md) | 中文

## Problem

通用创作指令可能让不同角色都变成解释证据、确认许可和重复方案的发言者。系统初始上下文的变更还必须保护已有故事书和实例拥有的配置。

## Decision

`StorybookLibrary.contextDefaults` 与 `saveContextDefaults` 在书库默认设置命名空间中持有经过修订校验的配方。没有显式配方的新 schema-v6 草稿获取副本；导入时明确提供的配方保持原样。发布版本和实例不跟随此设置。已有草稿省略配方时，保存仍保留其历史隐式值；旧发布版本省略配方时，使用固定的历史配方。缺少创作模块时也保留其历史解释。读取不写入或升级配置。

侧栏打开“上下文默认与本书共享”。“系统初始上下文”编辑完整配方，分别提供保存和放弃草稿重新载入操作；未保存编辑可跨导航保留。本书共享模块继续按 BookId 隔离，由实例主动选择跟随。修改系统默认值不会发布共享模块，也不会改变共享订阅。[本书共享说明](2026-09-10-shared-creative-settings.zh.md)负责该机制。

演员指导保留选择的篇幅偏好，将强制的回应、理由、方案顺序改为依人物而定的具体贡献。语汇、修辞习惯和关注点来自角色与关系。运行指令区分私有执行规则、个人记录、场景指导和虚构交流。知识归属仍限制提交的记录；控制权与裁定仍由既有应用强制执行。剧情涉及危险、所有权或个人意愿时，角色仍可按场景动机表达顾虑。

共用的演员提交结构将记忆限定为其意义能持续到当前场景之外、对人物有个人重要性的经历。事件刚发生，不构成把日常过程复制进私有记忆的理由。演员执行指引要求转述他人的话时保留来源与条件状态；有条件的修车提议并不是已确定的结论。同一次提交的言行之间不会插入他人的回应，因此请求别人配合后，不能在同轮执行依赖对方配合的动作。创作指引鼓励人物作出自己的下一步选择，不接力复述他人的警告，也不逐项宣告收到的事实。这些是模型指令，已接受的场景历史和世界裁定仍是权威来源。

默认值将普通交流视为一次有用的对话推进，通常用一到三句说出口的台词，而非以 3–10 句为目标。角色可依照自身利害与关系回答、回避部分问题、行动或保持安静，不预设统一的两步发言结构；冲突、情绪、重要决定和多项新信息仍可展开。作者篇幅偏好与已保存的表演模块优先。这项默认值只在新配方或显式恢复时复制，不迁移已有故事书和实例。

讨论准备要求私有、可修正的意图，不要求发言提纲。演员只看到自己的立场和积极程度，不携带准备时间戳或轮次计数。公开席位指令允许放弃发言，以及结束需要外界结果才能继续的交流。导演指令要求差异化指导和裁定待处理尝试，避免重复猜测。这些指令不会自动关闭讨论或制造共识。

导演创作指引把作者章节视为候选压力与机会，让真实选择的后果进入下一处局面；新问题由有具体需求的人和会变化的代价承载。调度考虑候选人物各自的利害与能够回应的对象，不向所有人分派同一方案，也不要求每位在场演员发言；别人已经说清关键点时，角色也可以保持安静。模型仍可能不用这些选项，所以需要以实际对白记录评估质量。

讨论邀请聚焦一个需要角色彼此回应的议题。导演执行指引要求：待结算的世界结果或外部当事人的回答决定选择时，先延后邀请；可用普通对话处理的汇报议程则予以拒绝。场景指导说明眼前目标，不编排逐项汇报。裁定尝试时，导演在旁白中保留记录的行动者，不把行动改派给别人。

## Baseline evidence

本地月影账簿的 BookId 为 `f51c0256-c263-483f-99ef-e892dc7ea572`，发布版本为 `a21a44e6-68a7-4ea5-b8cf-a8423c949f46`（第 1 版），草稿修订为 3。两份书文档都没有保存上下文配方。在两个仍保留的实例中，`story-54a615ff-1ba6-4b5b-8d1d-8be0bf7e1cb0` 的配方修订为 0，最近运行于 9 月 9 日；`story-5a310eb6-ecaf-482c-8b44-e24e3f56b80f` 的配方修订为 4，最后保存于 `2026-09-10T15:53:48.785Z`，之后继续生成。采用后者作为初始化基线，因为其已接受证据包含用户反馈的对白，且模型请求包含保存的编辑。

基线保留来源顺序、启用状态、消息角色、末尾 user 角色的思考模块、导演 500–900 中文字篇幅和演员 300–600 字篇幅。保留演员新增思考要求的意图：以角色身份思考，不进行常规工具或字数规划。原配置未保存数值型旁白字数设置，因此默认不启用它。创作措辞针对个性表达调整；角色知识、世界、场景指导和运行历史不复制到系统默认值中。

记录的请求指向数个相互强化的来源：先解释理由再提出方案的通用要求；盖尔设定中的学者式区分；要求盖尔提出可中止试验、要求影心先验证再判断并说明取舍的场景指导；将这些模式带入后续上下文的私人意图与已接受对白。执行轮次术语也确实出现在已接受对白中。这些证据支持多个来源相互强化，而非单个模型供应商设置，也不能据此要求所有人物都变得寡言。

本任务明确执行的本地修正仅将新版创作文字和四条场景指导应用到已定位的实例，使配方更新到修订 5，叙事状态从修订 120 到 125。其保存的演员思考文字和修订 120 的历史回放保持一致。本地修改前快照保留原配置。系统配方另存为默认修订 1；故事书、发布版本、其他实例和共享订阅不迁移。此修正是有记录的作者操作，不属于启动行为。

## Alternatives considered

- 缩短所有回复会掩盖重复，并覆盖保存的篇幅和角色偏好。
- 将所有角色改为统一的自然对白模板会消除有意义的差异。
- 读取时或从旧发布版本创建实例时使用最新默认值，会静默改变已有故事书。初始化副本和固定的省略值解释保留各自独立性。
- 跨书动态共享完整系统配方会耦合无关故事。本书共享仍是单独的主动选择。

## Consequences

[领域测试](../../../../packages/story/roleplay-core/tests/world.spec.ts)覆盖修订冲突、持久化、副本和显式值、旧书省略配方、版本和实例不变、本书共享隔离及私有准备投影。[执行器测试](../../../../packages/experimental/actor/tests/narrative-executor.real.spec.ts)通过真实 Loader 与 Agent 循环记录模型可见指令。[浏览器测试](../../../../apps/web/tests/player-performance.e2e.ts)保存并重载系统配方，同时检查已有书、故事实例和共享值没有变化。

隔离诊断使用已记录的月影账簿演员输入和当前配置的 DeepSeek 模型；其输出不进入实际故事。首批样本仍有部分既有谨慎立场的重复，一份回复的工具 JSON 格式错误。指令快照证明实际传入的指导和宿主行为，不证明文学质量已经稳定。积累的角色历史可能保留旧习惯，因此仍需继续运行故事来评估表达差异和实际推进。

后续隔离探针让三名角色分别在独立实例中回应同一初始观察，并在默认值修改前后运行。修改前孩子在一次探索动作后分四段发言，摆渡人与店主原本已有不同且直接的声音。修改后首轮孩子压为一段，但成年人仍出现局部别扭措辞；第二次复采得到简短且有区分度的回应，实务动作仍在。三次探针的原生总输出 token 分别为 3,416、2,912、2,945；缓存读取随请求变化，不能由这些样本证明成本或质量改善率。实际执行请求、观察者正文和原生用量保存在 `.artifacts/voice-performance/`。探针未覆盖多回合重复和讨论席位质量；更短的默认指导也不能保证随机生成始终口语自然。

配对复测在同一构建版本中补全在场人物，修改前实例显式加载旧默认文案。六个请求均包含相同的十二个上下文区段 ID，演员表演文字修改前 906 字符、修改后 1,037 字符。孩子两侧均有两段台词，但后者更聚焦；摆渡人由三段缩为两段，同时保留登船安排；店主仍简短。修改后店主调用用了两步，摆渡人可见台词变短却输出了更多 token。另用两回合摆渡人配对探针先结算系绳尝试，再投递客人递包提问；两侧都接话并重复安全提醒，新版回答更短，且伸手接包。这些样本确认指导投递和局部口吻变化，不能宣称普遍节省 token，也未测长期重复。

独立的五角色探针采用原创的《余烬与晨星》四十章规划及开场。最初的双轮样本里，角色将有条件的修车说法转述为确定结论，其中一些还被写入记忆。修订后的提交结构和转述指引通过真实 Loader 与模型运行，并为每项待处理检查提供明确的世界反馈。修正测试场景后的两阶段样本中，十个演员轮次全部提交，公开回应没有断言未经核实的车行库存。部分场景事件仍进入了私有记忆，药师的一次动作也提前假定孩子会配合、未等她回答。样本只覆盖一个上午，不能证明长期人物成长或事实连续性完全无误。探针将请求、工具调用、观察者剧情和原生用量记录在 `.artifacts/longform-performance/`。

后续压力场景加入发热的旅人、持有可能合用车轴的车夫，以及灰隘缺热的急信。配对演员指导对照中，额外的口吻指令并未优于原有指导，因此已撤回。导演探针显示另一种流程化对白来源：一次邀请把多项汇报打包成群组会议，后续场景指导又把凭据、检查、路线和回信逐项交给主角安排。导演现在延后这种邀请，场景指导聚焦眼前一项选择，并在提出条件后调度外部当事人回应。同一剧情边界的复跑没有开启群组讨论；连续两次续跑中，车夫同意并按印换轴，工匠装轴，队伍选择慢道。使用聚焦指导措辞再次复跑也未开启群组讨论，但主角仍在同一轮向多人交代，药师对病人的后续状况说得过于肯定。这些都是随机场景，不能证明对白已彻底摆脱编排感。记录中仍有逐项分工和凭空补出的精确路程，口吻与事实依据仍需继续检验。

新建实例中的五人三阶段对白对照：现有指导产生 23 条公开台词；增加“优先向一个人说话”的规则为 24 条；大幅缩短指导为 27 条；人物设定加入对白示例为 25 条。条数只作观察，不能当作质量分数。各版本仍有重复的风险提醒和事务讨论，因此没有把这些候选写入默认值。对白示例试验参考了 [SillyTavern 的人物设计文档](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/Characters/characterdesign.md#examples-of-dialogue)，在本应用样本中未见明确收益。

另一个厨房场景显示了更强的会议感来源。强制五人轮流发言时，一张被汤水洇湿的信纸很快变成路线与装备检查。只给孩子一条关于信纸的轻提示，改变了他的当下回应，其余被强制调度的人仍转向出发准备。让导演自行调度时，原故事书立即引入黑匣委托与柜台员；仅增加安静候选节拍或通用关系指导，也没能稳定保住厨房互动。把当前开场方向及转入委托的条件明确写进作者指导后，两次独立导演运行都留在厨房，没有引入新委托或柜台员；公开记录各有 14 行，第二次出现了递布等人物间的小动作，而非任务会议。这支持作者明确当前节拍与转场条件，不能保证所有安静场景都自然：两次仍提到路线或靴子，也有模型补写的背景细节。逐轮报告和可导入存档保存在 `.artifacts/longform-performance/voice-new-instance-*`。

导演 finish 的工具描述引导依赖上一人实际回应的场景先调度一人，只在几人各有独立行动理由时批量调度；style 工具示例不再要求角色解释计划、分段提出方案。这些仍是模型指引，不设人数硬上限。启用[导演响应式接话](2026-09-29-reactive-director-speaker-choice.zh.md)后，同一次推进可依据已接受的单人回应继续选择。此前构建版本的两次厨房回放分别出现逐次单人调度和两人调度，未再一次传唤五人；一次仍谈雨和靴子，另一轮较集中于湿信。不能据此认定语义趋同已解决。曾试验将 finish 限制为一人：本轮便在首名角色后结束，依赖玩家再推进，故未采用。压力场景复核中途收到供应商余额不足，未得到可比较结果。
