# Agent Note：上下文长度与原生计时

Status: implemented

[English](2026-09-11-context-length-and-native-timing.md) | 中文

## Problem

组装后的上下文字符上限会无声省略整条证据，并拒绝过长的必需设定或置顶原文。叙事 token 展示也缺少原生 DSH 事件已支持的首 token 延迟和解码速率。

## Decision

ContextAssembly 完整纳入已启用配方模块的文本，不设总字符上限或配方模块条数上限。演员与导演自动上下文现在纳入全部已授权、未被摘要替代的历史和有效记录，不按条数选取。组装时按模块 ID 索引来源，同时保留配方顺序、消息角色和来源标识。观察者过滤与有效摘要替代继续生效。`recallCharacterLimit` 和 `queryPageLimit` 只限制显式回忆单页，长原文可续读；旧 `PerspectiveBudget` 及条数配置已移除。旁白输出字数设置保持独立。此调整更新了[带人物归属的角色感知](2026-09-11-attributed-character-perception.zh.md)中的长度策略。

公开的 session-stats deriveTurnPerformance 复用原生投影对完整持久日志的折叠。已结束技术轮次提供可选的首个进入步骤 TTFT 和平均解码速率。速率使用有效步骤的提供方输出 token 总数除以对应解码总秒数，不含预填充和工具等待。非空推理和工具增量也计为首 token；步内重试沿用原生语义。首步计时缺失时不使用后续步骤替代，推理 token 不重复累计。

执行请求索引将这些读数附加到同轮每条请求。可携带存档保留计时，旧存档缺失的字段保持未设置。原生 token 展示继续使用；正文回合底部和请求详情增加秒与 token/秒。缺失读数显示“未记录”，与有效零值区分。不增加提供方请求，也不向模型上下文加入统计文本。

## Alternatives considered

- 提高字符上限仍会造成任意遗漏及过长置顶失败。
- 保留自动条数筛选仍会无声省略已授权历史，即使没有总字符上限。
- token 除以整轮耗时会混入工具等待，直接平均各步速率则会给长短步骤相同权重。
- 根据 token 数补猜旧存档计时会制造并未测得的读数。

## Consequences

完整的已授权历史会增加模型输入，并可能触及提供方上下文窗口限制；应用不会无声截断，提供方容量仍是外部约束。有效摘要仍替代其覆盖的原文（置顶除外）；归档、遗忘或无权限记录仍被排除。回忆单页限制继续提供明确的续读机制。按索引组装减少本地来源收集工作量；它不改变模型输入长度，也不能据此推断提供方延迟下降。

领域测试覆盖长设定、感知、置顶、时间顺序、停用模块和受众隔离。原生计时测试覆盖多步加权速率、缺失用量、重试、零值和未结束轮次。请求索引与存档测试覆盖字段传递和兼容性。界面测试覆盖单位和缺失值；真实 Loader 浏览器布局测试验证已记录计时与窄屏溢出。构建与定向检查记录在任务中；变更范围之外的全仓文档失败单独说明。
