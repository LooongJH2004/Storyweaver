# Agent Note：上下文同步页面

Status: implemented

[English](2026-09-11-context-sync-workspace.md) | 中文

## Problem

来源选择、保存来源、发布表单和复制操作在各上下文模块内重复出现，书稿导入和系统初始配置又分散在其他位置。玩家不容易判断修改的是哪份配置、影响哪些故事，以及持续跟随和复制一次有什么区别。

## Decision

同步页支持双向操作，左侧固定为本书共享配置，右侧固定为故事。反向同步选择故事已保存的值，通过既有 fromInstance 修订校验仅发布选中模块。共享或故事存在未保存修改时禁止反向发布；跟随关系保持不变，既有跟随故事在下次玩家操作时采用新的共享修订。共享内容为空时也可直接从故事填充。

“上下文同步”左侧显示本书共享内容，右侧显示目标故事，中间用箭头标明同步方向。五个紧凑行对应可选模块与目标的当前来源。一个主按钮同步所选项，默认复制一次，另用明确选项开启以后自动跟随共享更新。上下文编辑器保留来源提示和一个管理链接。

共享内容编辑后自动纳入本次统一保存，提供逐项撤销和放弃草稿。草稿按书隔离并跨页面保留。取用故事已保存值需要显式操作，不直接发布。版本冲突保留草稿，要求重新核对。

模块全文在对比窗口中查看。共享内容编辑与来源恢复放入次级窗口，书稿导入与新书初始配置放在“更多”下。恢复时区分保留的独立值和开局固定书稿。状态区分已更新、待更新和暂停跟随。未保存的实例草稿阻止同步。共享草稿可继续编辑，同步使用已保存的共享值；主按钮明确标注此选择，旁边提供继续编辑草稿的入口。导入书稿保留其他未保存修改，返回编辑器检查、保存和发布。

CreativeSettingsApplication.read 在已有原子读取中增加生效配方和固定书稿配方。预览不应用待同步值，也不推进剧情版本。来源绑定支持单项或非空、无重复的多项选择，所有所选变更一次提交。任何值不可用或版本过期都会拒绝整次操作。发布与绑定继续拒绝运行中修改。共享范围为旁白篇幅、导演与角色的创作要求和思维模式。

## Alternatives considered

- 只修改各处按钮名字仍保留重复流程和互相干扰的保存语义。
- 只将控件分组到标签页仍无法直观看到来源与目标；同时展开全部说明则会淹没同步操作。
- 用共享内容替换整个故事上下文超出了现有五项共享模块的权限范围。
- 导入书稿后自动保存可能覆盖未保存的创作，也容易让玩家误以为已经发布。

## Consequences

同步操作集中到一个页面，原地文本编辑仍在配方编辑器完成。详细内容按需展开，窄屏将来源与目标上下排列。窗口受视口高度约束并可内部滚动，沿用原生窗口的焦点恢复和键盘关闭能力。

真实 Loader 浏览器场景覆盖桌面对齐、收起侧栏后的窄屏布局、共享保存、刷新后草稿保留、有共享草稿时从已保存值批量跟随且保留草稿、恢复独立值、复制一次、编辑器来源提示和书稿导入。领域测试验证只读预览、批量原子性和过期版本拒绝。客户端测试覆盖导航与按书草稿保留、可读预览和暂停与待更新状态区分。全仓文档既有失败与这些定向检查分别记录。
