# Agent Note：故事原生累计用量

Status: implemented

[English](2026-09-11-story-usage-totals.md) | 中文

## Problem

单条回复提供原生用量，但故事输入框缺少原生对话已有的历史累计统计。一个故事使用独立的导演和角色执行会话，只连接导演会话会低估总消耗。

## Decision

输入框底部复用原生 StatsSummary。通过实例授权的查询，对导演和角色日志执行原生 sessionStats 与 tokenUsage 计算并汇总。持久化日志无需启动 Agent 即可读取。导入的完整原生日志参与统计，同一会话的重复副本只计一次。只有便携请求记录的证据无法重建完整原生统计。

统计行显示技术轮数与步数、模型与工具耗时、有效样本平均首 token 时间、累计生成速率、按输入量加权的缓存命中率及互不重叠的输入输出总量。推理 token 已包含在输出中。计费包含实际发生的已废弃尝试及原生重试统计，不随当前可见剧情分支或历史页改变。原生计算区分未记录的计时样本和已记录的零。

浏览器在故事版本与执行状态改变时刷新。切换故事立即隐藏前一故事的数字。读取不会推进剧情、切换视角或打开请求检查器。读取失败提供明确的重试入口。过长统计行使用原生截断与悬停提示，避免挤占输入框。

## Alternatives considered

- 累加回复脚注会在多次请求之间重复累加同一轮用量，并遗漏未分页加载的历史。
- 对角色速率求简单平均会给短生成和长生成相同权重，导致总速率失真。
- 单独制作统计组件会重复原生格式与计费语义。

## Consequences

原生包提供完整日志的纯读取函数，原生对话组件将现有统计渲染从会话钩子中分离。执行适配器负责解释技术日志，前端只接收总量。测试覆盖跨会话加权、重复用量替换、重复导出日志、计时缺失、故事切换，以及刷新后的原生浏览器统计条。
