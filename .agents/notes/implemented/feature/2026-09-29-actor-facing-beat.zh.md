# Agent Note：角色可见的本拍指导

Status: implemented

[English](2026-09-29-actor-facing-beat.md) | 中文

## Problem

玩家的临时要求送到了导演，却没有直接送到其调度的演员。导演有时将场景边界改写成一名角色的指导，后续回应则可能遗漏。把完整导演要求发给所有演员又可能泄露作者秘密或私有剧情规划。

## Decision

「继续故事」输入区提供单独、可选的 `actorFacingBeat` 草稿，带可见标签和隐私提示。只有这段明确标为角色可见的文字会在本次运行中进入导演及演员请求；原有 `instruction` 仍只给导演。模型请求将其标为作者侧表演方向，而非角色亲历的事实或必须作出的选择。空字段不改变请求。导演初始调度、世界反馈续步和 reactive 接话选择都将同一节拍传给本次调度的演员；之后独立发起的回合不继承。

根 `director.open` 和每次 `execution.open` 的命令输入记录节拍及其来源。冻结演员请求从自身已记录的执行输入重建文字，重试时保留精确的模型可见来源。文字不写入场景风格、感知、角色知识或记忆。输入区按实例保留独立草稿，成功后只清除当时提交的值。

## Verification and limits

核心测试覆盖直接调度与 reactive 续步、世界反馈续步、私有指令隔离、独立演员回合和来源。API 与客户端测试覆盖转发、带标签的可选输入和草稿保留。定向类型检查、测试与 Host 构建通过。一次全新 DeepSeek V4 Flash 厨房回放在三个导演请求和三个演员请求中都查到完整的角色可见节拍及相同来源。人物没有进入委托或出行安排，但仍从湿信转到地图问答。这证明传递与该次行为，不证明文风稳定改善；需要限定当前一拍时，玩家仍须在单独字段写明具体边界。
