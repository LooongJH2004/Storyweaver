# Agent Note: Repeatable Storyweaver evolution rounds

Status: implemented

English | [中文](2026-09-29-repeatable-storyweaver-evolution.zh.md)

## Problem

Roleplay quality changes are stochastic and span actor voice, narration, direction, memory, and context assembly. A compelling excerpt or one successful replay cannot show which change helped, whether private information leaked, or whether a different build or configuration caused the result. Earlier exploratory runs also used stage names that could overwrite evidence.

## Decision

The repository skill [storyweaver-evolution](../../../skills/storyweaver-evolution/SKILL.md) defines a reusable round with one registered causal factor. At least two Sol agents explore the same frozen evidence independently; a separate Sol reviews proposals and implements one candidate; a simulation Sol gives Luna at low reasoning only each character's model-visible context and asks it to play the role. Luna's output diagnoses context clarity and voice, while repeated real API baseline/candidate replays supply comparative evidence. An independent acceptance Sol recommends a verdict and the root agent checks the raw evidence and decides.

Each round freezes fixtures, model and resolved settings, source/build fingerprints, replay stages, budget, decision rule, and holdout before candidate output is viewed. The token stop can be absent (`maxTokens: null`); native usage is still recorded, while positive time and cost limits remain. The local `run_pack.py` helper initializes a unique run package and validates fingerprints and replay artifacts; it does not call the model or store credentials. A single package maps A/B to distinct frozen actor guidance; source or other instruction changes use reciprocal packages with a checked one-factor difference. The long-form e2e harness reserves its stage directory exclusively and reports effective provider, fixture, guidance, and native usage for postflight comparison. A Director-only replay can import the same accepted Actor history into each checkout, apply that build's default policy through instance settings, and compare fresh Director requests with separate native usage deltas. Blind reviewers cite scene and event IDs against an eight-dimension rubric. The decision records quality (`accept`, `reject`, or `inconclusive`) separately from evidence status (`valid`, `invalid`, or `incomplete`), with private-knowledge leaks, player-control violations, settled-fact rewrites, and configuration mismatches treated as hard failures. Smoke simulations verify the workflow, not quality improvement.

Offline Luna submissions pass the recorded tool schema through the original built `validateJsonSchemaValue` and `ToolArgsError`, then enter `CognitionApplication.submitTurn` on a deep copy of the request revision restored through commit replay. The [native validator](../../../skills/storyweaver-evolution/scripts/native_npc_validation.mjs) captures loaded module, source, schema, packet, report and archive fingerprints. Its writer executes the complete admission handler and stops with a sentinel before publication; an accepted plan establishes validity, never an action outcome. Both arms share the original actor state and validator; style patches are frozen separately. Feedback preserves native error messages and violations, while its diagnostic transcript transport explicitly excludes the private ToolRegistry envelope. Focused tests retain all four original R31 posture failures and check malformed arguments, unavailable person and evidence references, nonexistent state updates, and repeated isolated plan validation.

Expression diagnostics can register one source-grounded cue connecting the actor's current activity to a choice about the immediate exchange. Reviewers score the choice and communication purpose rather than prop words or gestures. Anonymous final literary scores are frozen before the same reviewer inspects initial rejection and repair chains. A field comparison then records retained, changed and removed dialogue, legal behaviors and private intentions; illegal physical `posture` descriptions are not treated as admitted actions. Progress reports lead with concrete repaired or observed behavior, supported by counts and the registered verdict.

Archived multi-actor diagnostics extract each actor's complete original session and its uniquely receipted commit command with the [archive packet helper](../../../skills/storyweaver-evolution/scripts/extract_archive_actor_packet.py). Original sequence numbers, archive/session hashes and evidence IDs remain recorded; actor-private inputs stay isolated. An unknown historical producer is labeled unknown, while compatibility parsing, revision replay and admission identify the frozen runtime actually used. Native replay verifies the command epoch against the restored execution; invalid archives require fresh capture. One shared author performance rule can be appended to the recorded input without changing facts, state, memories, tools or source provenance. Natural source participation allows subtle differences and reasonable similarity, including help and agreement; no relevant memory opportunity is recorded as untested. Current rubric interpretation applies to new registrations while frozen historical scores remain intact.

## Alternatives considered

The [bootstrap capture helper](../../../skills/storyweaver-evolution/scripts/bootstrap_capture.py) retains one complete local read as exclusive stdout/stderr evidence and promotes a structured staging record of the same actual inner tool return into an exclusive final file. Plain non-TTY stdin closes immediately in the current tool, and `apply_patch` Add File overwrites existing targets, so neither provides exclusive final persistence. Focused checks cover large UTF-8 returns, embedded CR/LF and control characters, malformed staging and duplicate-target refusal; a full original Actor packet is also compared recursively after capture. The model receives the original `r.output` once. Outer platform logs remain unknown, and local preservation never establishes complete model reception or literary improvement.

- **One agent proposes, implements, and judges a change:** faster, but it exposes the evaluator to its own hypothesis and makes favorable stochastic samples too persuasive.
- **Use Luna's self-assessment as the result:** cheaper than live replay, but it tests a different model and lets the performer grade its own dialogue.
- **Keep a fixed transcript as the benchmark:** repeatable, but it cannot exercise the current runtime, Director decisions, actor-visible context, or model usage.

## Consequences

The [durable host runner](../../../skills/storyweaver-evolution/scripts/durable_transport.mjs) and [verified argv launcher](../../../skills/storyweaver-evolution/scripts/durable_transport.py) move both handler and sequence authority to disk without changing the original field view or role instructions. Each fresh process reads a frozen derived plan and continuous exclusive checkpoints; fixed invocation ACK still requires an extra call after the last frame. Permanent bootstrap claims, partial/orphan/tamper rejection and outer-error quarantine prevent recovery of failed sessions. The one source-byte capture is local fs evidence in original-capture.bin, separately named from actual host stdout and exec returns; synthetic guard input proves only data validity. This removes cache dependence while retaining unauthenticated reception and manual-copy uncertainty. R47 stays closed incomplete; fresh R48 uses six new original inputs and conditional native recall on component/preparation checks, without pooling old turns or requiring old PASS.

The separate [native recall adapter](../../../skills/storyweaver-evolution/scripts/native_narrative_recall.mjs) restores an originally available read-only tool as a diagnostic continuation factor. It replays the original authenticated request revision, closes the memory loading store, and gives native PerspectiveQueries only clone reads at that instance/revision. Original schema/parser, owner visibility, ordering, pagination, continuation and JSON rendering remain authoritative; the unchanged NPC adapter retains admission ownership. Explicit fixture query budgets are compatibility settings with source fingerprints, while archived effective producer settings remain unproven. Exact arguments, native results/errors, rendered bodies, raw streams and actual exec returns precede a same-session tool-result-equivalent continuation. No production ToolRegistry envelope, live cancellation lease, world commit or publication is claimed. This gives up arbitrary file reads and reconstructed summaries as substitutes for native recall. Focused verification covers private/missing/future records, scope, native argument errors, exact rendering, snapshot immutability, continuation and provenance drift. R43 stays closed incomplete after its autonomous unserved recall; R44 stays unrun. R45 is closed INVALID dispatch / INCOMPLETE evidence, and the strict R46 PASS prerequisite remains unmet. A separately registered R47 baseline preserves those failures and admits six fresh complete original turns using prospective component/preparation checks. Recall is conditional on autonomous requests, with every actual request requiring exact native same-session continuation; no request leaves callback coverage untested separately from expression adequacy. Accepted final arguments are scored before initial/repair drift disclosure, and initial hard failures remain reported. The [dispatch intent helper](../../../skills/storyweaver-evolution/scripts/dispatch_payload.mjs) checks complete intended payload fields and exact UTF-8 message SHA, then persists intent exclusively. Host thin-entry path components use forward slashes at construction; actual sent arguments are audited when available, while final manual-copy authentication remains unknown.

The typed-field transport mode preserves ordered containers, unknown/empty/scalar values and original strings while sending each tool object once. It restores the complete original Actor envelope from both units and frames, with separate raw/view fingerprints and explicit unit offsets. This changes reading representation rather than content; exactAssembly refers to the derived payload concatenation. The independent R43 proposals also suggest a knowledge-state clarification, but that separate cue is not combined with the reading-view factor. R41 remains closed incomplete, and native admission/source capture stay unchanged.

The functions.exec FREEFORM entry receives raw JavaScript rather than a JSON object, quoted string or Markdown fence. R41 clarifies that same submission rule for bootstrap and cached next while preserving pre-compilation actual-return persistence. Both independent proposals identified the audit gap from moving persistence into the trusted program; that larger change is not selected. R39 remains closed incomplete with unknown failure cause, and exact visible errors are retained rather than inferred. New transport smokes have zero bootstrap retries and no literary cue.

R38 delivered one complete framed chain with initial native validity, while its second Actor reported input_incomplete without a capture directory; the round remains incomplete and the second cause unknown. A thin entry now loads a hash-checked frozen control record and caches the same trusted handler behind a short loader. Only registered transport code executes, with explicit globals; Actor data never enters program source. Control loading is additional code access, not a second context read. This preserves the one-frame/final-ACK/native chain while reducing repeated handler generation, and requires two fresh transport smokes before any later continuity diagnostic.

R37 stopped after its first Actor reported input_incomplete; complete local/inner evidence did not identify the unavailable outer failure layer. The [framed transport helper](../../../skills/storyweaver-evolution/scripts/bootstrap_frames.mjs) retains the exact guarded output and delivers one bounded Unicode-safe envelope per independent execution. Fixed next invocation acknowledges the pending frame; an extra invocation acknowledges the last frame before done. Exclusive sender records precede state advance, and failed persistence cannot finish delivery. The buffer limits individual serialized envelopes, not total context. These sender/Actor-call observations support a transport chain diagnostic, never authenticated outer reception or literary/growth improvement.

Explicit request/header coordinates now select one complete recorded input from a full multi-request Actor session. Both helpers share uniqueness, ordering and ownership checks; missing coordinates for ambiguous sessions and conflicting wrapper selections fail. Receipt-linked future original commands stay in coordinator/native audit evidence. R36's two fresh guarded transport samples passed collection validation; R37 registers six independent existing-memory continuity observations, without a prompt candidate or simulated early-to-late delivery. Pending attempts and conditional promises remain distinct from delivered outcomes, and this diagnostic cannot establish stable growth or isolate memory from concurrently visible speech.

The reusable [bootstrap guard](../../../skills/storyweaver-evolution/scripts/bootstrap_guard.mjs) checks original process completion, absence of a running session, complete JSON parsing and required Actor input types after return preservation and before body emission; failure stops enactment without treating body words or hashes as reception evidence.

Comparative rounds require more calls and reviewer time. The registered budget and stopping rule bound that expense. Invalid and inconclusive rounds are preserved rather than silently retried until a favorable result appears. The helper verifies what it can observe locally; reviewers must still inspect model-visible requests and judge literary quality. Accepted results advance the baseline one tested factor at a time.
