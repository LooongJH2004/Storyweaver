# Storyweaver iterative evaluation

Use this workflow for one proposed behavior change per round. Read [the experiment protocol](references/protocol.md) before dispatching agents or running live probes. The protocol defines role separation, evidence, decisions, and stopping rules. Score with the portable [eight-dimension rubric](references/rubric.md); the historical `.artifacts/longform-performance/voice-rubric.zh.md` may add examples when present but is not required.

Apply the protocol's model assignments to every newly dispatched subagent, including coordinators and reviewers. For character expression experiments, also read [the expression design protocol](references/character-expression.md).

1. Establish a frozen baseline: scenario fixtures, story archive or storybook hash, public and character-private knowledge, player beat, transition condition, forbidden facts, model/provider/reasoning, all effective e2e flags and string overrides, build and relevant source fingerprints. Pre-register budget, sample plan, decision rule, and holdout before seeing candidate output. Use `scripts/run_pack.py init` to create a fresh run directory for each scenario; `validate` must pass before each comparison and before acceptance. Register a distinct `DSH_ROLEPLAY_LONGFORM_STAGE` per case, variant, and replicate. Execute stages serially. The e2e must atomically claim a stage exclusively before writing; the pre-run existence check alone cannot prevent concurrent overwrite.
2. Ask at least two Sol agents to investigate the same baseline independently without edits. A separate Sol reviews their competing hypotheses and implements exactly one testable factor. Another Sol dispatches Luna at low reasoning to **play** assigned characters from the actual actor-visible request context, with private context isolated by character. Luna's enactment is a diagnostic of context clarity and role separation; do not count Luna's self-rating as deployment-model quality.
3. Run baseline and candidate from the same frozen starting state through the existing `packages/story/roleplay-services/tests/longform-performance.e2e.ts` real API path. Interleave independent A/B replays according to the pre-registered plan. Run `postflight` to check each stage's provider, fixture/guidance hashes, effective settings, recorded requests, archive, failures, and usage; it does not score literary quality. Blind reviewers to candidate labels and give them actual multi-character scenes, director choices, world state, request sources, and usage. An independent acceptance Sol makes a recommendation; the root agent checks raw evidence and decides.
4. Record `accept`, `reject`, or `inconclusive` for quality, and separately record `valid`, `invalid`, or `incomplete` for evidence. A smoke run checks the chain only; it cannot establish improvement. One attractive stochastic output is never an improvement claim. Stop at the registered time/token/cost or failure budget; preserve negative and uncertain results.

`run_pack.py` freezes and checks inputs only. It does not call an API or manage credentials. Its config may state `credentialRefPresent: true/false` but must contain no credential name, path, or value. Real replay uses the existing e2e and its credential store environment variable, supplied outside the run pack. Do not overwrite an existing stage or change unrelated product files to make a result pass.
