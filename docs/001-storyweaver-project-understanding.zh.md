# Storyweaver 角色扮演项目理解与继续开发基线

> 状态：持续维护。本文用于在长上下文被压缩后继续开发，不把尚未验证的猜测写成已完成功能。
>
> 参考实现：`D:\projects\AIAgentRolePlay`。参考项目只用于找回产品语义，不直接继承其旧数据格式或实现约束。

## 1. 产品到底是什么

Storyweaver 不是一个让玩家逐项调用底层 API 的管理后台，而是一个持续自动运行的多角色故事世界：

- 故事书保存可复用的世界基础设定、导演设定、角色列表及每个角色的独立设定。
- 从故事书创建的是一次独立故事运行。运行中的修改只影响本次故事，除非用户明确修改故事书基础设定。
- 导演负责剧情编排、世界推进、角色调度和群组讨论；角色在各自可见、可知的上下文中自主行动。
- 玩家主要观察世界正在发生什么，并在需要时干预，而不是先填写一组技术表单世界才开始运行。
- “功能完成”必须形成完整链路：产品入口 → 领域数据 → API → 持久化与重新加载 → 实际模型上下文或运行时消费者。

## 2. MVP 中必须保留的产品语义

`AIAgentRolePlay` 的价值是说明原产品如何工作，而不是提供需要兼容的旧格式。

### 2.1 提示词与上下文

- 世界设置中的 `director_prompt` 是导演的可编辑自定义设定。
- 角色设置中的 `identity_prompt` 是该角色独有的可编辑设定。
- 导演设定进入导演上下文；角色设定只进入对应角色的私有上下文。
- 导演设定、角色设定和模型思考过程语言必须各自成为可独立编辑、启停、排序并指定消息身份的模块；运行规则与能力调用规则同样独立。
- 推理语言是独立上下文模块；运行时把用户填写的语言渲染成明确的强制指令，要求私有分析、规划、工具选择和一致性检查始终使用该语言。它不改变可见输出语言，也不要求泄露隐藏思维链。
- 必须区分两层规则：宿主程序真实执行的权限、工具授权、来源校验和私有数据隔离不可由提示词改变；界面中的“运行权限与安全规则”“可用能力与调用规则”是可编辑的模型指导模块。
- 上下文编辑器允许查看和编辑每个玩家拥有的来源，所有可见模块均可启停、拖动排序并选择真实 `system`、`user` 或 `assistant` 消息身份；同时提供恢复默认值、全文预览和字符/token 统计。
- 全局非空故事书默认值只包括模型思考语言，以及导演/角色各自的 `policy`、`tools` 四项上下文规则。新建故事书直接物化这些值；导入 schemaVersion 4 故事书或完整故事包时，缺失、`null`、空字符串或纯空白的对应项也会物化为同一默认值。导演设定和各角色设定是故事专属内容，空值表示没有额外自定义层。
- MVP 先按受众过滤可见数据，再渲染模块；角色不能看到其他角色的私有设定、内心活动和不可感知信息。

### 2.2 群组讨论

- 导演可根据剧情提出讨论，自动选择参与角色并推进发言顺序。
- 玩家可以允许或拒绝讨论、申请发言、指定下一位发言者、跳过、中断，或让导演收束。
- 手工创建讨论是高级干预，不应成为默认启动方式。

### 2.3 故事运行

- 故事书可产生多个彼此独立的故事运行。
- 新故事继承故事书基础设定；运行中的覆盖值不反向污染故事书或其他故事。
- 回退和改写发生在同一故事运行内；新故事的大纲应从空状态开始。
- 《月影账簿》是默认测试故事书，必须以当前格式真实存在于可用数据中，并能在界面中打开，而不是只放一个未被导入的 fixture 文件。

## 3. 当前 Storyweaver 架构理解

### 3.1 领域数据

- 故事记录位于 `packages/story/story`，当前故事领域版本为 8。
- 当前故事书为严格 `schemaVersion: 4`，显式包含基础世界信息、`reasoningLanguage`、`directorPrompt`、四组 `contextRules`，以及角色列表、每个角色的 `rolePrompt` 和无真伪标签的 `privateContext.perspective`。
- 每次故事运行包含世界状态、记忆、剧情账本、导演大纲、讨论状态、带消息身份的上下文配方，以及本次故事的设定、推理语言、policy/tools 覆盖值。
- 当前实现已经有故事级提示词覆盖结构，目标语义是“默认继承故事书，故事可单独覆盖并可恢复默认值”。

### 3.2 API 与运行时

- `story-controller` 提供故事、故事书、提示词、讨论、世界运行和上下文预览等远程接口。
- `context-preview.ts` 构造下一轮导演或指定角色会收到的真实独立消息，返回每段实际全文、消息身份、来源、权限、可见范围、字符数和估算 token。会话历史、宿主基础系统提示词与实际工具 schema 不属于这个可编排配方。
- 每次请求前都会重新读取当前 Story 与故事书，并按保存的配方生成独立 `Message[]`。开头连续的 `system` 模块通过 `agent/request-prefix-context` 写入 `request/header.prefixContextMessages`，放在持久会话历史之前；从首个 `user` / `assistant` 模块开始的其余内容通过 `agent/request-context` 写入 `request/header.contextMessages`，放在历史之后。这样既保留真实消息身份与自定义顺序，也不会污染对话历史。
- 默认配方把稳定的规则、角色身份与故事书放在可复用前缀，把世界、记忆、账本、讨论和本轮 Brief 分隔为易变块；导演与 Actor 的“思维链限制”保持最后一个 `user` 模块，以强化当前回合约束而不破坏前方稳定前缀。
- DeepSeek 适配器按原始身份发送；只有单一 system 通道的 pi-ai 路由会把多个 `system` 模块按顺序合入原生 systemPrompt，而不是降级成 user 消息。
- 导演与角色的上下文配方本身全部可配置。真实安全边界由 Host 工具注册、Session 所有权、Actor 私有构造和事件结算代码负责，不依赖一段不可编辑提示词。
- 长期记忆提供独立的准确修订更新链路；每条记录分为导演摘要、全员公共摘要和逐角色主观记忆。修改标题、三层内容、类型和事件引用时会保留审核状态，并立即成为当前 Story 数据的一部分；Actor 内容为空时不会回退读取导演摘要。

### 3.3 前端职责

- 故事书工作室负责编辑可复用的基础设定。
- 当前故事中的“上下文构建”工作区统一承载提示词、长期记忆、实际上下文检查和上下文配方。模块列表同时负责装配顺序、启停与消息身份；点击模块会打开独立编辑器，承载对应来源编辑和已保存实际内容；下方集中展示完整有序请求上下文。
- 故事运行台负责解释系统正在做什么、当前讨论状态以及玩家可做的干预。
- 上下文构建可选择导演或具体角色；导演/角色设定、policy、tools、思考语言、长期记忆和故事书上下文源可就地编辑。运行时派生的世界、账本、Brief 和讨论可预览但不能直接伪装成来源编辑器；内容定义与消息编排在同一连续工作区中完成。

## 4. 已确认的问题

### 4.1 `R0` 是内部实现泄漏

`R0` 表示导演大纲修订号为零，但用户无法从该缩写理解当前状态。产品界面应显示“尚未生成大纲”“等待导演创建”等状态；存在大纲后显示“已更新 N 次”或“大纲版本 N”。内部并发修订号可以保留在 API 和数据层，但不能直接作为主界面文案。

### 4.2 已修复的旧问题：上下文页把提示词编排伪装成不可用表单

系统固定段使用禁用复选框和禁用输入框，既看不到内容，也不知道为何固定；可配置段也只能改预算和顺序。这不符合 MVP 的“可理解、可预览、可编辑”语义。改造原则：

- 默认展示实际模型上下文，而不是内部配方表单。
- 使用中文名称、来源、可见范围和固定原因解释每一段。
- policy/tools 不再冒充“系统锁定”而隐藏内容；它们拥有独立编辑器、默认值/覆盖值和恢复默认值链路。
- 每段可展开查看实际文本，并显示完整字符数与估算 token；不按字符数截断。
- 导演/角色切换时，角色模式必须选择具体角色。
- 配方调整收进“高级配置”；保存后立即刷新实际预览。

### 4.3 数据存在不等于导入成功

fixture、磁盘目录和应用当前索引是不同层次。只有故事书被当前存储索引读取、在界面中可见并能创建/打开故事运行，才算导入成功。此前《月影账簿》已通过故事书工作室导入当前故事，但仍需把仓库内默认数据改成明确的当前格式，避免依靠导入时默认补字段。

### 4.4 不保留旧格式兼容层

本次要求是把现有有效数据重写为唯一的新格式，然后移除旧格式数据和兼容分支，不是遇到缺字段时在读取路径上不断打补丁。删除或迁移前必须先区分：

- 当前索引正在使用的故事记录；
- 已废弃但仍留在磁盘的旧记录或孤儿目录；
- 仅用于 MVP 对照的旧样例；
- 仓库中仍接受旧字段名或旧 schema 的兼容代码。

任何清理都不得删除当前活动的《月影账簿》故事。

## 5. 本轮明确实施项

1. 完整核对当前存储记录和 schema，确认旧格式边界。
2. 将仍有价值的数据一次性重写为当前格式，清除旧记录、旧字段和读取兼容，不新增 fallback。
3. 将所有用户可见的 `R0`/`R{n}` 改为明确的产品状态。
4. 将提示词、长期记忆、真实上下文预览和配方编排整合为统一的“上下文构建”工作区。
5. 所有可见上下文模块都支持拖动、启停和消息身份选择；宿主真实安全边界留在程序执行层，不伪装成提示词卡片。
6. 持续更新本文，记录最终修改文件、数据清理范围和仍未实现的功能。

## 6. 已核实的实现边界

- 活动数据只保留一份严格新格式《月影账簿》模板；两份旧运行已经移出加载路径并保留可恢复备份。
- 旧故事书、Story 与 Story Package 版本不会在读取时自动补字段；旧格式被严格拒绝。
- 导演和 Actor 的下一次模型请求会即时读取最新故事书基础值与当前 Story 覆盖值。
- Director 看不到角色的 `rolePrompt`、`privateContext`、`actingGuidance` 或私有 `state`；每个 Actor 只收到自己的这些字段。`privateContext.perspective` 只记录无真伪标签的主观经历；未知事实必须完全省略并只留在 Director 可见的世界真相中。
- 群组讨论具备 Director 主动发起、Host 持久发言权和自动继续调度；玩家表单只是高级干预。

### 7.5 心路历程已成为稀疏、可审核的角色私有事件

- Actor 只有在信念、目标、关系、内心冲突、自我认同或核心记忆意义发生会持续影响后续选择的变化时，才随单次 `npc_commit_turn` 提交心路转折；普通情绪、重复确认与常规回复必须提交空数组。
- 每条转折保存触发经历、角色主观解释、重要度、明确的前后变化及支撑它的私有状态事件引用，并使用独立修订号持久化到该 Actor Session。
- 角色状态面板新增“心路历程”时间线。玩家可编辑完整内容，将其标记为尚未定型、已内化、已逆转或已否定；否定记录保留审计，但下一轮模型上下文不再读取。
- Actor 上下文最多选择六条未否定转折，按重要度、状态及与当前目标、关系、记忆和近期行为的相关度排序。它们只进入所属角色的私有上下文，不进入 Director 或其他 Actor。

## 8. 当前仍需诚实区分的边界

- “有效上下文预览”准确展示 Storyweaver 在下一次请求中追加的独立消息，但不是整个请求的逐字节网络日志；会话历史、基础 Agent systemPrompt、实际工具 schema 和适配器协议字段不在拖动列表中。
- policy/tools 是模型指导文本，可以被玩家编辑；Host 权限、工具注册、Actor 所有权、私有数据过滤和事件结算是不可由这些文本修改的执行边界。
- 模型思考语言采用最强制的提示词表达，但任何提示词都不能对第三方模型的隐藏实现提供数学保证；产品只承诺发送明确指令，不宣称能够读取隐藏思维链。
- 本轮没有用浏览器验收视觉结果，遵守“不测试、不自测、不验收”的要求。

## 9. 术语约定

- **故事书基础设定**：新故事的可复用默认值。
- **本次故事覆盖值**：只影响当前故事运行的修改。
- **宿主执行边界**：由程序执行的权限、工具授权、来源校验、角色隔离和事件结算；不是一段可编辑提示词。
- **上下文规则**：玩家可编辑的 policy/tools 模型指导，可存于故事书或当前 Story 覆盖层。
- **上下文配方**：决定每段模型上下文顺序、启用状态和真实消息身份的高级配置；不包含字符上限。
- **角色扮演实际消息**：按当前故事状态和受众权限构造的请求级消息；字符数与 token 仅为统计，不包含会话历史与宿主另行附加的系统/工具上下文。
- **大纲版本/更新次数**：面向用户的修订状态；界面不再使用 `R0`。
