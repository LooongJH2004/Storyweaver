# Storyweaver Actor 自主性、推理循环与角色扮演优化草案

状态：持续实施；单次事务提交、角色线性调度、稀疏心路历程与受众隔离长期记忆已完成
日期：2026-08-31

## 1. 目的

本文记录当前 Storyweaver Actor 运行架构中重复推理、角色被动和表演生硬的原因，并给出分阶段优化方向。

当前优先解决三个相互关联但不能混为一谈的问题：

1. 一个 Actor turn 内多次工具调用导致模型反复重新整理同一份状态；
2. Actor 虽然拥有独立会话与私有状态，但行动机会仍主要由 Director 发放；
3. 角色提示词能描述人物，却不足以稳定产生有潜台词、有关系差异和有主动意图的表演。

本文定义总体方向；其中阶段 A 的思考语言边界、Actor 单次事务提交和 Director 线性调度已于 2026-08-31 实施，其余自主决策、状态检索和主动唤醒仍是后续设计。

## 2. 当前架构事实

### 2.1 Actor 上下文已经具备的隔离

当前 Actor 使用独立 Agent Session 和独立上下文配方。它只接收：

- 固定运行规则与能力调用规则；
- 可配置的私有思考语言；
- 公开身份、角色私有设定与表演指导；
- 自己有权获得的世界感知、记忆和角色状态；
- Director Brief 中只属于自己的感知与不确定项；
- 自己参与的讨论记录。

Actor 不接收 Story Bible 全文、世界真相、Director Outline、其他角色私有设定或 Director 期望的具体回应。普通 assistant 正文没有世界权限，只有被 Host 接受的 NPC 工具调用才能形成发言、行动或私有状态变化。

角色的初始认知不再拆成“已知、未知、秘密、错误记忆”等真伪分类。故事书 v4 只保存一组 `perspective` 主观经历；真正未知的事实完全不进入 Actor 上下文，错误确信则像普通经历或记忆一样自然呈现，不附带“错误”标签。Actor 规则只统一提醒感知、记忆和判断可能片面、过时或源于误解。真实运行与最终上下文预览共用同一个渲染函数，避免预览正确而模型实际仍收到元标签。

因此，当前“提线木偶感”并不主要来自 Director 直接代写角色，而来自唤醒权、提示词决策结构和状态使用方式仍然偏被动。

### 2.2 Agent loop 支持多工具响应，但模型不保证使用

模型的一条 assistant response 可以包含多个 sibling `tool-call` block。Agent loop 会收集完整响应中的全部调用，然后按照模型给出的顺序交给工具调度器。

这意味着框架本身没有要求模型按以下低效方式工作：

```text
思考 -> npc_feel -> 收到 accepted
思考 -> npc_believe -> 收到 accepted
思考 -> npc_speak -> 收到 accepted
思考 -> npc_yield -> 收到 accepted
```

理论上模型可以在一次响应里完成一次总体决策并提交一个有序调用组。但实际运行截图显示，即使固定策略和故事书规则明确要求 sibling 调用，模型仍可能坚持“一次 reasoning + 一个工具”的保守循环。因此模型协议能力不等于产品行为保证，不能只靠提示词解决。

当前实现改为一次模型工具调用：

```text
一次私有决策
  -> npc_commit_turn({
       emotions: [...],
       beliefs: [...],
       behavior: [speech/action ...],
       intentions: [...],
       posture: ...
     })
```

### 2.3 “一次提交多个调用”不等于“并发修改角色状态”

需要严格区分两个概念：

- 模型级事务调用：同一条 assistant response 中只提交一个 `npc_commit_turn`；
- Host 级并发执行：多个工具 body 同时执行。

NPC 操作会修改同一个 Actor 的事件日志、情绪、信念、关系、目标、意图和 turn 状态，因此 `npc_commit_turn` 在 Host 内部按事务参数顺序执行。贸然把这些状态写入标记为 concurrency-safe 会引入状态竞争和顺序不确定。

优化目标应当是：

> 模型一次规划、一次调用；Host 在一次工具执行中按顺序可靠落账并关闭回合。

## 3. 重复推理的根因

### 3.1 模型倾向于一次只调用一个原子工具

早期仅通过提示词要求批量 sibling 调用，即便已经明确下列规则，实际模型仍可能不遵守：

- 在响应开始时只做一次完整决策；
- 把已经确定的状态变化、发言、行动和 yield 一次提交；
- 常规 `{ "accepted": true }` 结果不值得重新规划；
- 只有工具失败或出现新外部信息时才重新评估。

模型因此容易采用最保守的单工具循环：调用一个工具，观察结果，再进入下一次模型 step。

### 3.2 每个单工具响应都会触发新的模型 step

只要上一条 assistant response 包含工具调用且没有通过工具结束 turn，Agent loop 就会把工具结果加入历史并请求下一步模型响应。下一步会再次看到大体相同的系统上下文、自我状态、Brief 和历史，于是产生类似：

- “让我整理当前状态”；
- “新的 Brief 给出了感知与不确定性”；
- “已经接受的行动是……”；
- “现在我需要……”

工具通常只返回 `{ "accepted": true }`，没有足以改变计划的新信息。反复调用模型主要增加 token、延迟和重复推理展示，并没有增加决策质量。

### 3.3 思考语言指令放大了重复

当前思考语言模块要求模型在“每次工具调用和最终响应前”静默检查私有推理语言。该规则原意是提高语言约束强度，但容易让模型把每个工具调用理解成一个新的分析边界。

思考语言模块应只负责语言约束，不应该同时定义 Actor 的 turn 协议。后续建议：

- 每条模型响应开始时检查一次推理语言；
- 整条响应内持续使用该语言，不在每个工具前重新开始；
- Actor 的批量工具协议放入 `actor-tools`，而不是共享的 `reasoning-language`；
- 不要求模型复述计划，也不要求公开隐藏思维链。

## 4. 第一阶段：优化一次规划、多工具提交

这是投入最小、最直接改善截图中重复推理的阶段。

### 4.1 已实施的 Actor 工具协议

`actor-tools` 应明确表达：

```text
在每条响应开始时，基于当前上下文为本次完整角色回合形成一次私有计划。

恰好调用一次 npc_commit_turn，把本回合真正需要的私有状态变化、发言与行动一次提交。
behavior 数组保留发言与行动的先后顺序。不要为了等待常规 accepted 结果而拆成多轮。

只记录真正发生变化的情绪、信念、关系、目标、记忆和意图；
不要在每个回合机械调用所有状态工具。

事务成功后由 Host 自动关闭回合，不再要求模型另行调用 npc_yield。
底层原子能力仅作为恢复原语保留，自治模型直接逐个调用会被 Host 拒绝。

只有工具失败、参数被拒绝或收到新的外部信息时，才重新评估计划。
```

### 4.2 事务内部的语义顺序

默认建议顺序不是强制模板，而是帮助模型维持因果关系：

1. 真正发生的私有状态变化；
2. 值得持久化的长期变化；
3. 当前世界行为，其中 `behavior` 数组保持 speech/action 顺序；
4. 未来承诺；
5. Host 写入终止标记并结束回合。

同一个回合不需要覆盖所有层。多数自然对话只需要一条 speech behavior；沉默可以提交空 behavior 和当前 posture。

### 4.3 `npc_commit_turn` 不是公开计划工具

仍不新增 `npc_plan`，也不持久化模型的完整推理。`npc_commit_turn` 只是一项事务式语义写入能力：它承载本轮最终选择的结构化状态变化、发言和行动，不承载隐藏思维链。

当前 reasoning stream 已足够用于玩家观察和问题诊断。世界权威仍应只来自现有语义工具。

## 5. 角色扮演感是否主要依赖提示词

短期内，提示词优化是收益最高的首要工作，但不是完整答案。

可以把问题分成三层：

### 5.1 提示词层：决定角色“怎样选择、怎样表达”

当前最值得优先优化：

- Actor 自主决策契约；
- 工具批量提交协议；
- 表演与对白策略；
- Director Brief 的非命令化语义；
- 角色提示词中目标、禁忌、秘密和关系差异的表达。

这些变化不需要重写 Actor 内核，就能明显减少重复、自我说明、设定复述和“为了推进剧情而回答”的倾向。

### 5.2 状态与检索层：决定角色“有没有足够稳定的自己”

仅靠提示词无法补偿缺失或失焦的状态。角色需要长期稳定但可演化的：

- 核心价值、底线和自我认同；
- 长期目标、当前意图和未完成承诺；
- 私人利益、秘密与自我欺骗；
- 对不同人物分别维护的信任、恐惧、依赖、嫉妒和戒备；
- 带主观含义的记忆，而不只是客观事件摘要；
- 情绪惯性和衰减，而不是每轮重新决定情绪。

当前 Actor kernel 已拥有记忆、情绪、信念、关系、目标和意图事件，这是良好基础。后续重点不是继续增加更多字段，而是改进哪些状态会进入当前 turn、它们的优先级和相互冲突方式。

### 5.3 调度层：决定角色“是否真的能主动”

如果 Actor 只能在 Director 点名时行动，即使台词非常生动，仍然是高质量的被动演员。

更完整的自主性还需要：

- 目标机会或威胁触发的自主唤醒；
- 底线被触犯时主动申请行动；
- 承诺、事件和条件到达时激活 `npc_intend`；
- 群组讨论中主动插话、拒绝发言、退出或要求继续；
- Actor 可以判断事件与自己无关并保持沉默；
- Director 负责世界节奏和结算，但不垄断角色行动意图的产生。

因此建议结论是：

> 第一阶段主要优化提示词和工具协议；角色扮演上限最终由状态质量、上下文检索和自主调度共同决定。

## 6. 第二阶段：Actor 自主决策契约

Actor 应明确按自己的内部优先级行动，而不是把 Brief 当作任务：

```text
核心价值与不可逾越的底线
> 长期目标、当前意图与未完成承诺
> 自己相信的事实和知识边界
> 私人利益、秘密与自我欺骗
> 对现场人物的关系立场
> 情绪和身体状态
> 当前环境压力
> Director 提供的感知与不确定项
```

Director Brief 只能提供最后两层的信息，不能覆盖角色前面的身份、价值和目标。

自主决策契约应明确允许角色：

- 拒绝、质疑或误解现场要求；
- 隐瞒、撒谎、回避或转移话题；
- 延迟行动、保持沉默或认为事件不值得回应；
- 选择与 Director 预想不同但符合自身利益的方案；
- 主动提出目标、安排未来行动或改变关系；
- 因知识不足做出合理但错误的判断。

## 7. 第三阶段：表演与对白策略

建议将“角色是谁”和“角色怎样表演”保持为可分别编辑、排序和预览的上下文来源。

### 7.1 角色自主设定

- 核心欲望；
- 最害怕失去的事物；
- 价值观、禁忌与底线；
- 当前目标和私人赌注；
- 秘密、自我欺骗和不愿承认的事实；
- 对关键人物的关系立场；
- 角色当前经历、记得或相信的主观内容，不附带客观真伪标签；

### 7.2 角色表演策略

- 措辞、节奏和句式习惯；
- 面对不同关系对象时的语气差异；
- 回避、说谎、紧张和愤怒时的行为表现；
- 常用但不能机械重复的非语言动作；
- 明确不会使用的表达；
- 少量高质量、关系明确的对白示例。

### 7.3 通用表演原则

```text
每次回应只围绕一个主要意图，不同时完成所有剧情任务。
对话首先是一种行动，其次才是信息传递。
使用措辞、停顿、动作、回避和潜台词表现心理，不直接解释全部动机。
回应现场最后一个具体刺激，不复述刚刚发生的事情。
不要主动总结剧情、人物关系或自己的完整设定。
不要为了方便玩家而一次性交代所有信息。
允许半句话、沉默、答非所问、试探、反问、打断和改变主意。
根据交谈对象改变表达方式，不维持单一角色腔调。
角色特征自然出现，不在每句话重复口头禅或标志动作。
```

角色示例的价值通常高于更多抽象形容词，但示例必须体现不同关系和压力场景，不能只提供一种固定语气，否则容易让模型模仿句面而不是人格。

## 8. Director Brief 的约束方向

参考项目中强约束的职责隔离值得保留，但 Spotlight/Cue 不应给角色预设选项或期望反应。

不推荐：

```text
你被一剑重创，你是选择跪地求饶还是拼死反击？
```

推荐：

```text
你感知到腹部剧痛，右手正在失去力量。
持剑者仍站在两步之外。
你不确定酒馆老板是否会帮助你。
```

Brief 应描述：

- 角色实际感知到的刺激；
- 对角色当下有意义的已知变化；
- 不确定、缺失和可能误判的信息。

Brief 不应包含：

- 祈使句形式的角色任务；
- “你应该如何回应”；
- 导演期待的情绪；
- 封闭式行动选项；
- 角色不知道的剧情目的。

## 9. 建议实施顺序

### 阶段 A：提示词与工具协议

1. ✅ 简化思考语言模块，只保留整条响应级别的语言约束；
2. ✅ 新增 `npc_commit_turn`，代码保证一次规划后只需一次工具调用，Host 内部顺序落账并结束回合；
3. ✅ Director 按 Brief 顺序逐个唤醒和结算 Actor，并向后一角色提供此前对其可见的已接受发言；
4. 在 `actor-policy` 加入自主决策优先级与拒绝/沉默权；
5. 优化默认角色提示模板，减少设定复述和解释性对白；
6. 将自主决策与表演指导作为独立可编辑模块呈现。

### 阶段 B：状态选择与调度

1. ✅ 心路历程围绕当前目标、关系、记忆和近期行为选择最多六条相关转折，而不是简单堆叠；
2. 激活已存储 `npc_intend` 的事件/条件触发；
3. 增加 Actor 自主申请唤醒和 Director 节奏仲裁；
4. 允许讨论中的拒绝、插话、退出和主动延续。

### 阶段 C：可观察性与评估

建议记录而不是凭主观印象判断：

- 每个 Actor attempt 的模型 step 数；
- 每条 assistant response 的 NPC 工具调用数；
- 常规 accepted 结果后是否发生重复推理；
- reasoning 文本的高重复片段；
- 每轮机械更新情绪/信念/关系的比例；
- 角色保持沉默、拒绝或提出自身目标的比例；
- 对话中设定复述、剧情总结和直接心理解释的比例；
- 同一角色面对不同关系对象时语言差异是否稳定。

### 已完成的心路历程与长期记忆实现

这次实现没有照搬 `AIAgentRolePlay` 中把近期 psyche 更新当作 epiphany 的做法，而是把两类长期信息分开：

- **角色心路转折**归 Actor 私有 Session 所有。它必须伴随实质状态变化，记录角色自己的解释，可以被玩家修订、逆转或否定，并按相关度有界进入该角色上下文。
- **故事长期记忆**归 Story 所有。它按导演连续性、公共知识和逐角色主观记忆拆分，先提案后审核，并由同一“上下文构建”工作区编辑。

角色状态面板的“心路历程”时间线负责审阅角色成长；普通行动和发言继续使用原有独立气泡，不塞进时间线卡片。Director 只在有实质进展的场景结束、转场或篇章不可逆变化时提出记忆，不按每轮生成摘要。

当前数据格式直接使用 `directorSummary`、`publicSummary`、`actorMemories`，旧 `summary` / `actorNotes` 不再接受。`actor/turning-point` 已成为当前 Session 事件词汇的一部分。

## 10. 当前结论

1. 截图中的重复思考不是 Host 强制每个工具前生成一段 reasoning；主要原因是模型一次只发出一个工具调用，工具结果又触发了下一模型 step。
2. Agent loop 支持多工具响应，但模型并不稳定遵循 sibling 调用提示，因此产品层改用单个 `npc_commit_turn`。
3. Actor 状态写入不适合真正并发执行；当前由单次事务提交、Host 顺序落账。
4. “每次工具前自检语言”的措辞应改成每条响应检查一次，并与 Actor 工具协议解耦。
5. 短期角色扮演提升主要依靠提示词和上下文协议；长期上限取决于状态检索与自主唤醒调度。
6. `npc_commit_turn` 不保存完整思维链，只保存语义结果；现有 reasoning 仅用于玩家观察。
7. 心路历程不是思维链摘要，也不是每轮状态快照；它只保存会持续改变后续选择的主观转折。
8. 长期记忆不能使用一份全局摘要冒充所有角色知识；导演、公共和逐角色内容必须显式隔离。
9. 未知事实必须靠上下文隔离，而不是写成“你不知道某事”；角色初始认知统一使用无真伪标签的主观经历。
