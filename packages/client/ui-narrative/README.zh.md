# @deepseek-ai/dsh-client-ui-narrative

[English](README.md) | 中文

<a id="summary"></a>
## 概述

此 Client 插件提供独立 Storyweaver 的侧栏、游玩页面、作者工作区、故事书发布和历史控制。它消费[角色扮演浏览器 API](../../api/roleplay-controller/README.zh.md)，不读取 Story 聚合、Session 事件或存储文件。

记忆提案展示简述，可选经历详情折叠在主题下。编辑提供简述、经历、理解、影响与未决事项的标签字段，并保留来源覆盖和目标修订。原始 JSON 编辑作为次级操作保留；取消放弃本地修改，保存失败保留草稿。经历摘要的回忆结果不提供原文置顶操作。

经历中的理解和影响是简述的可选补充。编辑器明确说明这点，主题与经历仍必填；清空任一可选字段时移除该字段，而不保存空字符串。审核卡片不显示缺失的详情字段。已填写完整的旧经历仍可编辑，移除文字不会改变来源引用。

记忆面板列出当前有效摘要，停用操作绑定查看时的故事和摘要修订。失败显示错误并允许重试，成功后刷新查看状态。停用恢复没有其他有效覆盖的来源，并保留历史详情。

同一面板可为当前所有者的新摘要选择自动生效或审核。选择框使用已保存的策略，保存失败不会显示为已启用。已有待审核提案仍可审核，自动生效的提案带有明确标记。

角色的书稿私有设置可选择继承共享常识或提供独立列表。取消继承时列表初始为空，保持为空即不授予共享常识。该选择修改草稿定义，运行实例保留固定版本的定义。

AI 创作工作区启动绑定独立书稿的原生对话，支持明确选择的可选本地目录和任务专用提示词设置。书库将编号实例放在对应故事书下，加号从已发布版本开始新实例。手工书稿表单保留高级 JSON，可移植故事书包保留嵌入资源。浏览器存储保留书稿编辑、设置、编排和未发送正文。来源模块提供规则、工具和推理语言编辑。玩家要求可在同一实例内编辑重发，历史保留被替换版本。重发保留当前已保存的上下文配方。配方编辑器在创作输入框旁显示未保存状态并提供保存应用操作，滚动时保存栏保持可见。移除操作区分故事书创作入口与单次实例。

游玩显示原生 dsh 回合用量及请求次数。长篇历史消息可原位展开，思考、正文和工具分别成块。来源编辑通过弹窗打开，当前角色流式呈现带标识的草稿，同时保留先前步骤供查看。

讨论控制和输入区域显示已用及剩余公开交流次数。故事书与实例设置共用预算和发言分配控件，修改其中一项保留另一项。可为后续讨论选择均衡机会或原有积极性规则，旧配置省略的策略保持原意。私有准备不消耗公开交流次数，跳过会消耗一次。

待处理讨论申请在输入区域提供入口，并在现有讨论面板展示申请人、议题、可展开的目的，以及接受／延后／拒绝操作。处理操作同时携带实例与申请版本，失败时保留申请并显示错误。接受会创建讨论，不代演参与者或自动填写公开回应。

流式正文采用增量 Markdown 渲染。阅读列在绘制前跟随内容增长；向上滚动暂停跟随，回到底部或点击“回到最新剧情”后恢复。同一回合刷新时保留历史用量栏和已展开思考的 DOM；切换故事、角色或历史版本则立即清除上一选择。预留滚动条空间，避免出现溢出时回复宽度改变。

故事正文与流式草稿共用 Markdown 排版，支持标题、强调、引用、列表、表格、链接和代码。连续的字面量 `\n` 或 `\r\n` 分隔符显示为段落换行，简单的 `<br>` 标签显示为行内换行；段间距和软换行保持可见。行内代码、代码块、URL 和 Windows 路径保留字面内容；单独的转义换行可能属于符号表达，因此保持原样。复制正文采用相同的分隔符规范化结果，已存剧情和原始请求检查仍保留准确源文。原始 HTML 仍不启用。

角色正式正文到达后，即使两条流乱序到达，也会阻止旧执行草稿重现。已结算用量和已完整加载的结算记录停止后台刷新；命令完成时补查未结算用量。用量栏在数字到达前预留空间。书库列表刷新与命令完成独立，避免执行结束后仍让输入栏保持忙碌。

<a id="product-views"></a>
## 产品视图

故事标题与游玩工具共用一个吸顶导航容器，阅读后续消息时仍可进入人物、状态、风格、上下文、模型与记忆功能。当前场景人物通过阅读列之外的原生弹窗展示，开关列表保留正文宽度和滚动位置。Escape 关闭列表并将焦点归还入口。窄屏工具按钮在窗口内换行。

作者工作区的吸顶导航始终提供 **返回剧情**。从人物、状态、风格或上下文编辑返回时，恢复暂停阅读的位置并保留未发送的引导。原本跟随最新回复的读者继续跟随；切换故事或视角则从对应视图的最新回复开始。

阅读列保留各次讨论开始位置的可折叠准备卡。紧凑的角色按钮每次展开一个准备记录，显示已记录的推理以及提交的立场、发言意愿和思考。读取绑定准备 attempt 与固定版本，公开发言不会替换准备记录。展开中的实时记录保留已有内容并刷新，收起后停止读取。群组数量区分执行中、等待和完成状态；私有记录仅作为作者诊断，不进入剧情消息。

在进行中的创作对话里，**编辑创作提示词**会展开当前任务设置并聚焦提示词输入框。任务开始后仍可修改提示词、启用状态和消息角色。**保存任务设置**会确认保存结果，后续模型请求读取已保存设置，无需新建会话。其他任务的默认设置保持独立。

书库使用统一的翻开书页标识、欢迎区、两个创作入口和文字书封。已有作品的导入区位于入口下方，按需展开。故事简介、发布状态和运行入口集中在书架卡片内。温暖浅色与柔和深色配色共用语义令牌；窄屏纵向排列卡片，并保留可见的键盘焦点。

人物回合只显示一次供玩家参考的姓名，并附次级外貌称呼。思考在人物姓名下方、已提交正文之前原位展开。玩家引导后的导演调度入口保持可见，包括没有旁白的初始调度；展开可查看记录的思考与工具步骤。当时上下文打开请求步骤阅读器，消息可搜索，原始 JSON 独立展示。在侧边查看器中，历史请求横向排列在正文上方，宽屏和窄屏下都会随正文滚走。侧栏删除先明确目标再确认。默认角色修复仍须显式编辑并保存；具体行为与实测限制见[配方与阅读决策](../../../.agents/notes/implemented/bug-fix/2026-09-08-recipe-roles-and-turn-reading.zh.md)。

故事书库与所选编辑器分开。分区导航覆盖世界设定、角色、导演风格与上下文配方；角色标签提供私有认知、初始状态与演员风格。单一保存栏在发布审核前保留草稿。新实例立即显示作者、模型和记忆工具。思维链模块的归属及已有实例的显式恢复见[编辑器与思维链决策](../../../.agents/notes/implemented/bug-fix/2026-09-08-storybook-editor-and-reasoning.zh.md)。

暗色使用石墨表面、轻量角色分隔、单层输入栏和米白色提交按钮。

游玩页以故事标题、开场引导、已提交的角色回合和底部输入区组织。流式回复与已提交回复共用同一阅读列，打开人物面板时也保持对齐。对话与行动标注使用 14px 半粗文字，便于辨认。相同人物在同一修订中的相邻对白与动作归为一组；模型回合提供明确面向玩家的诊断折叠入口，查看记录的请求和推理。空场景不显示人物面板；闲置时不显示暂停按钮。手工建立讨论位于“更多操作”，进行中的讨论显示对应控制。记忆审核和模型检查使用独立对话框，保留剧情位置与未发送输入。手机布局使用模式选择器和同样可关闭的人物弹窗。

故事库列出独立实例及其固定故事书版本。游玩页面显示应用返回的已接受剧情、发布时的身份称呼和执行阶段。代演通过已揭示的称呼选择人物，支持说话、私语、书面消息和行动尝试。感知区分亲身观察、听到的说法和转述。切换输入模式保留正文；接受提交后只清除实际提交的文字。

多人讨论控件支持建立有轮数上限的讨论、推进自动回应、插话并等待玩家、恢复、请求发言顺序和结束讨论。玩家插话在技术取消前使旧执行失效。作者工作区编辑本次实例设置、人物、场景出入场、复制后的表演风格、临时场景指导、动态状态、上下文配方和保留提案。

玩家侧人物称呼在感知描述后用括号显示真实姓名。此附注与人物认知、模型上下文分离。历史正文保留发布时的措辞；姓名附注读取所选剧情修订中的记录。人物、认知和记忆审核共用卡片、本地化状态标签与可展开的依据。详情保留原始记录及高级 JSON 编辑。参见[玩家身份展示决策](../../../.agents/notes/implemented/feature/2026-09-08-player-identity-presentation.zh.md)。

故事书提供可编辑草稿、规范化发布预览、不可变发布版本和按版本创建实例。素材提取默认只选择人物基础设定；经历、认知和状态需显式选择。历史控件支持查看修订、创建检查点、补偿恢复、按原版本重新开始，以及完整剧情归档的导入导出。

作者上下文检查区分当前预览与已记录的模型请求。请求列表限定为所选实例、人物和剧情修订，并区分已准备请求与已记录响应。先前选择的迟到响应不能把私密数据发布到新选择中。导入的执行日志保留为归档证据，不成为活动会话；导出时保存的请求正文可在作者界面查看，并标注为导入记录。无法序列化的请求保留日志及不可用原因。

<a id="composition-and-ownership"></a>
## 组合与所有权

原生 dsh 侧栏负责紧凑栏、列宽拖动和设置。此插件提供 `sidebar.stories`、`sidebar.brand.mark`、`sidebar.brand.name` 及有类型的 `sidebarNavigation`；创建操作打开故事书，不启动技术 Session。Markdown、剪贴板、图标和工具对话框使用 dsh 共享组件。正文精确遵循字号设置以及原有 `dsh.conversation.contentWidth` 偏好。回复两侧可拖动阅读宽度，输入栏顶部可拖动高度。“布局”提供滑块和恢复默认入口。聚焦手柄后支持方向键、Shift 大步调整、Home/End，以及 Escape 取消拖动。拖动仅预览，松开后保存；阅读宽度与输入栏高度分别记忆在浏览器中。窗口大小约束显示尺寸，不覆盖已保存的偏好。模型与记忆工具保留未发送输入。

实验性[独立组合](../../experimental/roleplay-web-profile/cordis.patch.yml)启用此插件及剧情服务，并禁用原 Story UI 和业务写入者。它选择独立的 Storyweaver Home。它已成为默认角色扮演组合；旧组合仅为不导出的回归夹具。

浏览器分页从应用读取 `queryLimits`，采用主机的 `queryPageLimit` 配置。插件拥有会话区域插槽；根作用域子插槽使共享导航独立于技术 Session 选择。API 插件拥有可观察的服务器数据。UI store 只拥有导航、输入模式和未发送正文。组件接收具名回调与视图 hook，不接收 Cordis Context 或 Remote 服务。

响应不确定时，命令尝试保留原命令 ID 和已审阅修订。应用分别报告命令是否提交、执行是否结束；只有确认拒绝或已结束的失败／取消尝试，才为下一次用户提交释放 ID。重复的进行中执行命令共用同一次操作。设置刷新保留用户修改的字段，并接收其他人对未修改字段的更新；取消覆盖恢复固定版本基础值。内置风格和浏览器个人预设均先复制再编辑。当前状态来自动态定义和值；当前状态为空时不会再次显示初值。

<a id="model-experience"></a>
## 模型体验

通过作者编辑的剧情配置间接影响模型；应用所有者组装提示词与工具定义，本包展示已记录的请求和用量。

#### KV 缓存影响

故事与书稿中的演员配方编辑器提供显式的缓存排序操作，保存后生效。它调用核心排序器，将稳定来源放在实时状态和证据之前，保留作者内容和自定义模块边界。读取不会改写已存配方。故事与故事书编辑器在缺少 performance 时显示继承的默认创作规则。作者可分别编辑、停用或恢复导演与演员的模块；保存故事配方影响后续请求，故事书修改发布后供未来新运行使用。表演风格编辑器提供此设置的入口；已保存预览使用执行时的渲染器。本 UI 不声称已测得缓存命中率或 token 节省。

## 已知限制与后续工作

「玩家控制」列出当前运行的全部有效人物并标注未入场状态，不再复用当前场景代演列表。加载中与运行确实没有角色时分别提供提示。开场前可以接管未入场人物，但入场前不能提交其回应，输入区会说明如何推进或安排登场。

角色设定提供「添加主角」，创建普通角色并将其 ID 选为叙事重点。未指定的主角在导入、普通角色创建、保存及发布中保持为空，只有「添加主角」才明确选中新角色。游玩输入区提供持久的「玩家控制」，独立于阅读视角和临时代演，刷新后恢复所选人物。讨论轮到玩家时显示回应与明确保持沉默的入口；回应或让过后，「继续自动讨论」仍在输入区旁，控制权不会隐式解除。导入故事书仍需检查后发布，已有运行保留固定版本。

<a id="known-limitations-and-deferred-work"></a>

输入区使用 Enter 提交、Shift+Enter 换行，保护输入法选词与长按键盘。「继续故事」有单独展开的可选字段，用于把本拍表演方向给被调度的角色看；它不是角色已知事实，不应填写作者秘密。草稿按故事保存，提交成功时只清除仍与提交内容相同的文字；导演输入不会自动复制进来。进行中的操作显示状态，不提前宣称完成。已接受的玩家指导出现在消息流中，并随重载与导出保留；它不是剧情证据。失败操作保留可编辑草稿。本地选择恢复上次仍存在的故事，并使用旁观视角。人物查看和记忆审核共用原生弹窗，完整编辑可在作者工作区完成。

`apps/web/tests/reading-layout.e2e.ts` 独立验证尺寸调整、尺寸记忆、取消拖动、键盘操作和窄屏几何位置，不调用模型。

`apps/web/tests/independent-narrative.e2e.ts` 中的真实 Loader 与浏览器场景在没有模型凭据的情况下验证独立产品，包括讨论、风格复制、原始请求查看、检查点、补偿恢复、存档导入、重载和窄屏布局。定向 Client 测试覆盖命令重试、状态编辑、回合记录按需读取、请求步骤分页和迟到私密响应。应用与 Harness 测试覆盖实际请求重建、讨论取消、状态所有权和剧情回放。

- 独立开局模型诊断不代表长期扮演质量已通过验收。任意设定对象使用类型化递归控件，并保留可选的原始 JSON 编辑；剧情历史使用有界分页。

<a id="dev-note"></a>
### 开发备注

“上下文同步”左侧显示本书共享内容，右侧显示目标故事。勾选紧凑模块行后统一同步，默认复制一次，后续自动跟随需要明确选择。全文、共享内容编辑和来源恢复按需展开。“更多”包含书稿导入和新书初始配置。上下文编辑器保留来源提示和一个管理链接。共享草稿跨页面保留，不阻止同步已保存的共享值；书稿导入保留其他未保存修改，返回检查，不自动保存或发布。见[同步体验决策](../../../.agents/notes/implemented/feature/2026-09-11-context-sync-workspace.zh.md)。

玩家代演提供独立的言语与行为输入框，各自选择对象。任一项可留空；同时提交时按言语、行动尝试的顺序写入同一命令。草稿按故事与角色保存，成功回执仅清空仍与提交时相同的文字。代演模式单独记住输入栏高度。玩家控制提供明确的「交还 AI 演绎」按钮；解除控制后回到旁观，点击「继续故事」推进 AI 演绎，包括已设定的主角。临时代演不改变持续控制权。参见[玩家回应输入说明](../../../.agents/notes/implemented/feature/2026-09-10-player-response-inputs.zh.md)。

参见[独立剧情架构说明](../../../.agents/notes/implemented/architecture/2026-09-07-independent-narrative-instances.zh.md)。保留旧数据；不提供隐式迁移或双写。

[游玩交互恢复说明](../../../.agents/notes/implemented/feature/2026-09-08-play-interface-recovery.zh.md)记录已恢复的阅读流程与相对旧界面仍存在的缺口。

讨论准备证据插入首次公开讨论回合之前，位于之前的玩家输入和导演准备之后；旧讨论卡保留各自的时间线位置。讨论控制通过常驻导航或输入栏的状态条打开侧边检查面板，不再挤占正文或藏在正文底部。记录上下文、记忆和模型检查采用统一侧栏布局，沿用原生 Escape、焦点约束和返回入口。打开记录上下文直接请求执行证据，不再重建无关的当前作者视图。

人物发言标题（包括流式生成）并列显示供玩家参考的姓名与角色定义中的客观外观描述；场景称呼仍单独用于视角控件。人物工作区常驻显示素材收录卡片及流程说明；选择并预览素材后创建新草稿，再到故事书中审阅和发布，不会合并进原故事书。

侧栏、书库和故事书编辑器均提供「导入已有作品」入口。侧面板区分故事书 JSON／文件包与独立运行存档，支持选择文件或粘贴 JSON，并在确认前展示内容摘要。宿主校验成功后才打开新草稿；失败保留所选内容，重试沿用同一草稿 ID。导入不覆盖已有故事书，也不自动发布。编辑器将已保存的设定和资源导出为按书名命名的 .storybook.json 文件包；未保存修改需先保存。剧情进度仍通过「历史与恢复」中的运行存档单独保存。

两个上下文编辑器均提供旁白最低字数、目标字数、自动补足开关与就地范围校验。保存的数值优先于文字篇幅建议。阅读界面在补充段落生成期间保留同一个未发布草稿，并在执行停止后保留次数耗尽的草稿与明确计数。

剧情回合底部和请求详情在原生 token 用量旁展示本轮首 token 延迟（秒）及平均生成速率（token/秒）。缺失计时显示“未记录”，零值保留。多步速率使用有计时的输出 token 总数除以对应解码总秒数，不含工具等待。

输入框底部显示导演与角色会话的原生累计统计，覆盖持久化历史与导入的完整日志。执行状态改变后刷新，复用原生对话的统计渲染。见[累计用量决策](../../../.agents/notes/implemented/feature/2026-09-11-story-usage-totals.zh.md)。

生效记忆也可直接展开经历详情，无须进入编辑。记忆及提案的来源记录提供编号的“查看原文”按钮，包含处理批次之外的补充依据。按钮复用按角色限定范围的检索，将焦点移至结果，并保留读取错误供重试，不批准或修改记忆。

已识别的完整行为原文显示当时的发言人／行动者称呼、传达方式或对象及原始内容；行动记录仍标为尝试。完整原文折叠在原始数据中。识别时核对检索条目的来源身份和修订，仅识别接收者行为的展示结构。其他记录及分段内容保留原样；界面不替换为当前身份，也不推断结果。
