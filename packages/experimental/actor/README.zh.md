# @deepseek-ai/dsh-experimental-actor

[English](README.md) | 中文

## 概述

`dsh-experimental-actor` 把一个精确的 dsh 实时 Agent 变成持续存在的虚构 Actor。Actor 通过类型化操作主动决定说话、行动、内心活动、记住、回忆、遗忘、建立目标与安排未来意图。每项操作都是只写日志的 Session 事件，当前状态由事件重放得到。独立的可信 PlayerAuthority API 可以观察私有状态、选择故事方向、介入世界，或代替任何 Actor 说话与行动，同时不会伪造事件来源。

这个包是实验性基础层。它定义身份、自主性、记忆、权限和审计语义；环境结算、自主唤醒调度与玩家 UI 属于后续独立层。

成功的 `actor/turn-closed` 可以携带稀疏的连续性来源标记。Story 集成验证其受众与归属，确立所引用行为后再幂等记录标记。Actor 回滚与 Story 运行时检查点共同恢复私有状态和这些有来源的事项。

`actor/state-changed` 记录定义驱动的私有状态。`actor/commit` 将完整同步事务保存为单条持久事件；事务内读取包含先前暂存操作，校验失败不会发布其中任何操作。玩家修订使用相同的精确字段修订号，并保留补偿历史。`playerInspectEvents` 直接从保留日志投影未运行的 Actor，不启动模型请求。

`HarnessActorExecutor` 为独立剧情实例提供执行适配：创建或恢复按实例隔离的人物会话，通过应用回调提交模型的语义变更，并记录冻结的剧情请求及回执。它保留本轮完整工具事务，在下一次模型请求中排除更早的执行消息。

独立演员提交通过 `discussion_request` 支持讨论邀请，接收者引用由剧情应用解析。导演调度通过讨论控制提供绑定修订的邀请处理。旧 Session Actor 适配器明确拒绝邀请，避免静默丢弃。邀请工具字段和导演指导通过请求快照记录。

演员工具将邀请描述为需要相互回应的单项议题，而非逐人汇报或等待外部证据。导演执行指引要求：答案仍依赖待结算结果或外部当事人的选择时，先延后邀请；场景指导也不写成会议议程。是否接受仍由导演决定，这些文字不保证文学质量。裁定指引要求描述结果时保留待处理行动记录中的原行动者。

私有整理使用独立的执行指令与漏交纠正提示，不加载普通表演或讨论席位指令；纠正提示要求静默提交上下文更新，不建议提交行为。演员工具只展示静默姿态和上下文更新，当前请求的工具结构不展示普通回合字段。应用继续校验精确来源覆盖并拒绝额外写入。演员与从领域生成的导演记忆结构均说明：新增不传摘要身份，其余操作使用已有摘要编号和该摘要的精确修订号，每条变更单列来源。剧情执行对不完整 JSON 返回具体解析错误，要求重新提交完整对象；不自动修补或提交无效输入。普通演员请求保留完整工具结构。 私有整理区分指定批次来源与旧记忆已有证据；修订自动保留旧来源，演员无需把它们再次列为本批处理对象。

独立版 `context_update` 提案可为简要摘要附加经历详情。工具结构要求记录主观经历、理解、影响和未决事项；`narrative_recall` 可通过保留引用读取已批准详情。应用负责来源校验、审核和上下文替换；附加详情不等于自动批准，也不授予其他角色记忆的读取权限。 回忆时，已知记录编号放在 query。sourceId 用于续读校验，不用于选择记录；新查询省略 sourceId 与 characterOffset，续读则使用返回字段并保持原查询。

导演转场指导要求通过共同或逐角色观察，将可察觉的新时间或地点投递给相关演员。旁白和场景指导不更新感知证据，旧约定条款不作为新观察重新投递来提示回忆。这是模型指导，宿主不推断接收者或广播文学旁白。

导演 finish 指令明确演员名单按顺序各执行一次。后执行者可回应自己可见的先前行为，先执行者不会自动再获一轮。导演应将发起者放在回应者之前，需要往返交流时使用讨论调度，并保留玩家控制与沉默。

演员指令要求从原始经历理解相对期限，并依据新感知的时间变化判断是否需要行动。私有整理保留相对于原事件的时间含义，区分计划与完成情况，在没有依据时保留不确定性，不编造日历日期。这属于模型指导，不是宿主维护的故事时钟，也不能保证每次生成的摘要都正确保留时间含义。

上下文摘要和按需读回的摘要详情通过 sourceRevisionRange 展示所属角色可见原始记录的修订范围，并与摘要版本号分开。这表示证据顺序，不是故事日历时间。整理指令区分早先事件中的未知与当前视角中仍未决的问题；不能把指定批次以外的后续证据说成该批次证明的结果。原文和已保存摘要版本保持不变。

演员指令允许在感知与旧说法冲突时作出可错的信念修订，不要求先知道隐藏解释。指令抑制只为保住旧说法而编造例外，以及等待绝对确定，同时保留人物有动机的否认与信任。这指导角色的私下选择，不要求台词讲授证据规则，也不自动修改已存信念。

独立行动工具提供公开或隐蔽可见性，旧 Session 适配器拒绝隐蔽行动。导演观察支持共同感知及逐角色补充／替换模式，待发布旁白草稿也保留这些字段。宿主将其展开成有顺序的证据，不额外调用模型。这些结构与指导变更影响模型可见前缀，不据此推断缓存或扮演质量提升。

独立导演工具提供完整操作示例与非空文本提示，参数解析同时拒绝多余根字段和无效操作字段。NPC 字段指导区分回合状态与身体姿势、已有状态更新与新字段定义，以及讨论私下准备与公开发言。证据与限制见[本地日志驱动的协议修正](../../../.agents/notes/implemented/bug-fix/2026-09-08-log-driven-tool-guidance.zh.md)；这些措辞变化会改变请求前缀，但不代表已测得模型错误率或缓存改善。

`director_observe` 接收单层结算字段，将客观证据、按受众区分的感知和可选旁白一起提交。`director_command` 承担其余规划与调度操作。两者共用执行权限校验和回执日志。旁白指导区分可观察的结果与人物接下来的反应或披露；这是模型指导，不是文学文本的语义校验器。流式草稿识别单层工具及既有记录中的嵌套旁白。 每次 director_observe 调用必须显式提交 settles 数组：结算待结果尝试时填写准确编号并同时投递行动者反馈，没有待结算项时填写 []。漏填会在观察写入前被拒绝；领域输入和已存记录仍保留原来的可选字段。仅在文字中描述结果仍会留下待结算尝试；修复指导保留已发布事件，不重放旁白。 导演讨论工具仅提供关闭和申请处理；玩家专属的席位指定、介入和恢复操作不出现在工具中，工具解析也拒绝它们。

人物记录和生命周期校验位于 `roleplay-core`；本包解释 Session 执行事件及撤回坐标。Story 集成提供 `ActorNarrativeReader`，其中只有已绑定人物可访问的来源、引用和初始认知。Actor 代码不能直接查询 Story Registry。

`HarnessDirectorExecutor` 与 `HarnessActorExecutor` 通过 `HarnessExecutionSessions` 共享会话获取、取消、请求历史隔离、回执日志和释放。导演协议调用应用命令并返回回应计划，不直接修改人物状态。会话键将同一实例的导演与任意人物分开。`HarnessRequestHistory` 捕获两类执行，并在不恢复 Agent 的情况下导出完整的不可变日志证据。

导演输入通过原生工具定义暴露领域嵌套字段。请求摘要包含原生完整回合用量汇总及尝试次数，可移植存档保留这些值。实时诊断保留当前执行的先前回应。

演员回忆与导演普通、私有整理回合的回忆复用领域 schema 的精确读取和续读说明。已知记录编号放入 query；sourceId 仅随返回的续读游标使用。该指导不改变检索、权限或分页行为。

实际请求回归验证：演员和导演的长篇公开表达偏好及场景提示出现在私有整理前后的普通请求中，不进入整理请求。专用区块快照保留私有请求的角色和顺序。该分离由叙事应用完成，Harness 记录并执行收到的请求。

<a id="use-this-package"></a>
## 使用此包

在 Agent registry 之后挂载服务，创建全新 Agent，并在第一次对话回合前绑定：

```ts
import type { Context } from '@deepseek-ai/cordis'
import ActorService, { ActorId } from '@deepseek-ai/dsh-experimental-actor'

declare const ctx: Context
declare const sessionId: Parameters<typeof ctx.agentLoop.create>[0]

await ctx.plugin(ActorService)

const actor = ctx.agentLoop.create(sessionId, { provider: 'deepseek', model: 'deepseek-chat' })
ctx.actors.bind(actor, {
  id: ActorId('archive-keeper'),
  displayName: 'The Keeper',
  persona: 'Protects the archive, distrusts fire, and remembers promises.',
  capabilities: ['speak', 'act', 'reflect', 'memory', 'goals', 'schedule'],
})
```

Actor Session 必须从空白开始：继承 fork 历史会被拒绝，对话开始后再绑定也会被拒绝。稳定的 `ActorId` 与显示名、Session id 相互独立。该 id 只要求在所属 Story 内唯一，并非进程级唯一；两个独立 Story 运行可以为同一个故事书角色保有不同的实时 Actor Session。

### Actor 自主性

服务提供显式操作，不把 assistant 普通文本当成行为：

- `speak()` 与 `act()` 提交面向世界的意图。
- `reflect()` 提交供可信观察者检查的虚构内心活动。
- `remember()`、`recall()` 与 `forget()` 让 Actor 主动控制记忆。遗忘会追加墓碑，不会删除审计记录。
- `setGoal()` 与 `abandonGoal()` 维护带修订号的自主目标。
- `recordTurningPoint()` 稀疏保存会持续影响信念、目标、关系、冲突、自我认同或记忆意义的主观转折，并带独立修订号。
- `schedule()` 用世界时间触发器记录未来意图。
- `closeCurrentTurn()` 记录 Actor 停止当前回合的原因。

只有活跃记忆会进入回忆结果和模型上下文。核心记忆达到上限时，服务会先以持久的 `core-memory-capacity` 墓碑归档重要度最低且最早写入的活跃记忆，再提交新记忆；长期运行的 Actor 不会因容量满而整轮失败，淘汰记录仍可审计。

### PlayerAuthority

可信宿主 API 有意不把玩家建模成某一个虚构角色：

- `playerChooseDirection(controlSession, direction)` 选择故事方向。
- `playerInterveneWorld(controlSession, description)` 改变或声明世界状态。
- `playerSpeakAs(actor, request)` 与 `playerActAs(actor, request)` 代替任意 Actor 说话或行动。
- `playerInspect(actor)` 读取上帝视角私有投影，包括内心活动、心路转折与已遗忘记忆的墓碑。
- `updateTurningPoint(actor, request)` 基于准确修订编辑、内化、逆转或否定一条转折。

代演说话和行动会同时产生玩家介入事件，以及带 `origin: 'player'` 的匹配表达/行动事件。故事可以把它视为经由该角色发生，同时审计与后续推理仍能区分它并非 Actor 自己的选择。

<a id="understand-the-implementation"></a>
## 理解实现

精确的实时 Agent 对象就是权限凭证。`ActorService` 将它映射到稳定人物身份及可修订的作者配置，并拒绝过期 Agent 对象。它不会把裸 `ActorId` 当作权限边界，因为不同 Story 运行可同时拥有同一创作身份；因此只有该 id 在进程内没有歧义时，`find(actorId)` 才返回成员。Story 编排始终通过 Story 自有的 Session 注册定位 Actor。每个 Actor 自有的值都写进自己的 Session；与 Actor 无关的故事和世界介入可以写进独立控制 Session。

[`src/fold.ts`](src/fold.ts) 严格解码事件词汇，并校验描述身份、唯一 id、记忆墓碑、目标与转折修订、玩家代演来源和每回合一次的关闭事件。[`./invariant`](src/invariant.ts) companion 会在追加前针对已提交前缀重放候选事件。

作者初始化在每个分支中只执行一次，以同一事务写入状态、记忆、目标和意图，不受模型修改能力开关限制。当前上下文提供生命周期记录的稳定来源引用，用于解释动态状态变化。Host 可通过 `configure` 按准确配置修订更新姓名、设定及授予能力；稳定 Actor ID 不能改变。这些作者设置独立于 NPC 提交记录，并在剧情状态撤回时保留。配置修改保留当前状态和生命周期记录。

<a id="dev-note"></a>
## 开发备注

决策记录见[自主 Actor 内核基础](../../../.agents/notes/implemented/feature/2026-08-28-autonomous-actor-kernel-foundation.zh.md)。

独立的 `HarnessActorExecutor` 还通过应用提供的查询回调开放 `narrative_recall`。回调绑定实例、演员与剧情修订，工具参数只包含查询和分页。共用执行生命周期校验当前 Agent，拒绝取消或接受完成后的调用，并在技术请求历史中保存查询结果。导演协议通过导演应用命令路由 `recall` 与待玩家审核的 `context-update`。

NPC 指导鼓励在姓名与交往有关时自然询问，而不要求逐个盘问陌生人。导演旁白仍展示给玩家，感知仍按指定对象显式投递。导演被要求保留关键可感知细节并替换过时指引；指引假设的情境已过时时，角色依据较新的感知回应。这些是提示词要求，不是自动旁白筛选或语义一致性校验，不增加模型调用。参见[带人物归属的角色感知](../../../.agents/notes/implemented/feature/2026-09-11-attributed-character-perception.zh.md)。

独立 NPC 执行将发言权、知识校验和玩家控制视为私有执行指令，不将它们变成虚构对白或所有人物共有的性格。导演指导聚焦人物眼前一项选择或机会，具体表达交给各角色；提出条件后，导演优先调度能答复的人，不让队友再轮流重复提议。保存的私人记录维持连续性，不规定重复发言。详见[角色表达与上下文默认值](../../../.agents/notes/implemented/feature/2026-09-11-context-defaults-and-character-voice.zh.md)。

<a id="model-experience"></a>
## 模型体验

### Actor 自我状态投影

#### 模型看到什么

领域包本身不安装提示词或工具。与 [`@deepseek-ai/dsh-experimental-tool-actor`](../tool-actor/README.zh.md) 配合后，模型会收到自己的 persona、活跃记忆、按相关度选择且有界的心路历程、活跃目标、已安排意图，以及有界的近期说话/行动窗口。内心活动、被玩家否定的转折和已遗忘记忆不会进入其中。每个可见状态快照都会组装进请求头，因此由 dsh 常规请求边界记录。

#### Token 影响

Actor 领域事件只存在于日志中，不会变成聊天消息。投影自我状态的 token 消耗随活跃记忆、最多六条已选转折、目标、意图和有界近期活动窗口增长。紧凑工具回执只暴露已经先完成提交的状态。

#### KV Cache 影响

行为契约和当前 Actor 配置构成前缀。投影中的记忆、目标、意图、表达或行动发生变化时，会重写动态自我状态段，并从该位置起使缓存失效；私有内心活动和已遗忘记忆墓碑不会改变它。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- 说话和行动目前只是意图；尚无环境适配器结算成功与否、目击者和后果。
- 未来意图可以存储，但尚无自主时钟/调度器唤醒 Actor。
- 活跃记忆目前在进程内重放，并使用简单的不区分大小写文本/标签检索；尚无语义记忆 Provider 或检查点压缩。
- PlayerAuthority 是可信宿主 API；尚不包含认证、多人权限和 UI 控件。
- 故事/世界介入可以记录，但尚无世界状态投影将其分发给受影响的 Actor。
- 此包私有且处于实验阶段；事件与服务约定可能变化，且不提供迁移承诺。

导演私有整理沿用普通执行的 `director_command` 参数封装：顶层仅有 `command`，操作及所属字段放在其中。私有指导提供结束调用示例；既有结构校验拒绝多余的 `arguments` 封装。参数修正不提交剧情，也不免除来源覆盖校验。

独立执行使用 `HarnessActorExecutor`、`HarnessDirectorExecutor` 和 `HarnessRequestHistory`；默认剧情 profile 不挂载上述旧 Actor 服务。回应重建区分正文、推理与工具调用，不因缺少结束事件而推断已完成。可移植证据在导入后仍按实例隔离。实时读取合并 Session 通知，每次刷新重新授权视角，并在取消时释放监听。`ExecutionModelSettings` 对接既有设置存储；每次执行读取模型选择并保持到本次执行结束，请求头记录实际路由。

历史请求详情在重建请求头时复用已读取并完成归属校验的事件日志，避免同一次详情读取再次检查持久化日志。这不缓存变化中的回复，不恢复模型执行，也不改变请求内容。

独立导演协议依据实际玩家控制权区分旁观自动演绎与保留给玩家的回合，即使作者文本将主角称为玩家角色也如此。它要求有意义地推进场景，并通常通过角色执行器调度在场、可行动的主角。旁白按配置风格展开可观察事件；精简规划不限制公开正文。这些是模型指令，不保证叙事节奏，也不强制主角每回合发言。宿主保留在场、控制权和讨论发言权校验。请求快照记录该协议与场景输入；提示词变更会替换一次稳定前缀，不改变模型路由、token 上限或已有作者设置。

director_command 的工具参数和规则演示了在 finish 前使用 scope=scene 的 style 为指定接收者提供表演指引。指引可推动角色朝用户期待的方向发展，而不在旁白中直接发布其选择。可编辑的 performance 上下文模块提供默认创作目标，包括实质性旁白的 4～6 段、约 500～900 中文字符；明确的 lengthPreference 和场景指导优先。固定执行协议保留工具与控制权规则，模块停用后不再追加另一份创作篇幅目标。这些参考目标只计算公开正文，不包括私有记录，并非硬性要求。可选的独立 director-performance 诊断记录实际正文长度和演员指引传递；无需密钥的组合快照验证同一条工具到上下文的路径。

启用的旁白字数数值增加一个有记录的上下文模块，优先于文字篇幅目标。director_revise_narration 使用回执中的准确修订号追加或替换待处理草稿。草稿回执进入同一技术历史；最多两次修订，每次增加一个模型请求及与草稿长度成比例的输入。次数耗尽的回执结束回合并报告失败，不发布其世界事件。参见[旁白字数决策](../../../.agents/notes/implemented/feature/2026-09-10-narration-length-check.zh.md)。

独立执行历史通过原生 session-stats 包的 deriveTurnPerformance，为已结束技术轮次的每条请求附加可选 turnTiming。同一份已授权日志提供 token 用量和计时，不增加模型调用。可携带存档保存这些字段；旧存档缺失时不补猜。

导演整理同样使用专用指令，director_command 仅展示读回、上下文更新和结束操作。下一次普通执行恢复场景、旁白与调度工具。精确批次校验和私有写入限制仍由应用负责。Harness 回归覆盖提交被拒后的修复和协议恢复；尚未证明真实模型的重试成本下降。

导演结算指令将尝试与结果的边界同样用于旁白：完成交接不等于执行了拟议的记账或离开。时间跳转保留最后确立的状态，不能补写角色选择或证明未记录的承诺失约；当前检查不能证明历史期间物品始终未转手。

工具参数被 JSON 解析拒绝后，演员和导演共用的执行适配器会在发现字符串未闭合、缺少结束括号、括号不匹配或多余时补充定界符提示。字符串内部的括号与转义引号不会被当作容器。这仅是错误说明：原提交仍被拒绝，模型须重新提交完整的预期更新。合法请求、工具结构及普通提示词前缀不变。本地测试与实际 Harness 组合验证了提示及修复后重试链路，真实模型重试是否减少仍待验证。
