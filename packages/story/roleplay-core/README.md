## Summary

The product injects `MemoryQueue` into the runtimes: foreground completion enqueues private consolidation, and a separate worker stages and integrates results while foreground work is idle. Direct runtime construction without this scheduler retains synchronous consolidation. The [queue decision](../../../.agents/notes/implemented/feature/2026-09-13-background-memory-queue.md) owns scheduling, restart, conflict and archive boundaries.

Exact-revision reads use the committed projection when the requested revision is current, checked within the same read transaction. Older revisions still replay immutable history. This avoids repeated full-history reconstruction in current author and memory queries without changing storage, model inputs, or token use.

This package owns framework-independent character, knowledge, state, style, and storybook rules. Application services accept explicit command authority, instance scope, revision, and retry identity. The memory adapter exercises these operations without Cordis, an Agent, or a browser. The shipped Actor adapter uses the character lifecycle projection; the independent narrative application is undergoing product integration.

`DiscussionApplication` shares pure floor rules with the existing Story adapter. `CognitionApplication` advances preparation or speech in the same transaction as cognition and behavior. `DiscussionRuntime` invokes the Actor execution port serially and reports waiting-player, awaiting-director, yielded, paused, or failed outcomes. A failed preparation cannot publish speech or advance the floor. When a concurrent preparation fails, its originating error is retained while sibling executions are cancelled and drained. Participant ordering cannot replace that error with a secondary cancellation.

Actor discussion context exposes used, total and remaining public turns from the frozen discussion revision. Speak, pass and conclude each consume one turn; private preparation does not. The limit remains maxRounds times participant count. Guidance encourages concise responses to perceived contributions, permits quiet disagreement, and distinguishes finishing a reply from concluding the group exchange; explicit author length guidance remains applicable.

Discussion settings optionally select `floorPolicy`: `balanced` prioritizes fewer public opportunities, breaking ties by eagerness and participant order; `eagerness` retains the original weighted rule. Missing values retain the original rule. Both prioritize directed handoffs and queued floor requests and permit passing. The application captures the policy when starting a discussion; later settings changes affect subsequent discussions. Player projections expose public-turn counts independently of paginated transcript rows.

Actors may submit `discussion_request` with a topic, opening purpose and local references to other present people. Tool guidance distinguishes requesting a shared exchange before deciding from addressing ordinary speech to several people, which does not request discussion turns. Ordinary questions need not become discussions. The actor transaction stores a private invitation in the discussion ledger; duplicate pending or deferred invitations merge. Directors and players accept, defer or decline an exact request revision through discussion control. Acceptance checks current attendance and starts a discussion atomically using saved settings. Other actors receive no invitation contents before acceptance; the requester, director and player review have separate projections. Archive import rejects actor-authored resolution or changes to another request.

World observations optionally carry one `shared` perception with explicit recipients. Recipient deliveries supplement it by default, or replace it only for a listed shared recipient. Shared and supplementary evidence retain separate kinds and sources; stored order puts shared evidence first in chronological context and remains available to newest-first recall. Duplicate recipients and orphan replacements reject the whole settlement. Narration drafts retain the complete shared settlement until publication.

New actor requests also carry frozen capability metadata for the execution adapter. npcTurnParameters advertises only granted cognition fields and behavior kinds; an actor with no speech or action grant receives no behavior field. A missing capability list in older recorded metadata retains the previous complete schema. This display filter does not replace domain permission checks or affect the separate retention protocol.

The actor identity section includes its authored capabilities. Tool guidance maps capability names to permitted fields; reflection denials identify the submitted thoughts, state_changes, knowledge_changes or turning_points that require permission. This does not grant new rights or change transaction validation.

An authored `displayName` labels a person for the author; it is not automatically inserted into that actor's own identity section. When the character knows their own name, put it in their `rolePrompt` or private perspective. Other characters still learn that name through admitted encounters or speech.

The model-facing action tool requires an explicit public or concealed visibility choice. Public attempt text is routed verbatim, so its guidance excludes silent thoughts and private discoveries; private inspection belongs in a concealed action. This is not a semantic privacy classifier. Existing domain inputs retain their default. An action may declare `visibility: concealed`. Its attempt becomes evidence only for its performer; neither the target nor the observer receives an automatic broadcast. The director can inspect the accepted attempt and deliver what others actually notice. Concealment guarantees neither success nor secrecy. Ordinary action and speech routing remain unchanged; archive validation rejects a concealed attempt with a broadcast audience.

Actions marked `awaitResult` remain pending until a settlement names them and delivers feedback to their performer. Director continuation uses the configured feedback budget and stops without new results or when player control is due. Retrying a failed continuation preserves its failure even if the settlement already succeeded; accepted results are not duplicated or silently reported as a completed response. Pausing invalidates late feedback before publication.

Personal context includes all active goals, scheduled intentions, active memories and non-rejected turning points. Effective retained notes replace their covered originals unless pinned; those originals remain available through owner-scoped recall. No entry-count budget selects a subset of authorized records.

Character definitions may override `commonKnowledge` with their own ordinary-knowledge list. Omission or null inherits the book's shared list; an empty list inherits none. This distinguishes background knowledge without using age as an automatic unlock. Authored private judgments and later received evidence remain separate and continue to work. Instances and archives retain each character's definition; changing one does not grant the same knowledge to others. This scope does not remove the language model's pretrained knowledge, so role instructions and quality checks remain necessary.

The actor context includes every owner-visible, unrepresented received event and active judgment. An explicit query can order judgments by lexical relevance, but does not remove entries. Frozen revision previews use only records visible at that revision. Ranking does not establish that a belief is true.

When discussion advancement reaches the summarizing phase and consolidation is enabled, each AI participant privately processes up to the configured threshold of unprocessed personal evidence, even below the ordinary trigger threshold. Evidence from this discussion’s accepted turn revisions and linked world results takes priority over older backlog, preserving chronological order within each priority group. Player-controlled characters are skipped. These executions use the existing cancellation and source-coverage checks and do not add public turns; direct director-summary entry also schedules remaining actor evidence. With the background scheduler, director context is generated without waiting for those jobs. Cancellation preserves accepted participants and rejects late submissions; a new run resumes only unprocessed evidence.

Private actor and director consolidation lists include a short `sourceRef`, such as `$source:1`, beside each canonical source ID. Models can use these local references in unit and note `sourceIds`; recall continues to use original IDs. The runtime resolves them only against that execution's assigned batch before ownership and exact-coverage validation. Unknown references and duplicate canonical sources reject the whole update. Persisted notes use canonical IDs, and ordinary turns do not inherit these aliases. The extra reference field increases request text slightly; reduced transcription errors and output cost require model measurement.

Actor and director contexts include all effective retained briefs. Effective notes replace covered originals unless pinned; originals remain available through owner-scoped recall. Director facts and accepted behavior are presented chronologically after this coverage filter. Same-commit behavior keeps its submitted order. Guidance or an empty query does not remove authorized entries.

Starting a new director memory child requires the unchanged completion revision of its root orchestration. Retrying an old completed request cannot consume evidence from later story changes; an already opened child retains its original receipt and failure semantics.

Director memory executions use host-assigned source IDs, accept one complete context-update followed by finish without dispatch, and reject world writes. The owner’s activation policy governs summaries; original records remain retrievable.

Context-note changes optionally include an `episode` with topic, experience, interpretation, impact and unresolved questions. The activation transaction preserves it together with note revision, owner and covered source IDs. Effective episode notes expose brief text, topic and `detailReference` in ordinary context; recall can search that reference for full details. Pending notes are not effective memories. Other actors and director recall cannot retrieve an actor's episode details, while the original evidence remains retrievable and archives preserve both records. Automatic consolidation is not supplied by this optional detail structure.

Ordinary retained briefs include identity, revision, epistemic kind, status, text and source revision range, with topic, unresolvedCount and a detail reference when an episode exists. The count describes questions saved in the details, not whether they remain open now; a status-only update preserves those details. Shared retained-note guidance directs owners to recall the details before revision and update the complete episode when new evidence answers a question or changes an interpretation. Owner, author and complete source-ID arrays remain in storage and scoped recall responses rather than repeating in each brief. A note ID can also find its full record through recall. This projection does not change approval, source coverage or revision validation.

Recall and consolidation mark personal judgment, state, and retained-note versions with `revisionScope: record`; those versions are not story timestamps. Event originals retain story revisions. Undated personal originals sort separately by stable identity, and a note's `sourceRevisionRange` is null if any supporting original is undated. A mixed or undated private batch emits no later-event window because its end cannot be established. This projection preserves stored records and source identities; it cannot recover an unrecorded occurrence time.

The actor policy distinguishes personal record versions from experience age, explains null source ranges, and prohibits inferring occurrence time from the display position of an undated record. This guidance supplements the projection without modifying saved author recipes; it does not establish model compliance with every temporal claim.

Actor consolidation retains status-only references to its own assigned attempts that still await world feedback at the frozen request revision. The corresponding original header also carries resultStatus=awaiting-world-feedback beside its execution-local sourceRef. The status section contains no action body or out-of-batch attempt and does not change processed membership. It distinguishes an unfinished attempt from an outcome; absence from the list is not proof of success. Consolidation itself neither settles the attempt nor changes the review policy.

Recall ranks an exact record reference first, then matching effective summaries in their latest update order, then matching originals by narrative revision and event order. Summary-local revision numbers are not compared with world revisions to determine recency. Corrections affect subsequent recall; frozen historical requests keep their original order. Paging and continuation use the same frozen ordering, and every unselected original remains available.

Player correction edits an effective summary immediately through a revision-checked review command. It preserves ownership, source coverage, note kind and status, records an approved player correction, and leaves the automatic/review policy unchanged. Archived and superseded notes cannot be corrected; historical versions retain their previous text.

Revising or changing the status of an existing note preserves episode details when the change omits them. Explicit details replace the previous details; replacing a note with a new note does not inherit omitted details. Historical revisions remain unchanged.

Player review can set an owner's `activation` policy to `automatic` or `review`; omission retains review mode. Automatic mode activates only newly submitted valid units in their originating transaction, preserving source and revision checks. Existing pending proposals stay pending, and other owners are unaffected. Model context and proposal metadata distinguish automatic activation from player approval. Changing mode does not revoke effective notes; players can disable them separately.

Consolidation guidance groups related sources into experiences, keeps a concise current understanding and places useful detail in the episode. Private requests omit public performance guidance and current scene performance cues, while retaining identity, personal cognition, evidence and reasoning settings. Private background also excludes personal-memory retellings, which can contain later plans or mistaken recollections; goals, beliefs, retained notes and authored recipe content remain available. An explicitly assigned personal-memory source still appears in its batch with its source kind. Ordinary acting and scoped recall keep those personal memories. Their source list reflects only included sections. Ordinary requests retain the saved guidance. Surrounding context may inform interpretation; it must not be substituted for the assigned events. This guidance does not mechanically establish summary accuracy. Context-summary updates distinguish unavailable targets from stale or inactive notes. Unavailable targets include other owners' notes without disclosing their existence; a new summary uses add without a target ID or revision. A stale target requires its own current note revision, not the story revision. Rejected updates do not commit partial changes. Memory field guidance assigns current understanding to the brief, supporting experience to details, and only currently open questions to unresolved. Empty unresolved lists are valid. The actor tool and director domain schema share these descriptions; prompts guide interpretation without validating narrative truth. The model-facing action tool requires an explicit await_result boolean: true requests feedback for inspections, searches and consequential object transfers or storage; false is for expressive gestures needing no settled outcome. Existing domain inputs and stored behavior remain readable; the host does not infer physical success from wording. Action-field guidance treats behavior as an attempt now; conditional proposals remain speech or future intentions. Deliberate differences between speech and action remain possible when the actor makes that choice explicit. Episode guidance preserves attribution, negation and event order instead of inferring a source's instruction from a later choice. These are model instructions, not semantic validation. Director consolidation rejects incomplete, extra or repeated source coverage before persistence and names the offending references. Completion checks the accepted batch again; a rejected update remains retryable without partial notes. Director consolidation selects sources by revision, then within-turn order, before using IDs to break ties. Director recall and consolidation preserve behavior authors, actor/player origin, scene, recipients and within-turn order. Action originals remain attempts, and speech retains its delivery mode. This projection omits private purpose and does not change actor visibility or stored records.

With a positive consolidation threshold, a successful ordinary actor run outside an unfinished discussion can open one private consolidation execution for that many oldest unprocessed received events. Already submitted sources are excluded, including rejected proposals, to avoid repeating a player decision. The request includes frozen owner-visible originals and accepts only silent posture plus context updates covering the assigned batch exactly once. It changes neither public behavior nor posture and uses the same executor, cancellation controller and logged request path. Retry reuses the child execution; failure preserves the accepted ordinary turn. Event-boundary integration is described below.

During a discussion's summarizing phase, director context asks the existing summary execution to retain public events, commitments, conditions and unresolved consequences through context-update before closing. Missing earlier contributions remain available through director recall. The guidance distinguishes claims from facts and attempts from outcomes, excludes private actor cognition and permits closing without invented change. Note generation is model-directed rather than a mandatory note-count rule; activation follows the director's saved policy. Dedicated director consolidation and discussion-boundary actor consolidation use the execution rules above.

Player retention review supports `revoke` for an exact effective note revision. Director preparation receives an existing-person directory before staging an opening. Completed discussions hand back to the Director once without creating a player message. Private consolidation separates processed sources from supporting citations. Each unit still covers only its exact assigned batch. Model guidance asks for recall before using later evidence to decide whether an older question or obligation remains open. Actor windows compare received event revisions, excluding personal record versions; director windows use admitted narrative originals. A later pointer does not establish an outcome, process extra sources or bypass visibility. It adds request metadata and may lead to a recall call; no token or fidelity improvement is guaranteed.

## Development Contract

`StorybookLibrary` separates editable drafts from immutable published versions. `createStory` requires a version ID and seeds an independent instance exactly once. Removing a draft preserves its published content. The host supplies a `ResourceVerifier`; published and imported embedded resources must have valid portable paths and matching byte digests. `MaterialExtraction` previews selected instance material and creates a separate draft at the reviewed revision; publication remains explicit.

`NarrativeCommands` commits events, current entity projections, the revision, the command receipt, and pending delivery in one synchronous transaction. The host constructs `Principal`; model parameters cannot grant authority. A repeated command returns its accepted receipt; changed content under the same ID is rejected. `NarrativeDeliveries` retries notification failures without executing the narrative again. Callers must retain command IDs across transport retries.

`PeopleApplication`, `CognitionApplication`, and `WorldApplication` own separate operations. Current state, evidence, and knowledge never fall back to opening values. Private lifecycle changes use the same memory release, goal, intention, and turning-point rules as the existing Actor adapter. `ActorRuntime` invokes an `ActorExecutor` outside storage transactions and fences cancelled or superseded attempts. `PerspectiveQueries` assembles the same revision-bound text for current preview and an execution request.

`CharacterCommands` and `applyNpcTurn` own the complete semantic turn rules used by the existing NPC tool adapter and the independent application. Model submissions describe changes; the transaction allocates lifecycle identities, validates observer-local field and person references, and stores context proposals as pending player review. Supply character limits, the field-reference formatter shared with preview, and the source-proposal budget when constructing `CognitionApplication`.

`NarrativeArchives` validates archive version 1 and imports history into a fresh instance and template-version scope. It retains original command provenance and checkpoint narrative revisions, treats imported execution coordinates as evidence, and appends an execution invalidation. Restoration appends a compensation record without deleting earlier commits.

The dependency check rejects framework imports in core modules and application imports in domain modules. Only the invariant companion imports Cordis. Cross-package consumers use declared subpaths; Story's schema exports forward to this package's single implementation.

`RecoveryApplication` captures execution coordinates separately from the narrative checkpoint. Restoration appends a compensation commit and invalidates old attempts before requesting cancellation. Cancellation failure returns a committed receipt with a pending execution result; retrying that receipt targets only the original invalidated epoch. Archive import validates person ownership, private sources, audiences, discussion participants, and Actor write authority at every replayed revision.

`RetentionApplication` owns revision-checked player edits, approvals, rejections, and original-text pins. Actor proposals commit atomically with the turn; fenced director proposals remain separate from world facts. `RetentionQueries` reads narrative originals without Actor sessions. Owners are `director` or `actor:<id>`, so a character named director does not gain director access. Retrieval filters by instance and owner before search and pagination; returned text has a configured budget and explicit truncation. Actor recall binds to the original request revision and rejects cancelled attempts.

Previews and actual requests share approved-note rendering. An original retires from the selected context only when its approval permits it and the required replacement notes are included by the enabled recipe. Pins retain complete original text without a total character ceiling. Originals remain retrievable; explicitly forgotten knowledge and memories are excluded from recall and cannot reappear through summaries or pins. Review history, source pointers, checkpoints, compensation and archive reimport remain independent of execution logs.

Actor memory tools exclude the canonical `fact` kind and describe observations as the actor's retained perspective. The domain independently rejects actor fact notes; director tools retain the fact kind. This avoids advertising a submission that actor authority cannot accept.

Editable actor creative defaults aim for one to three spoken sentences in an ordinary exchange, with a concise action when the character has something to do now. Conflict, emotion, important choices or several new facts can expand. What a character answers, avoids or leaves unsaid follows their immediate purpose and relationship; the default does not prescribe a two-step speech structure or turn private reasoning into a polished speech. Character, scene and player length preferences take priority. Age, education, experience and relationships guide each voice without prescribed slang or catchphrases. Action detail focuses on changed choices and conditions, with a concrete motive for repeated checks. These instructions are copied into new recipes or an explicit default restoration; saved custom text, disabled modules, length preferences and settlement permissions retain their existing semantics. The actual Harness request snapshot covers the copied instruction, while the same composition test preserves explicit edits and disabled modules. Adopting it changes a default prompt prefix; native token and cache measurements remain sample-dependent.

Received behavior carries the speaker or performer, their recipient-known label and ref, speech addressees and delivery mode, or an action's person target. Original text stays exact; intent and purpose remain private. Context admission presents all authorized, unrepresented events chronologically, including their order within a commit. Recall and pins preserve attribution. Extra metadata increases the selected context text without dropping entries by character count; no additional model request is needed. Historical records without frozen target attribution do not infer it from later recognition. See [attributed character perception](../../../.agents/notes/implemented/feature/2026-09-11-attributed-character-perception.md).

System initialization owns a saved full context recipe, copied only into newly authored books. Existing explicit recipes and the historical interpretation of omitted recipes remain independent of future defaults. Actor instructions distinguish private execution checks and historical intentions from spoken behavior; discussion preparation does not prescribe a speech outline. See [initial defaults and character expression](../../../.agents/notes/implemented/feature/2026-09-11-context-defaults-and-character-voice.md) for the saved Moonshadow baseline, scope and validation limits.

Director creative defaults carry authored beat candidates forward as pressures, not required scenes. Consequences of accepted choices shape later situations. Unlinked observations keep their plain text. The links come from the frozen owner's records, not inferred wording or later outcomes; they help distinguish attempts from results without exposing another perspective.

## Model Experience

### Perspective and retained memory

#### What the model sees

Actors receive their own selected perceptions, attributed behavior, retained briefs and available tools; directors receive authored guidance and their permitted world records. Actors read detailed memories on demand with `narrative_recall`. Discussion floor messages distinguish ordinary invitations, private preparation and public turns. Creative defaults remain editable and explicit saved preferences take priority.

#### Token effect

Selected text is retained in full without a total character ceiling. Recall pagination still applies. Attribution, note metadata and guidance add input text; private consolidation and recall add recorded calls. A retained brief can replace covered originals, but net token savings depend on the actual notes and subsequent requests.

#### KV Cache effect

New recipes place reusable settings before changing state and evidence. Saved ordering changes only through an explicit edit. Tool description changes invalidate part of the reusable prefix; no fixed cache hit rate or latency improvement is guaranteed.
