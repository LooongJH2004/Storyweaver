# @deepseek-ai/dsh-roleplay-core

[English](README.md) | 中文

## 概述

产品向运行时注入 MemoryQueue：前台结束只提交私有整理任务，独立工作器暂存结果并在前台空闲时接入。直接构造运行时且未注入队列时仍保留同步整理。调度、重启、冲突及存档边界见[队列说明](../../../.agents/notes/implemented/feature/2026-09-13-background-memory-queue.zh.md)。

指定修订查询在同一读取事务内核对当前修订；匹配时直接读取已提交投影，旧修订仍从不可变历史重放。当前作者与记忆查询因此不再重复重建全部历史，不改变存储格式、模型输入或 token 用量。

本包拥有不依赖框架的人物、认知、状态、风格和故事书规则。应用服务接收明确的命令权限、实例作用域、修订号和重试标识。内存适配器可在没有 Cordis、Agent 或浏览器的环境中运行这些操作。现有 Actor 适配器使用其中的人物生命周期投影；独立剧情应用仍在进行产品集成。

`DiscussionApplication` 与现有 Story 适配器共用纯发言规则。`CognitionApplication` 在认知和行为事务中推进准备或发言。`DiscussionRuntime` 串行调用演员执行接口，并报告等待玩家、等待导演、让出、暂停或失败。准备失败不能发布发言或推进席位。 并行准备失败时保留最先发生的错误，同时取消并等待同批其他执行结束；参与者名单顺序不能使后续取消错误覆盖原始原因。

角色讨论上下文从冻结的讨论修订提供已用、总计与剩余公开回合。发言、跳过和收束各消耗一次，私有准备不消耗；上限仍是 maxRounds 乘参与人数。提示鼓励简明回应实际感知的交流，允许平静的分歧，并区分个人回答结束与整场讨论收束；作者明确的篇幅指导仍然适用。

讨论设置可选择 `floorPolicy`：`balanced` 优先给较少获得公开机会的人，同次数时按积极性及参与者顺序选择；`eagerness` 保留原有加权规则。缺省值保留原有规则。两种策略都优先处理定向交棒和排队申请，并允许跳过。应用在讨论启动时保存策略，后续设置变更用于下一场讨论。玩家投影提供完整公开回合计数，不受发言记录分页影响。

演员可通过 `discussion_request` 提交议题、开场目的及其他在场人物的局部引用。工具指导区分在决定前申请共同交流与面向多人说普通台词，后者不会申请讨论回合；普通问答不必转为群组讨论。演员事务在讨论记录中保存私人邀请，重复的待处理或延后邀请合并。导演和玩家通过讨论控制接受、延后或拒绝精确版本的申请；接受时检查当前在场情况，并按已保存设置原子创建讨论。接受前其他演员不接收邀请内容；申请人、导演和玩家审核使用各自投影。存档导入拒绝演员自行处理申请或修改其他申请。

世界观察可携带一个明确指定接收者的 `shared` 共同感知。逐角色投递默认补充共同感知，也可仅对共同接收者使用替换模式。共同和补充证据保留各自种类及来源；保存的顺序使共同证据在按时间排列的上下文中靠前，并保留给最新优先的回忆检索。重复接收者和无共同项的替换会拒绝整个结算。旁白草稿在发布前保留完整的共同结算内容。

新角色请求还向执行适配器携带冻结的能力元数据。npcTurnParameters 仅展示已授权的认知字段及行为种类；没有发言和行动能力时不展示 behavior 字段。旧请求元数据缺少能力清单时保留此前的完整工具结构。展示筛选不替代领域权限校验，也不影响独立整理协议。

角色身份区块包含设定授予的能力。工具指导说明各能力对应的字段；反思权限报错会指出本次提交的 thoughts、state_changes、knowledge_changes 或 turning_points。此修改不授予新权限，也不改变事务校验。

作者设置的 `displayName` 用于作者视角的称呼，不会自动加入该演员自己的身份区块。如果人物知道自己的姓名，应在 `rolePrompt` 或私有视角中写明。其他角色仍须通过获准感知的相遇或言语获知这个名字。

模型动作工具要求显式选择 public 或 concealed。公开动作正文会原样路由，因此指导要求排除默念和私人发现，私下检查应使用隐蔽动作。这不是语义隐私分类器；既有领域输入保留默认值。行动可声明 `visibility: concealed`，其尝试仅成为行动者本人的证据，不自动广播给目标或旁观者。导演可查看已接受的尝试，再投递其他人实际注意到的内容。隐蔽不保证成功或保密。普通行动和发言投递保持原意；存档校验拒绝具有广播受众的隐蔽尝试。

标记 `awaitResult` 的行动保持待结果状态，直到结算关联该尝试并向行动者投递反馈。导演续接遵循配置的反馈预算，无新结果或轮到玩家控制时停止。即使结算已成功，重试失败的续接仍保留其失败，不重复已接受结果，也不将其误报为回应已完成。暂停会在发布前拦截迟到反馈。

个人上下文纳入全部有效目标、计划意图、有效记忆和未拒绝转折。有效摘要可替代其覆盖的原文，置顶原文仍直接纳入；原文可通过本人回忆读取。授权记录不再按条数选取。

角色定义可用自己的常识列表覆盖 `commonKnowledge`。省略或 null 继承故事书共享列表，空列表不继承。这用于区分出身知识，不按年龄自动解锁。作者设定的私有认知与后续接收证据仍保持独立并正常工作。实例和存档保留各角色定义，修改一人不会向其他人授予相同知识。该范围不能清除模型的预训练知识，仍需角色提示约束及效果检查。

演员上下文纳入本人可见、未被摘要覆盖的全部接收事件和有效判断。显式查询可按词语相关性排列判断，但不会剔除条目。冻结修订的预览只使用当时可见的记录；排序不证明信念为真。

讨论推进进入总结阶段且启用整理时，每名 AI 参与者私下处理最多配置阈值数量的未整理本人证据，不要求达到普通回合的触发数量。本场已接受回合及其关联世界结果优先于更早的积压见闻，各优先组内保持时间顺序。玩家控制角色跳过。整理沿用取消及来源覆盖校验，不增加公开发言；直接进入导演总结的入口也安排剩余演员证据；注入后台调度器时，导演无需等待这些任务即可生成上下文。取消保留已完成参与者的记录并拒绝迟到提交，新运行只续接未处理证据。

演员与导演的私有整理来源列表在原始编号旁提供短 `sourceRef`，如 `$source:1`。模型可在整理单元及摘要的 `sourceIds` 中使用短引用，回忆仍使用原始编号。运行时只按当前执行指定批次解析引用，再检查归属及完整覆盖；未知引用或解析后重复的来源会使整次更新被拒绝。保存的摘要使用原始编号，普通回合不继承这些别名。新增引用字段略增加请求文字，是否减少抄写错误与输出成本仍需真实模型测量。

演员和导演上下文纳入全部有效保留摘要。有效摘要替代其覆盖的原文，置顶原文除外；原文仍可按所有者权限回查。导演事实和已接受行为经同样的覆盖过滤后按发生顺序呈现，同次提交的行为保持提交顺序。指导文字或空查询不会剔除已授权条目。

首次启动导演记忆子执行要求故事仍处于根调度的完成修订。旧的已完成请求重试不能消耗后来剧情产生的证据；已经打开的子执行仍沿用原回执及失败语义。

导演记忆执行使用宿主指定的来源 ID，接受一次完整 context-update 后结束且不调度，拒绝世界写入。摘要遵循所有者生效策略，原始记录仍可读取。

上下文摘要变更可携带 `episode`，记录主题、经历、理解、影响和未决问题。生效事务将其与摘要修订、所有者和覆盖来源一起保存。有效经历摘要在普通上下文中仅呈现简述、主题及 `detailReference`，回忆可按该引用读取完整详情。待审核提案不是有效记忆。其他角色和导演回忆无法读取演员经历详情；原始证据仍可检索，存档保留两者。可选详情结构本身不提供自动整理。

普通记忆简述包含标识、修订号、认知类型、状态、正文和来源修订范围；存在经历详情时另附主题、unresolvedCount 和详情引用。数量表示详情中保存的问题数，不表示这些问题现在仍然未决；只更新状态会保留原详情。共享记忆指导要求所有者在修订前回忆详情，并在新证据回答问题或改变解释时同步提交完整的经历详情。所有者、作者和完整来源 ID 数组保留在存储及限定所有者的回忆响应中，不在每条简述中重复。记忆 ID 也可用于回忆检索完整记录。投影精简不改变审核、来源覆盖或修订校验。

回忆与整理通过 `revisionScope: record` 标明个人判断、状态和保留摘要的记录版本；它们不是故事时间戳。事件原文保留故事修订。没有发生时间的个人原文按稳定标识单独排序；只要一条支撑原文时间未知，摘要的 `sourceRevisionRange` 就为 null。混合或无时间的私有批次不生成较新事件窗口，因为无法确定批次结束时间。该投影保留存储记录和来源身份，不能恢复未曾记录的发生时间。

演员政策区分个人记录版本与经历的新旧，说明 null 来源范围，并要求不依据无时间记录的显示位置推断发生时间。该指导补充投影语义，不修改已保存的作者配方，也不证明模型对每一项时间说法都遵守约束。

演员整理保留本人本批次中、在冻结请求修订下仍等待世界反馈的尝试引用，只提供状态，不包含动作正文或批次外尝试，也不改变处理成员。该区块区分未完成尝试与结果；不在列表中不证明成功。整理本身既不结算尝试，也不改变审核策略。 对应原文的元数据头还会在执行内短引用 sourceRef 旁标注 resultStatus=awaiting-world-feedback，使状态与动作直接关联。

回忆优先返回完整引用匹配的记录，其次按最近更新顺序返回匹配的有效摘要，最后按故事修订及事件顺序返回匹配原文。摘要局部版本号不与世界修订号混排。纠正影响后续检索，冻结历史请求保留原有顺序；分页与续读沿用该冻结排序，未选原文仍可查询。

玩家可通过检查修订号的审核命令立即纠正有效摘要。纠正保留所有者、来源覆盖、摘要种类和状态，记录已批准的玩家纠正，并保持自动／审核策略不变。已归档或已被替代的摘要不可纠正，历史版本保留原文字。

修订既有摘要或改变其状态时，省略经历详情会保留原详情；显式提供详情则更新详情。替换为新摘要时不继承省略的详情，历史修订保持不变。

玩家审核可将某个所有者的 `activation` 策略设为 `automatic` 或 `review`，省略保留审核模式。自动模式仅在新提案的原始事务内启用通过校验的单元，保留来源及修订校验。已有待审核提案保持待审核，其他所有者不受影响。模型上下文和提案元数据区分自动生效与玩家批准。切换模式不撤销有效摘要，玩家可另行停用。

整理指导要求按相关经历归并来源，简述保留当前理解，有用细节放入经历详情。周边上下文可帮助解释，但不能替代指定事件成为经历来源。这些指导不构成摘要语义准确性的机械证明。 私有请求不携带公开表演要求与当前场景表演指令，保留身份、个人认知、证据和推理设置；私有背景另排除个人回忆的复述正文，避免后来的计划或误记替代指定经历；目标、信念、保留摘要和作者配方内容继续可用。明确分配为整理来源的个人回忆仍按来源类型出现在批次中。普通扮演和限定所有者的回忆读取仍保留这些个人回忆。来源列表只对应实际包含的段落。普通请求继续使用已保存指导。 上下文摘要更新区分目标不可用与版本过期或已停用。其他所有者的摘要同样返回目标不可用，不暴露其存在；新增摘要使用 add，不填写目标编号和版本。过期目标须提供摘要自身的当前版本，而非故事版本。拒绝时不提交部分更改。 记忆字段指导将当前理解放入简述、必要经历放入详情，未决列表只保留当前仍开放的问题，允许空列表。演员工具与导演领域结构共用这些说明；提示词指导理解，不自动判定叙事真伪。 模型动作工具要求显式填写 await_result 布尔值：检查、搜查、物品交接或存放等有结果的动作使用 true 请求反馈，不需结算结果的表达性手势使用 false。已有领域输入和行为记录仍可读取，系统不从措辞推断动作成功。动作字段指导将行为视为当下尝试，条件性提议留在台词或未来意图中；角色明确作出选择时仍允许有意的言行差异。经历指导保留归属、否定关系和事件顺序，不从后续选择反推来源指令。这些是模型指导，不是语义校验。 导演整理在保存前拒绝缺失、额外或重复的来源覆盖，并列出相关编号；结束时再次检查已接受批次。拒绝的更新不留下部分摘要，可以修正后重试。导演整理按修订、回合内顺序选择来源，仅以编号处理剩余并列。导演回忆与整理保留行为作者、演员／玩家来源、场景、接收者及回合内顺序；动作原文仍标为尝试，发言保留传递方式。该投影省略私有目的，不改变演员可见范围或存储记录。

整理阈值为正时，不在未结束讨论中的普通演员执行成功后，可为最早的对应数量未处理接收事件启动一次私有整理。已提交过提案的来源被排除，包括已拒绝提案，避免重复玩家决定。请求包含冻结的本人可见原文，只接受沉默姿态和恰好覆盖指定批次一次的上下文变更。整理不改变公开言行或姿态，沿用同一执行器、取消控制和请求记录路径。重试复用子执行，失败保留已接受的普通回合。事件节点集成见下文。

讨论进入 summarizing 阶段时，导演上下文要求现有总结执行在关闭前，通过 context-update 保留公开事件、承诺、条件和未决后果。更早的缺失发言可经导演回忆读取。指导区分声称与事实、尝试与结果，排除演员私密认知，并允许没有实质变化时直接收束。摘要生成由模型判断，不强制摘要数量，生效遵循导演保存的策略。独立导演整理和讨论节点演员整理遵循上文的执行规则。

玩家保留审核支持对有效摘要的精确修订执行 `revoke`。停用将摘要归档而不删除；没有其他有效覆盖的来源恢复进入上下文。重复命令 ID 返回原回执，过时修订或其他所有者的摘要被拒绝。旧修订仍可读取，导出历史保留停用摘要及详情。

`DirectorCommands` 在有效导演执行身份下，将场景、人物、感知、风格和讨论写入委托给各应用。`DirectorQueries` 为预览和实际执行共同渲染固定版本的作者设定及经过授权和摘要覆盖过滤的完整实例证据。`DirectorRuntime` 区分准备与演员或讨论的串行调度，保留后续执行失败前已接受的写入，并拒绝失效执行的工具。`NarrativeTransfer` 在存储事务外收集完整执行证据；收集期间剧情版本变化时拒绝导出。 finish 不能同时把当前讨论参与者作为普通演员调度。拒绝不改变调度状态，反馈说明应移除这些编号、推进讨论，或先关闭讨论再进行普通调度。

公共请求结构位于 `/command-inputs`；生成的浏览器契约不再从 Cordis 服务推导数据类型。`AuthorQueries` 返回固定故事书版本的名称、当前实例设置和逐字段来源。显式留空的覆盖保持为空；删除故事书的可编辑入口不会使实例原版本失效。发布必须由宿主提供规范化函数；预览和发布补全相同的默认值，不修改草稿，也不在读取时转换存档。

`PlanningApplication` 使用抽离后的纯大纲规则，时间与标识由宿主提供。玩家锁定、导演建议和审阅决定与世界事实、人物认知分别保存。`PlayerApplication` 将玩家代演或世界干预与执行失效一同提交；后续取消失败不会撤销已接受的剧情。

导演在布置开局前获得已有角色目录。已结束讨论自动交回导演一次，不创建玩家消息。原文检索通过来源 ID 和字符偏移续读截断记录；导演可见的玩家指令与已发布旁白保留不同来源。

讨论准备在当前回合预算内并发执行，每批参与者读取同一冻结版本。只有同批准备提交能推进该批写入版本；外部编辑或取消会拒绝晚到结果。全部待准备人物完成后，公开回合才开始逐人执行。游玩投影提供已接受的准备数量与每个角色固定的 attempt/版本坐标，不包含私有内容。坐标存入 discussion-preparation 实体；旧记录从首次公开回合回执推导读取边界。独立的执行历史读取器按需读取作者诊断。

独立发布默认指导使用 `director_observe` 的单层字段结算世界，用 `director_command` 调度。读到线索不意味着人物已发言或已向其他受众披露。显式作者措辞和已发布版本保持不变；执行工具指导提供当前可调用协议。

导演调度期间，游玩保持角色执行状态，包括演员提交到进度更新或最终结算之间的间隔。演员执行记录之间由调度游标提供当前角色；所属运行结算后才显示就绪。

共享回忆 schema 明确：精确记录编号放在 `query`，空格分隔的检索词必须同时匹配同一记录。`sourceId` 仅校验返回的续读游标，不用于选择记录。新查询从 offset 0 开始，省略续读字段。这些字段说明同时导出，供模型适配器复用。

演员和导演的私有整理省略表演、表达风格、场景表演及旁白篇幅区块。这些设置指导公开表达，不规定记忆篇幅。身份、可见认知、保留摘要及其他作者模块继续可用；已保存风格及普通请求不变。私有请求日志只列入实际包含的来源。这会移除无关输入文字，但不保证生成摘要更短或更准确。 私有整理同时省略导演指导区中当前有效的表演指令目录。普通调度仍收到该目录；已保存风格及场景指令不会被修改。

玩家操作及审核语义见[群组讨论与角色记忆使用说明](../../../docs/roleplay-discussion-memory-guide.zh.md)。

私有整理按来源逐条呈现：JSON 引用头后接保留原文的代码块。来源编号、本地引用、种类、修订及给定顺序不变，演员和导演共用渲染器。围栏长度大于原文中连续反引号的长度，避免原文在显示上提前关闭区块。原始记录、回忆结果与存储不变。该格式避免再次对正文进行 JSON 转义；请求体积取决于原文，不保证保真或 token 节省。

私有整理区分本批处理来源和佐证引用。每个单元仍只覆盖精确分配的来源；其中的记忆变更可额外引用同一冻结视角允许读取的其他原文，扩充记忆来源，但不会将额外原文标为已处理或自动移出上下文。模型指导要求在用较新证据判断旧问题或义务是否仍开放前进行回忆。宿主校验可见性和批次覆盖，不判断引用在语义上是否足以证明结论，也不机械保证模型遵循了回忆指令。

私有批次之后存在可读事件时，请求增加 consolidation-window 区块，包含批次边界、较新事件数量及第一条较新原文引用，不包含后续正文。该引用可用于精确回忆，记录在分配批次之外的独立区块。演员窗口比较已接收事件的故事修订，排除个人记录版本；导演窗口使用允许读取的叙事原文。较新引用不证明结果、不处理额外来源，也不绕过可见性。它增加请求元数据，并可能引起回忆调用，不保证 token 或保真改善。

## 开发约定

`StorybookLibrary` 区分可编辑草稿和不可变发布版本。`createStory` 必须指定版本 ID，且只初始化一次独立实例。移除草稿不会删除其发布内容。宿主提供 `ResourceVerifier`；发布和导入的内嵌资源必须具有合法的可移植路径，且字节摘要一致。`MaterialExtraction` 预览选中的实例素材，并按审阅时的修订创建独立草稿；发布仍是显式操作。

`NarrativeCommands` 在一次同步事务中提交事件、当前实体投影、修订号、命令回执和待发送通知。宿主构造 `Principal`；模型参数不能授予权限。重复命令返回原回执；相同 ID 携带不同内容会被拒绝。`NarrativeDeliveries` 重试失败通知，不再次执行剧情。调用方必须在传输重试间保留命令 ID。

`PeopleApplication`、`CognitionApplication` 和 `WorldApplication` 分别拥有各自的业务操作。当前状态、感知和认知不会回退到开局值。私有生命周期变更与现有 Actor 适配器共用记忆释放、目标、意图和心路历程规则。`ActorRuntime` 在存储事务外调用 `ActorExecutor`，并拒绝已取消或失效尝试的结果。`PerspectiveQueries` 为当前预览与执行请求组装同一份绑定剧情修订的文本。

`CharacterCommands` 与 `applyNpcTurn` 拥有完整的语义回合规则，由现有 NPC 工具适配器和独立应用共同使用。模型提交变更意图；事务负责分配生命周期标识、校验观察者可见的字段与人物引用，并将上下文提案保存为待玩家审阅。构造 `CognitionApplication` 时，须提供人物限制、与预览共用的字段引用格式器及来源提案预算。

`NarrativeArchives` 校验版本 1 的导出包，将历史导入新的实例和模板版本作用域。它保留原始命令来源与检查点剧情修订，将导入的执行坐标仅作为证据保存，并追加执行失效记录。恢复操作追加补偿记录，不删除既有提交。

依赖检查拒绝核心模块导入框架，也拒绝领域模块导入应用模块。只有 invariant 伴随入口导入 Cordis。跨包调用方使用声明的子路径；Story 的格式导出转发到本包唯一的实现。

`RecoveryApplication` 将执行坐标与剧情检查点分开记录。恢复先追加补偿提交并使旧尝试失效，再请求取消执行。取消失败时返回已提交回执和待处理的执行结果；重试该回执只针对原先失效的执行代次。导入按每个回放版本检查人物归属、私有来源、受众、讨论参与者及 Actor 写入权限。

`RetentionApplication` 负责带修订检查的玩家编辑、批准、拒绝与原文置顶。演员建议与本轮剧情原子提交；受执行约束的导演建议与世界事实分开保存。`RetentionQueries` 不启动演员会话，直接读取剧情原文。所有者使用 `director` 或 `actor:<id>`，名为 director 的角色不会因此获得导演权限。检索先按实例和所有者过滤，再搜索与分页；返回文本遵守配置预算，并明确标记截断。演员回查绑定原始请求修订，取消后的尝试不能继续检索。

预览与实际请求共用已批准摘要的渲染。只有批准允许且所需替代摘要通过已启用配方放入本次请求，原文才从所选上下文退下。置顶原文完整纳入，不受总字符上限限制。原文仍可回查；明确遗忘的认知和记忆不进入回查，也不会通过摘要或置顶重新出现。审核历史、来源指针、检查点、补偿恢复与导入重建均独立于执行日志。

演员记忆工具不提供世界客观 `fact` 类型，观察记录表达演员保留的视角。领域层继续独立拒绝演员事实笔记，导演工具保留事实类型，避免向演员展示其权限无法提交的内容。

可编辑的演员创作默认指导将普通问答中的一次回应设为通常一到三句台词；角色当场有事要做时可配简洁动作，冲突、情感、重要决定或多项新信息仍可展开。人物依照当下目的与关系决定回答、回避或暂时不说，不预设两步发言结构，也不把私下推理整理成发言稿。明确的人物、场景及玩家篇幅偏好优先；年龄、教育、经历与关系决定口吻，不规定俚语或口头禅。动作细节侧重选择与情况的变化，再次检查须有具体动机。新配方或显式恢复默认时复制这份指导；已保存自定义文本、停用模块、篇幅偏好与裁定权限沿用既有语义。实际 Harness 请求快照覆盖复制后的指导，同一组合测试保留显式编辑与停用模块。采用新指导会改变默认提示词前缀，原生 token 和缓存测量仍取决于具体样本。

接收到的言行携带发言者或行动者、接收者已知的称呼与引用、发言对象和传递方式，或者动作的人物目标。正文保持原文，意图和目的保持私有。上下文按发生顺序呈现全部授权、未被摘要覆盖的事件，包括同一次提交中的言行顺序。回忆和置顶保留人物归属。额外字段增加入选上下文文本量，不再因字符数剔除记录，不需要增加模型请求。历史记录未固定保存目标归属时，不用后来获知的身份补猜。参见[带人物归属的角色感知](../../../.agents/notes/implemented/feature/2026-09-11-attributed-character-perception.zh.md)。

系统初始化持有保存的完整上下文配方，仅复制到新建故事书。已有显式配方和省略配方时的历史解释均独立于未来默认值。演员指令区分私有执行检查、历史意图和公开行为；讨论准备不规定发言提纲。[初始默认值与角色表达](../../../.agents/notes/implemented/feature/2026-09-11-context-defaults-and-character-voice.zh.md)记录月影账簿保存基线、作用范围和验证限制。

导演创作默认指引将作者章节候选作为持续的压力，而非必经场景。已接受选择的后果影响后续局面。finish 工具提示导演：下一位发言者取决于当前人物的实际回应时，先调度一人；几人各有独立行动理由时才批量调度。配置的响应式续步可在单名角色提交后选择一名接话者；未启用时，导演要等玩家下一次推进。这是模型指引，初次调度仍可安排多名演员。

可选的角色可见节拍与导演私有的玩家要求分开。它进入本次运行中被调度演员的请求，包括世界反馈与 reactive 续步，不写入角色知识或持久场景风格。已记录的执行输入保留精确来源，供重试与请求检查。隐私边界及单场验证见[角色可见的本拍指导](../../../.agents/notes/implemented/feature/2026-09-29-actor-facing-beat.zh.md)。

演员提交结构只在经历的个人意义能够延续到当前场景之外时要求持久记忆。转述指引区分他人有条件的说法和已经确定的结果。同一次提交中没有他人的插入回应，因此依赖对方配合的动作须等到后续轮次。讨论邀请描述需要彼此回应的单项议题，不用于逐人汇报或等待外部证据。这些指令引导演员生成；应用仍把已接受的行为和世界反馈分别记录为证据。

修改玩家引导后重发会回退剧情，同时保留当前已保存的上下文配方，包括停用模块。恢复提交记录此选择，使重放与存档导入得到相同的请求配置。显式检查点恢复仍会还原完整的历史配置。

可选 contextRecipe.narrationLength 设置提供启用开关、最低字数与目标字数。启用数值优先于文字建议；未配置时不自动补足。短公开旁白保留为草稿，最多追加或替换两次，达标后一次性发布。次数耗尽时明确失败并保留未发布正文。计数在观察者投影与 Markdown 解析后统计 Unicode 文字和数字，排除标点、空白、链接地址和格式。目标不是上限；没有旁白的观察不受限制。参见[旁白字数决策](../../../.agents/notes/implemented/feature/2026-09-10-narration-length-check.zh.md)。

故事书版本可以携带作者上下文配方，每个新实例只在初始化时复制。默认配方末尾附加演员沉浸与导演简短思考指令，作为可编辑的 user 消息模块。已存配方在显式编辑前保持不变。可选的 performance 模块缺失时解析为可见的默认值；显式文本和停用设置优先。作者视图与模型请求使用同一解析结果，读取不写入存储。篇幅和推进目标位于这个可编辑模块，启用后完整纳入上下文，不再由固定执行协议规定。相同的有序内容进入预览与执行；指令不覆盖工具权限。参见[思维链模块决策](../../../.agents/notes/implemented/bug-fix/2026-09-08-storybook-editor-and-reasoning.zh.md)。

已迁移的校验保留当前 Actor 行为。新视角服务提供明确的观察者引用、私有判断、可感知状态，以及单独标明的表演示例。已启用模块完整纳入所选文本。自动上下文不设历史条数限制；字符配置只限制回忆查询单页，长原文可以续读。

讨论区段明确说明未分配讨论席位的情况，并提供私下准备示例。讨论摘要不展示不可引用的回合 ID；证据引用使用已接收证据 ID 或个人记录来源引用。来源与阶段错误提供具体修正指引，被拒绝的修改保持原子性。独立发布在未修改的默认指导中使用 `context_update`，保留自定义措辞与固定版本。[协议修正说明](../../../.agents/notes/implemented/bug-fix/2026-09-08-log-driven-tool-guidance.zh.md)记录本地失败证据。

演员工具寻址使用 CURRENT PEOPLE 中的 `ref`，`label` 仅用于展示。语义提交在暂存修改前集中校验人物字段，返回准确字段路径和仅限当前观察者可见的修正提示。匹配称呼不会自动转换，同名称呼必须明确选择，私有思考主题仍为描述性内容。[寻址诊断说明](../../../.agents/notes/implemented/bug-fix/2026-09-10-npc-reference-routing.zh.md)记录回归证据。共享工具 schema 保持固定，当前引用进入已记录的上下文，不变成每轮变化的 schema 枚举。

新的默认演员配方将稳定设定、判断与个人记录放在实时状态和证据之前。`optimizeActorContextRecipe` 为已保存配方提供同样的显式编辑，保留自定义模块边界、消息角色和全部模块内容，视角及来源覆盖规则不变。执行适配器必须保存历史请求的实际文本；可复用前缀变长并不代表已测得服务端缓存命中率或 token 节省。

没有进行中的讨论时，普通演员的席位消息区分 `discussion_request` 与已有席位使用的 `discussion` 决定，说明向多人说话本身不会创建邀请。一旦存在讨论，申请提示对参与者和非参与者均不显示；它不赋予调度权限，也不修改已保存的创作指导。

记忆字段指导优先将当前理解及其影响写入简述；归属、条件和精确数量在影响该理解时保留。可选经历字段补充不同的必要细节，简述足够时可省略。例行动作和重复描述仍可通过原文读取。指导区分行动尝试与已观察结果，不证明语义正确，也不强制字符上限。

简述先写仍有用的认识：演员保留有范围的信念、预期或下一步选择；导演保留已定情况、带归属的承诺与未决后果。一两句话属于写作指导，不是校验或截断规则。支撑经过放在经历详情或原文回忆中，演员理解不转成导演事实。

选中的摘要附带共同指导：有效保留不证明某项义务目前仍适用。较新的本人感知可以表明承诺已完成或兜底条件不再适用；除非新证据形成另一项约定，旧条款只作为历史。工具说明解释修订、解决、撤回、替换与归档，并要求检查同一义务的相关摘要。这些指导不自动结算尝试、不改写他人的记忆，也不保证语义正确。仅在选中摘要时增加上下文说明，并改变共享工具描述前缀。

私有整理仅在指定批次中提供原始事件。普通感知和言行流、包括待结果尝试列表，不再混入该私有背景；相同配方栏位中的作者参考文字仍保留。身份、认知和有效摘要继续提供解释与修订背景，不作为额外待引用证据。普通表演请求不变，演员与导演的记录来源均从实际私有段落重建。

经历中的主题、经历正文和未决列表必填；理解与影响在简述已表达或没有补充说明／影响时可省略。若填写，这两项仍需非空。显式替换经历可以移除它们，修订摘要时省略整个经历则保留原详情。演员／导演工具指导区分这种保留与新建无详情简述：修订带详情的摘要而尚未读取详情时，先读取其详情引用；若新的理解或状态使旧内容过时，再提交完整经历。已回答的问题从当前未决列表移除。这是模型指导，不是语义校验；玩家纠正、来源覆盖与审核维持原行为。

回忆和私有整理使用的原文保留明确结果关联：演员的结果观察包含本人可见的 `respondsTo`，导演事实包含 `settles`。没有关联的观察继续使用纯文本。关联来自该所有者冻结修订下的记录，不由措辞或未来结果推断；它帮助区分尝试与结果，不暴露其他视角。

<a id="model-experience"></a>
## 模型体验

### 视角与保留记忆

#### 模型看到的内容

演员接收本人选中的感知、带归属的言行、保留简述和可用工具；导演接收作者指导与权限内的世界记录。演员通过 `narrative_recall` 按需读取记忆详情。讨论席位消息区分普通邀请、私有准备与公开回合。创作默认值仍可编辑，明确保存的偏好优先。

#### Token 影响

选中文字完整保留，不设上下文总字符上限；回忆分页仍适用。归属、摘要元数据及指导增加输入文字，私有整理与回忆增加已记录调用。有效简述可以替换覆盖原文，但净 token 收益取决于实际摘要和后续请求。

#### KV Cache effect

新配方把可复用设定放在动态状态和证据之前；已保存顺序只通过明确编辑改变。工具描述变化会使部分可复用前缀失效，不保证固定缓存命中率或延迟改善。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

玩家控制候选包含所选运行中全部未归档人物，在场景建立前也可选择，并提供 inScene 标记。即时代演候选仍限于当前可见场景人物。两种投影都使用请求的剧情修订，名单不包含私有认知，选择人物不会自动让其入场。

故事书可选的 protagonistActorId 指向普通角色并标记叙事重点。即使角色列表非空，缺省、null 或空白值仍为 null，宿主不自动选择首个角色。非空 ID 必须引用角色列表。PlayerApplication.control 将独立运行的控制权保存到 player-control/current，在技术取消前先使旧执行失效。受控角色不能开始或提交自动回合，导演分派也会过滤他们。群组准备跳过玩家角色且不虚构其主观意图，公开调度轮到他们时等待。PlayerApplication.passDiscussion 明确让出当前发言权；代演提交玩家来源的发言或行动尝试。存档保留控制权，解除后恢复自动演绎。旁白指导表达相同边界，但自由文本不具备语义合规的硬保证。

导演上下文同时提供固定版本中的主角、实际玩家控制权以及由 AI 控制的在场人物 ID。实际控制权字段优先于作者文本中的玩家角色标签；主角为空仍表示群像故事。该名单绑定修订，后续变化应以成功布景的回执为准。NPC 指导鼓励基于目标主动行动并充分展开公开回应，同时精简私有变更、遵守讨论准备规则并将结果留给世界裁定。它不规定字数配额，也不增加自动回合。参见[旁观主动性决策](../../../.agents/notes/implemented/bug-fix/2026-09-10-observer-initiative.zh.md)。

场景风格指令也承载表演指导：导演可在调度前把用户需求转为针对 actor:ID 的目标、处理方式、主动性和回应深度。只有对应接收者收到指引，且它与感知证据明确分开；导演可查看全部有效指引、修改它们，或用空 instruction 清除某一项。切换场景 ID 后，这些指引不进入当前请求。角色执行器用自身口吻落实指引，不凭空创建事实或接管玩家选择。常规演员贡献采用可编辑的灵活篇幅指导，lengthPreference 和当前场景指引优先。这不是提交校验条件，也不要求将沉默、准备阶段或短暂插话扩写。参见[表演指引决策](../../../.agents/notes/implemented/feature/2026-09-10-director-performance-cues.zh.md)。

- 查询分页有明确预算，演员和导演上下文不设总字符上限，长原文可通过续读完整查看。独立真实模型开局诊断测量工具正确性、语言和用量，不代表长期扮演质量已经通过验收。

<a id="dev-note"></a>
### 开发备注

参阅[独立剧情实例架构提案](../../../.agents/notes/implemented/architecture/2026-09-07-independent-narrative-instances.zh.md)。新配置通过完整组合和浏览器验收前保留旧数据，不引入双写。

PlayView.discussionPreparations 用首次公开回合回执的版本记录各次讨论位置，保留剧情分页语义；最近一次准备摘要仍用于实时控制。历史回放在各版本之间共享未变化的不可变实体，最终返回独立副本；恢复仍解析到精确的历史版本。这消除了每个事件对完整世界的重复深拷贝，不复用可变或过期的世界投影。

PlayerPersonLabel 在游玩消息、场景人物和代演选项中分别提供角色定义的外观描述与已发布的场景称呼。这项仅供玩家查看的注释不替换视角称呼，也不进入模型上下文。运行中新建的人物与故事书原有人物使用相同投影。

启用的旁白字数指令和已选历史均完整进入上下文。总字符上限不再裁剪上下文或拒绝过长的置顶原文。模型自身的上下文窗口限制仍然适用；回忆查询单页大小仍按配置执行。

CreativeSettingsApplication.read 在返回来源绑定和本书最新共享值时，同时提供已保存的生效配方及固定书稿配方。同步预览在同一存储快照内读取这些内容，不应用待同步更新，也不改变版本。来源绑定支持单项或非空、无重复的多项选择，所有所选项原子提交。发布和绑定继续执行版本与运行空闲检查，任何所选值无效都会拒绝整个绑定命令。

演员指令区分场景时间流逝与个人经历：缺失时段不能据此补写过去行动或解释。提交应表达当前尝试或未来意图，不能把尚待回复的条件分支当作行动。这属于叙事指导；宿主不分类散文，也不禁止角色有意说谎。

导演请求区分内部反馈／讨论收束与玩家的空白继续指令。临时执行目的区块允许结算已有尝试及必要回应，要求收束中的讨论关闭，避免另造事件重新开启对话。不改变反馈预算、玩家继续行为、已存场景或私有整理。

讨论关闭时优先整理尚未处理的讨论来源及其关联结果。它们处理完后，不足常规整理阈值的无关旧见闻保留为原始证据，不因尚有批次额度就单独调用模型；达到完整批量的旧来源仍可处理。成功批次持久身份、取消和重试不变，延后不标记证据已覆盖。

内部导演指导现依据讨论状态与席位归属选择当前任务：进行中反馈恢复指定讨论席位，收束阶段保留后果并关闭；下一席属于玩家时，即使状态仍是 active，也等待玩家。讨论外反馈只调度必要回应。宿主权限不变。领域流程测试覆盖一人尝试、结算、另一人回应与收束，以及同等情况下不自动扮演玩家席位。

演员讨论上下文现展示各参与者的公开席位次数，使用观察者本地引用，包含公开放弃、不计私下准备。提示要求等待世界反馈时保留讨论，并在收束前区分尚未获得机会的人与已经同意的人。不覆盖交棒、不强迫发言，也不改变收束权限；历史请求按冻结的公开回合计算次数。


记忆经历指导要求区分见证与亲自行动，保留准确数量、时长、否定和先后顺序；后来的自述仍是说法，不覆盖先前观察。演员与导演共用该工具指导，不增加字段或语义事实分类器，来源归属与玩家审核继续有效。措辞增加工具结构文本并改变其前缀，尚无准确率或缓存收益保证。 必填简述字段同样要求保留所引经历中的行为归属、否定、数量和时长，不能用后来的自述替换证据；不填写可选经历详情时也适用。角色理解仍可错误，但不能编造经历或来源内容来支持理解。

普通演员表演保留过去事件的见证者与行动者区别，以及已提供的数量和时长；先前自述不覆盖原始观察，主动说谎仍属于角色当下的选择。导演创作默认指导将例行交接、位置确认和单项动作结果压到一个短段落，重要发展仍可展开；作者篇幅偏好及启用的旁白字数检查优先。演员协议改变稳定前缀，导演默认仅在复制或显式恢复时改变。不修改结构、权限或存储，质量和 token 效果须由真实输出评审。
