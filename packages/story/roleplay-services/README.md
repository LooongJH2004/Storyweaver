# @deepseek-ai/dsh-roleplay-services

English | [中文](README.zh.md)

## Summary

Memory consolidation uses a durable background queue and separate Harness sessions. Foreground calls enqueue work and return before generation. Results integrate only while foreground execution is idle and only if history and owner-memory fences still match. See [background memory](../../../.agents/notes/implemented/feature/2026-09-13-background-memory-queue.md) for failure, recovery and review semantics. `memoryQueueIntervalMs` defaults to 1000 ms. Background model calls remain included in native usage totals.

This plugin assembles independent roleplay applications with SQLite and the Harness Actor executor. It supplies separate storybook, instance, people, cognition, world, query, history, archive, extraction, delivery, and runtime capabilities. Application code receives explicit ports and never receives the Cordis Context.

`consolidationThreshold` selects the actor evidence threshold and batch size; zero disables automatic actor jobs. The Web profile selects 16. The queue submits jobs without waiting for model generation; saved owner activation policies remain in force.

`directorConsolidationThreshold` selects the equivalent director threshold after orchestration and feedback complete; zero disables it and the Web profile selects 16. Unfinished discussions and pending world attempts defer director jobs.

`consolidationBatchLimit` bounds batches per trigger; default 1, Web profile 2. Discussion closure shares the same durable owner/epoch batch allowance across entry points and prioritizes the exchange and linked results over backlog. Assigned and already processed sources are excluded. Remaining evidence stays readable.

`roleplayConfiguration` records copied style overrides and scene guidance. `roleplayDiscussions` owns discussion commands; `roleplayDiscussionRuntime` advances its floor through the character executor with `discussionTurnLimit`. `roleplayPlay` exposes filtered play and historical rows; `queryPageLimit` bounds play and author pages. `roleplayRequests` is the Harness reader for actual historical requests.

`roleplayDirector` coordinates director preparation, bounded tool commands, actor responses and discussion advancement. `roleplayDirectorViews` supplies its shared preview renderer; `directorCommandLimit` limits preparation operations. `reactiveDirectorLimit` bounds additional Director choices after a single actor response; zero disables them, and the Web profile selects one. Director and actor adapters share technical session lifecycle code but have distinct session identities, policies and tools. Recovery captures and cancels both. `roleplayTransfer` exports revision-pinned archives with complete Harness logs and imports them as independent instances; imported logs remain evidence rather than live execution sessions.

`roleplayAuthor` resolves author configuration and original-version labels; `roleplayPlanning` owns outline edits and proposal reviews. Instance settings are applied by the same resolvers used for actor and director contexts. `roleplayPlayer` owns embodiment and world intervention. `roleplayChanges` exposes revision-only notifications drained from the durable outbox at `notificationIntervalMs`; consumer failures retain delivery work and never replay fiction.

`roleplayExecutionHistory` authorizes instance, person, and revision before delegating to the Harness request reader. Requests with no response evidence remain marked as prepared. `roleplayBooks` uses the independent tool guidance when publishing untouched built-in context rules; custom instructions remain unchanged.

`roleplayCreation` stores revision-checked author defaults and per-book task preferences outside story documents. The creator entry binds its tools to a dedicated native Session and one draft; local tools require an explicitly selected, unchanged directory and retain native permission checks. `roleplayRecovery` supports same-instance player-direction rewriting and run removal, preserving historical commits and fencing late execution. See the [authoring recovery decision](../../../.agents/notes/implemented/feature/2026-09-08-independent-authoring-recovery.md).

## Development Contract

Mount through a dsh profile with the Agent registry, Session store, Session persistence, and LLM services. Configuration requires an absolute `databasePath`, SQLite `journalMode` and `busyTimeoutMs`, model `provider` and `model`, `characterLimits`, `recallCharacterLimit`, `maxContextUpdateUnits`, `notificationIntervalMs`, `directorCommandLimit`, `discussionTurnLimit`, and `queryPageLimit`. `recallCharacterLimit` and `queryPageLimit` bound explicit tool responses only; automatic Actor and Director context has no configured character or history-entry ceiling. No path or baseline is inferred from another running story. Select a new database for the independent application; the current product's old Story files are not converted.

`roleplayBooks` owns drafts and immutable versions. `roleplayInstances.createStory({ templateVersionId, commandId })` instantiates the selected version; `restart` uses the source instance's original version. Creating or editing fiction does not provision an Agent. `roleplayPeople`, `roleplayCognition`, and `roleplayWorld` retain their separate command authority. Callers construct host principals and preserve command IDs across retries.

`roleplayRuntime` invokes the Harness executor. Its sessions are scoped to both instance and character. The tool returns acceptance after the narrative commit; execution logs record the frozen perspective, commit receipt, and diagnostics. On disposal, runtime cancellation settles before execution sessions are released and SQLite closes. Registered application capabilities disappear with their Cordis scope.

`roleplayViews` supplies perspective queries. `roleplayHistory` exposes replay, receipts, checkpoints, and compensation-based restoration. `roleplayArchives` and `roleplayExtraction` keep import and author material selection explicit. `roleplayDeliveries` retains pending notifications for a transport consumer; consuming notifications does not execute fiction again.

`roleplayRecovery` coordinates checkpoint capture and compensation-based restoration with the Harness history reader and execution cancellation. Real HTTP tests cover checkpoint creation, restoration, and resend in the same technical Session while preserving the old log.

`roleplayRetention` and `roleplayRetentionViews` mount player review and perspective-scoped original retrieval over the narrative transaction store. The Actor Harness exposes `narrative_recall` through a host-bound callback; model arguments cannot choose an instance or owner. Director commands support `recall` and `context-update`. Tool results remain in execution evidence, while retained notes and approvals belong to narrative history. The isolated real Loader/HTTP test covers player review without new Actors, cold reload, original retrieval through the actual model tool, archive reimport and same-Session restoration.

<a id="model-experience"></a>
## Model Experience

### Execution requests

#### What the model sees

The executor uses the shared `npc_commit_turn` schema and version-bound perspective for the current tool transaction. Earlier technical conversations remain in execution history. Imported instances start independent execution sessions.

#### Token effect

Ordinary performance, private consolidation and recall consume provider tokens and are included in native usage. Failed or interrupted responses can lack timing or usage samples; missing values are not zero. This assembly does not guarantee a reduction in total input or output.

#### KV Cache effect

Each character turn starts a request series with its projected history recorded in request headers. Reusable prefixes depend on the selected recipe and provider. No fixed cache benefit or latency improvement is guaranteed.

## Known Limitations and Deferred Work

The [player discussion feedback composition](tests/player-discussion-feedback.real.spec.ts) uses shipped actor/director tools with controlled responses and SQLite. Under an explicitly balanced policy, it verifies that settling an actor's attempt preserves the next player floor, rejects automatic acting for that player without a model call, and retains the waiting state after archive import. It is execution and persistence coverage, not native model quality or browser interaction coverage.

The [episode revision probe](tests/episode-revision-performance.e2e.ts) seeds one unresolved actor episode through a controlled tool submission, then delivers an explicit answer and runs one native ordinary actor turn. It requires revision of the same note, updated details, and no stored open questions for this fully answered fixture. It saves original and revised memory, purpose-scoped native usage, and the archive under `.artifacts/episode-revision` before asserting results. Setup usage remains in the archive but is excluded from the reported native turn. Like the other native probes it requires a current build and provider credentials. Text fidelity and actual recall use require archive review; a structural pass alone does not prove them. Automatic activation is confined to the isolated fixture.

The [independent discussion comparison](tests/discussion-performance.e2e.ts) defines artifact-conflict, quiet-promise, counterevidence and first-tide learning scenarios for eagerness and balanced scheduling. It uses isolated instances and records published book settings, archived requests, outcomes, memories and native usage for human review. Run `pnpm exec vitest run --config vitest.e2e.config.ts packages/story/roleplay-services/tests/discussion-performance.e2e.ts` from the repository root after building. It skips without `DEEPSEEK_API_KEY`; scenario parsing and a skipped run do not establish provider or acting quality. `DSH_ROLEPLAY_EVAL_MODEL` selects the model, `DSH_ROLEPLAY_EVAL_REASONING_EFFORT` selects reasoning effort (default `low`), and `DSH_ROLEPLAY_EVAL_TIMEOUT_MS` controls the per-case execution deadline. The initial discussion must close through at most six director feedback runs before the later-scene instruction; the report records the revision boundary and requires a later actor response. A2, A5 and A7 also record fresh world observations rendered in each actor's first later-scene execution context, excluding other characters' behavior as a substitute; missing delivery fails the scenario. These structural checks do not grade that response or establish that an observation actually describes the new time or supports a revised belief. A5 contrasts an attributed notice with later observations; review checks whether actors retain attribution, reconsider confidence and adapt their choices without inventing an explanation. A7 supplies different personal common knowledge to a newcomer, a child and a native; it checks the initial requests for inclusion of their own authored knowledge and exclusion of the others' exact private text. This does not detect every paraphrased leak or prove long-term growth. Final play rows are collected page by page at one frozen revision, including rows beyond the first hundred. A pagination failure retains the first page with playPaginationError, preserves archive collection and fails the evaluation. Discussion statistics use durable accepted public turns, not speech paragraphs or private preparations. They report per-participant slot counts, speak/pass/conclude decisions, consecutive slots and speaker order; these are descriptive measures, not an automatic fairness or narrative-quality score. Results remain under `.artifacts/independent-discussion`; unreviewed quality fields remain null. `usageByPurpose` separates actor turns (including preparation), director turns, consolidation and unclassified calls using recorded execution contexts and native accounting; duplicate session copies are counted once and missing timing samples stay missing. The review is saved before archive and usage collection; either collector may fail independently, leaving successful evidence intact and marking collection incomplete. Collection failures fail the evaluation rather than appearing as zero usage or a complete export.

The [fixed-history memory probe](tests/consolidation-performance.e2e.ts) seeds personal observations and a private clue for another actor, then uses the native actor runtime for consolidation and a later choice. It records memory before the later scene, checks exact-reference recall and owner isolation, and separates native usage by execution purpose. Artifacts are saved under `.artifacts/independent-memory`, including failures. It requires the same build and provider credentials as the discussion comparison. Passing structural checks does not establish concise understanding, spontaneous tool use or a causal effect of memory on later choices. The probe requires effective memory before the later scene and reports sources still unrepresented. Summaries may originate in an ordinary turn or a private pass. With this small history fitting the evidence budget, unrepresented and unarchived originals must remain in the later request; only covered originals are expected to disappear. A mixed request is not evidence of a memory-only causal effect. It distinguishes processed note coverage from supporting citations: supporting event originals remain eligible for the later context unless separately processed. It records historySourceIds, supportingSourceIds and privateConsolidationRequests; already-covered experiences do not need a redundant private pass. Exact recall, owner isolation and exclusion of covered originals from later evidence remain required. DSH_ROLEPLAY_EVAL_HISTORY_FORMAT selects narrated (default, the historical four observations) or attributed. The attributed variant seeds the keeper’s spoken statement through the ordinary actor runtime using MockAdapter, then separately delivers the learner’s promise and three observations. Its five sources set a matching consolidation threshold; reports retain the format and source IDs. This is a different input representation, not a strict single-variable quality comparison. Purpose and per-execution usage start at initialRevision, excluding controlled setup; whole-instance usage and archives retain setup.

[Perception feedback composition](tests/perception-feedback.real.spec.ts) exercises concealed investigation, shared and private result delivery, actor responses, command retry and archive import through the shipped profile with a scripted model. It checks actual provider requests for visibility and duplicate delivery, and durable pending-attempt settlement. This is transport and runtime evidence, not live-model judgment.

[Live perception evaluation](tests/perception-performance.e2e.ts) seeds one concealed attempt with a scripted actor, then uses the selected native model for director settlement and actor responses. It checks fresh request observations, attempt settlement and exclusion of the private code from the witness full context, including peer actions. Consolidation is disabled to isolate perception; runtime limits and model settings are recorded. Reports and full native usage are retained under .artifacts/independent-perception. Per-purpose costs exclude seeding; whole-instance usage includes setup. Semantic duplication, invented details and role voice need separate review.

A7-decade-growth extends the spaced-learning sequence to ten years later, when the child is eighteen. The director must deliver the later time and age, without inventing schooling, occupations or intervening adventures. ### Dev Note

The [native invitation probe](tests/invitation-performance.e2e.ts) gives an actor a reason to consult two present companions, without prescribing a tool call. It records the ordinary response and any pending invitation, then explicitly accepts the request as the player. Assertions require no discussion before acceptance and the intended participants afterward. The test does not run the ensuing exchange or establish spontaneous invitation frequency across ordinary scenes; failure artifacts preserve speech-only responses under `.artifacts/independent-invitation`.

The [conditional-memory probe](tests/conditional-memory.e2e.ts) seeds the same active custody promise in two isolated instances, then supplies either a witnessed return or continued non-return at the deadline. Real actors choose their next behavior without a forced memory update; threshold consolidation is disabled to isolate interpretation from rewriting. Reports preserve the seed, request, actions, notes and native usage after setup under `.artifacts/conditional-memory`. Passing execution checks does not classify the choice: review whether the fallback applies, and distinguish attempts from settled results. This does not test self-generated summaries, long-term revision or a whole discussion.

See the [independent narrative proposal](../../../.agents/notes/implemented/architecture/2026-09-07-independent-narrative-instances.md). Preserve existing data and avoid dual writes while completing the product switch.

Evaluation reports also include executionUsage: native totals for each recorded execution, with owner, attempt, frozen revision and assigned memory-source count. This separates costly individual actor and director batches without duplicating session exports. Pre-request usage remains unclassified; absent timing samples are not invented. This is evaluation evidence, not an additional model call or product statistics endpoint.

At discussion closure, remaining exchange sources can use a partial batch. A purely unrelated older backlog must reach consolidationThreshold before consuming a remaining slot. Deferred sources remain available as originals; neither the saved batch budget nor activation policy changes.

A7-spaced-tide extends the same newcomer, child and native through repeated observation three days later, an openly covered lamp without rising water, and a different dock two months later. growthPlan records all intended phases; growthPhases records entered phases with start/end revisions, completion, before/after personal memory and each actor’s first response revision with fresh perceptions. Failed or unentered phases are not counted as learning evidence. Each phase must deliver new perceptions before the actor response, and the original knowledge-isolation checks remain. This fixture does not update age, grant lore or prove childhood-to-adulthood growth; model runs and quality review remain necessary.

The [precise-recall probe](tests/recall-performance.e2e.ts) seeds an episode through a mock actor commit, then excludes its procedure from the later materialized model request while retaining its brief. A keyless mock reader verifies the native read-before-action path and rejects another owner's reference. The live case requires provider credentials and checks whether a real actor reads the detail before committing; it does not prescribe the tool call. Reports identify mock and live modes, preserve the seeded-memory origin, and exclude the seed execution from purpose and execution cost totals. Full archive usage still includes setup. Both cases pass. In the recorded live sample, the model chooses keyword recall and submits the correct ordered attempts in 4,677 ms with 744 output tokens. This does not verify model-generated consolidation, successful world settlement or long-term growth. Artifacts are under `.artifacts/independent-recall`.

Set `DSH_ROLEPLAY_EVAL_RESUME_REPORT` to a completed A7 report to continue one unfinished phase in a fresh isolated import. The helper verifies collection, authored scenario, model, settings, phase boundaries and fresh observations before retaining completed phases. Native recovery restores the recorded boundary and checks retained memory against historical replay. An interrupted phase restarts at its beginning; completed phases are not replayed. The report records parent lineage and whether all planned phases completed. Purpose and execution usage cover the new run; archive totals include imported history. Preserved failed branches remain evidence, not current learning. Completion validates delivery and execution, not memory accuracy or narrative quality.

`DSH_ROLEPLAY_EVAL_ACTOR_LENGTH` optionally sets the existing actor lengthPreference field for each authored evaluation character. Empty or omitted values keep the authored defaults. Reports preserve the exact preference and published document hash, and require its presence in each actor’s ordinary request. This evaluation option does not modify saved product configuration.

`DSH_ROLEPLAY_EVAL_MEMORY_POLICY` selects `automatic` or `review` for all authored actors and the director. Fresh evaluation runs default to automatic activation for comparison with historical samples; the product retains its review default. A resumed run inherits its report's policy unless explicitly set, and rejects a mismatch with the restored owners. Reports record the policy alongside initial and final retention records. Review scenarios contain no player approval and require all proposals to remain pending with no retained notes. Success in that mode demonstrates continuity with unreplaced originals, not effective summary compression or summary-driven recall.

The [pending-attempt probe](tests/pending-attempt-performance.e2e.ts) seeds one unfinished action through a mock actor turn, then switches to the native provider before automatic private consolidation. It checks inline pending status, retained memory and unchanged pending settlement. Semantic review inspects the saved brief and episode rather than relying on those structural checks. Artifacts under `.artifacts/pending-attempt` retain the mock seed separately in actor-purpose usage; consolidation-purpose usage is native. Automatic activation is fixture-only.
